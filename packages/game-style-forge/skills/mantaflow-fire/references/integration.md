# Mantaflow fire bridge v1
Source: Blender 4.5 LTS built-in Mantaflow, GPL Blender; no separate executable or paid service. Official API: https://docs.blender.org/api/4.5/bpy.types.FluidDomainSettings.html and https://docs.blender.org/api/4.5/bpy.types.FluidFlowSettings.html . This module is authored adapter code, NOT an installed Blender binary or a completed simulation.

## Producer — Blender Model Animation Enhancer
Use a disposable local CPU worker with the official Blender 4.5 LTS build, fluid support and verified distribution checksum. Do not download or execute unknown scripts. The script intentionally creates a new clean scene and refuses an existing output folder; never run it against an open production file. Run `blender -b --factory-startup --python-exit-code 1 --python scripts/bake_mantaflow.py -- --out /absolute/new/fire-bake` (the actual script path is in this skill). For CLI-Anything use Skill Nexus to discover the installed executable, verify backend/version and choose documented command support; use the native Blender CLI if the wrapper cannot call a background Python script. No second fluid engine. VDB cache, blend and 48 full RGBA rendered frames are retained, 24 FPS, CPU, 64 domain resolution, 48-frame warm-up. This is a generic local plume; position at authored car engine, cabin or tire fire anchor after adapting the emitter to actual car geometry. Validate visual shape and lighting, not just command status. The simulation/render path requires real Blender execution; do not call it verified before it succeeds.

Run `python scripts/pack_fire.py /absolute/new/fire-bake /absolute/new/fire-asset` with Python, Pillow and NumPy. Rejects empty/static/repeated frames and large loop seams; emits fire.png + fire.json (schema mantaflow-flipbook-v1, source frame hashes, atlas SHA256, timing, light envelope, UV gutters). No fake smoke or generated stand-in on failure. Keep originals immutable. If seam fails, bake longer and choose a better continuous range, never duplicate frames. This is a 2D volumetric-simulation projection, NOT a genuine 3D sprite stack. For a volume renderer use the actual VDB grid in a separate validated future adapter, never extrude a photograph.

## Consumers — META Game Fusion / Game Style Forge
Copy the authored runtime `fire-runtime.mjs` and approved fire.png/fire.json to game assets. Validate JSON and SHA256 of actual bytes with `verifyFireBytes(bytes, meta)` before texture creation (offline: embed bytes and metadata; no network required). Verify decoded dimensions. Use Three.js existing world scene and `createFire(THREE,scene,texture,meta,anchor,{phase,scale,light})`; attach the effect to the burning vehicle's real transform/anchor; call `update(gameTimeSeconds)` in existing frame loop. For multiple cars use bounded independently phased effects. Existing three.quarks (if actually installed) adds only moving embers/ash, not a second flame/smoke layer; existing GLSL noise optionally drives screen-space heat distortion only over the plume; Postprocessing handles bloom and exposure once; Rapier remains physical authority, no damage or movement from visual FX. Use at most two dynamic fire lights near camera; remaining emitters use light:false. The adapter has no new renderer, state machine or RAF. On WebGL failure use `drawFire2D(ctx,image,meta,time,phase,x,y,w,h)` in existing fallback render; both paths share the same atlas and clock. Keep original environment and hero artwork. Before overlaying animated effects, remove baked static flame pixels from the car background using an approved clean vehicle render; never stack new flames over a static burning photograph. No claim of full volumetric runtime for billboards. Keep animated-world and black-screen guards.

## Quality — required for visible flames
Check alpha/motion/loop from actual bake, and inspect visible fire at near/far and both render paths using real browser frames. Compare cropped plume region, not moving HUD/camera or moving ember particles; fix camera for the comparison. Flame tongues must change shape independently, smoke must rise/drift, light must follow the same timebase. Check frame cadence and memory budget and game responsiveness. A static car background alone fails. Preserve 24 FPS by time-based playback, not frame-count scheduling. In low quality reduce number of effects/lights, not animation to a still picture. If no bake exists mark Mantaflow unexecuted. This module does not fix character rig, walk, sword or jump/attack clips; route those to the next dedicated integration.
