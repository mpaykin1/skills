CPU Python API: https://opencolorio.readthedocs.io/en/v2.4.2/api/processors.html . Reviewed worker package `opencolorio==2.4.2` with matching Python/architecture and verified distribution hashes; no GPU. Use built-in fixed ACES CG config `cg-config-v2.2.0_aces-v1.3_ocio-v2.4`, not latest aliases or external LUTs. Native runtime is external, do not claim installed without import and actual processing. Existing Blender built-in OCIO is another legitimate path, but never apply both display transforms to same image.

## Production
Keep material albedo in its declared sRGB texture encoding, normals/ORM/AO/height linear data. OSL/Material Maker produce materials, MaterialX standardizes, OpenSubdiv and Rigify/NLA evaluate source poses, Embree/Cycles CPU provide lighting, OIDN denoises new raw renders before the final display transform (HDR via existing Cycles CPU route; do not clip HDR to use standalone LDR denoiser). Mantaflow/OpenVDB/NanoVDB store physical fields and real RGBA volume slices: no display transform on physical data, no baking filmic grade into PBR maps or occupancy. Preserve approved art and existing game files. Render new preview/full-frame candidates in scene-linear Rec.709 or ACEScg (explicitly recorded, do not infer), export straight-alpha float32 HxWx4 NPY from actual linear render, before any Blender view transform. No sRGB PNG re-graded as linear. If source is premultiplied, convert to straight in the reviewed upstream export; no guessing. Prefer opaque scene composite before display transformation for physically correct lighting/compositing; independently graded transparent projections only as art-directed candidates, inspect compositing edges and matched illumination. No grade on existing approved pixel art. Same source/camera, pose/frame time, fixed profile across shots, views and animation. ## Consumers
Use `python scripts/ocio_cpu.py audit recipe.json OUTPUT_DIR --recompute` on approved CPU worker before atlas packing. For consumer metadata/color/alpha checks without OCIO omit --recompute; that is structural only. Apply the same approved profile on all newly rendered complete poses, background, smoke/fire projections; independent transparent compositing is an approximation and requires visual review. Do not transform true volume slices, do not turn projections into fake 3D slices. Canvas2D draws pregraded images as ordinary sRGB, no extra tone mapping. In Three.js display-referred unlit projections use sRGB textures, material.toneMapped=false, and do not put them through a second tone map in EffectComposer; composite in a separate display-referred pass if necessary. Real 3D geometry uses scene-linear lighting and one display transform at output; Three.js ACESFilmicToneMapping is an approximation, not identical to OCIO ACES. Do not promise cross-renderer exact match; compare reference shots. No OCIO runtime in HTML. Rapier remains physics authority, Effekseer combat, Quarks particles, Mantaflow continuous fire; no extra animation clocks, no static flame. Black Screen Guard and living-world guard unchanged.

## Quality
Inspect original and graded front/rear/side views, steel highlights, garment grain, flame/smoke, dark-scene visibility and temporal stability. Check for clipping, halo, lost detail, double tone mapping and contrast with gameplay UI. Audit source hashes and alpha; recompute with actual OCIO before claiming execution. Approved original sprites remain intact; no substitution. No measured visual improvement or FPS claim without real playback. CPU-only offline processing and Canvas2D fallback supported by design, not proof of game performance.
