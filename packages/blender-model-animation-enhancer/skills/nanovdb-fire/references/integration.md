# NanoVDB native + lossless browser volume transport
Upstream NanoVDB is part of OpenVDB v12.1.0 at https://github.com/AcademySoftwareFoundation/openvdb/tree/e4621ae7b37d993ffb93f11ded327736b8227f5f/nanovdb (Apache-2.0, LICENSE blob d9a10c0d8e868ebf8da0b3dc95bb0be634c34bfe). Native headers, OpenVDB Python bindings and C++ dependencies are not bundled. Obtain pinned sources and dependency packages from trusted reviewed origins on isolated worker, verify source hashes and licenses. Build the pinned OpenVDB with NanoVDB headers and NumPy binding; use its documented CMake configuration (set OpenVDB_DIR/CMAKE_MODULE_PATH as appropriate). `cmake -S native -B /new/build -DNANOVDB_INCLUDE_DIR=/approved/include` then `cmake --build /new/build --config Release`. Native bridge uncompiled here; no native GPU or runtime claims. No CUDA dependency in this bridge. NanoVDB is not a WebGL parser and does not simulate fire.

## Producer
Use existing Mantaflow and openvdb-fire config with actual immutable density/flame cache, fixed axis-aligned crop and matching transforms. `python scripts/pack_native.py config.json /new/dense --extractor /approved/build/meta_nano_extract` calls real native C++ float conversion, writes and reads NanoVDB, compares every voxel in the selected crop to the original OpenVDB values, extracts float32 arrays then uses existing shading, projection, frame and memory constraints. No quantization, no synthetic cache. Isolate worker and enforce process memory/time/disk limits (native parsing of trusted inputs only). Temporary native files are deleted after extraction; persistent NanoVDB cache not claimed. Native bridge requires little-endian worker and reviewed executable. If unavailable, existing OpenVDB producer remains valid but explicitly not NanoVDB. Retain same source, time, light curve, orientation and fallback. No guarantee NanoVDB file is smaller than VDB; compare measured sizes only if retaining actual files. No native GPU acceleration implemented.

`python scripts/pack_sparse.py /approved/dense /new/packed` adds independent lossless RGBA run-length encoding per frame, or raw frame if encoding is larger. It validates original bytes and exact roundtrip. This is META's browser transport, NOT NanoVDB format. Keeps exact same volume.json and fallback.png, source SHA, frame SHA, packed SHA, index. Existing source audit first, then `python scripts/audit_sparse.py /new/packed` verifies full reconstructed source and existing OpenVDB motion and seam checks. Browser stores packed data plus one reusable decoded frame; no full expanded animation buffer. Peak memory also includes source fallback PNG, GPU texture and application; no unsupported FPS claim.

## Consumers
Use runtime/sparse-runtime.mjs with existing openvdb-fire runtime. Verify fallback PNG hash and decode before showing; call `openFrames(verifiedArrayBuffer,sparseMeta,volumeMeta)` (validates full compressed hash, bounds and each decoded frame hash). `createSparseVolume(THREE,renderer,scene,provider,volumeMeta,position,opts)` updates one reusable RGBA Data3DTexture in same update loop. Keep Black Screen Guard, real 2-frame validation, same phase and fallback via drawFallback. Do not render both continuous fire paths simultaneously. Mantaflow remains solver; OpenVDB validates source; NanoVDB native reads verified crop; RGBA transport and GLSL raymarch render smoke/fire; Effekseer combat bursts, Quarks ambient ash, PostFX glow, Rapier collision unaffected. Same camera/hero pose source and no duplicate physics or action clocks. Keep mobile limit and exact art, use existing animated fallback if GPU/codec errors. No static photograph. Source-only until actual native conversion and browser playback verified. Quality checks do not substitute visual evaluation.
