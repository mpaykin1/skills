# Animation Layers + Rigify hybrid v1

Upstream optional UI: https://github.com/evilmushroom/Animation-Layers-for-Blender/tree/7e9ac93dcc0ecf185c1d9883f71ef36e5235efa9 (GPL-3.0; unmodified source and LICENSE, repository `mpaykin1/skills`, `third_party/animation-layers-for-blender/`). Upstream declares Blender 3.6.9 and uses legacy Action.fcurves and UI operators. Do NOT automatically enable it in Blender 4.5 or claim compatibility. No paid addon required. `install_layers.py --profile /new/isolated/profile --source-dir /path/to/reviewed/upstream` verifies the pinned Git blob hashes and stages the addon; without source-dir it attempts pinned raw files. Enable only after separate version-specific review in an isolated Blender profile. This is not a native runtime installation or a compatibility PASS.

**Production headless path: Blender 4.5 LTS native NLA API, no dependency on UI addon.** Official API: https://docs.blender.org/api/4.5/bpy.types.NlaStrip.html and https://docs.blender.org/api/4.5/bpy.types.ActionKeyframeStrip.html . Our original `nla_layers.py` composes actual NLA tracks and is independent of the optional GPL UI addon. No fake layers, no automatic creation of missing authored motions. Blender must be installed on an isolated CPU worker. Use native `blender --background` or Nexus CLI-Anything only when its actual documented Blender backend is available.

## Producer: Blender Model Animation Enhancer
1. Preserve the approved source .blend SHA, rig, mesh weights, materials, sword and existing original actions. Existing Rigify + approved Open Mocap/Rigger workflow creates base locomotion and authored jumps/attacks. Do not apply Rigify to approved 2D sprites. Work on a copy; no overwriting source. Mute unrelated NLA tracks in the approved copy and use Blender 4.5 layered Action slots. Keep the source file unchanged during sampling.
2. Use the existing rigify-hybrid sampling configuration (`mode=sample`, `source_sha256`, `hero_id`, `rig`, `meshes`, `bones`, `clips`; required idle, walk, run, jump_start, jump_loop, jump_land, light_attack, heavy_attack, air_attack). Each clip has base action, slot, start/end frames, explicit foot contacts, expected in-place root velocity and authored events as before. Add optional `protected_bones` (actual root/foot/leg IK control names) and `layers` list. Each entry has role (pelvis, upper_body, weapon, secondary, foot_correction), action, slot, bones (explicit mask of actual Rigify control bones), blend (REPLACE or COMBINE), weight (0<weight<=1). COMBINE additionally requires `authored_delta:true`: identity-relative authored action, not absolute quaternion angles. Base is always REPLACE. No overlapping correction masks, no non-transform correction channels, no upper body / weapon / secondary changes to protected leg/root controls. Explicit authoring and review required; do not infer foot contacts or create faux motion. Actions must cover exact same frame range. Limit 8 tracks; tracks removed after sampling. Preserve IK/FK constraints and control settings; no blind NLA baking with constraints left active on the same deform rig. Layer changes may indirectly affect feet via constraints; contact and visual checks remain mandatory.
3. Run `blender --background /approved/source.blend --python-exit-code 1 --python scripts/sample_layered_motion.py -- --config layered.json --out /new/output`. The script evaluates actual pose bones on NLA tracks and emits existing `rigify-motion-v1` data plus `layer_recipe_sha256` and per-clip layer list. It does NOT create the source rig, generate new motions, bake GLB or volume slices. Use `nla_layers.compose(rig, spec)` in the existing authorized export/volume bake worker to evaluate **the exact same** layered config, pivot, frame and units for complete poses and sword attachment. Use a separate approved export deform skeleton or verified evaluated glTF export; do not double-apply constraints. Validate exact transforms, events and identity after Khronos/glTF-Transform/meshoptimizer; no automatic deformation of existing approved pixel art. Full mesh and volume outputs must use identical source and config hashes, including all fallbacks. Reject inconsistent recipes rather than showing a substitute.
4. Walk away from camera is the rear view of forward walking, not reverse locomotion. Review pelvis rotation, shoulder counter-motion, foot contact, asymmetric sword grip, cloth/hair follow-through; separately author backward locomotion, jump/air slash, heavy and light attack, landing. Existing animation-quality gates and real 8-direction review remain required. Material Maker/PyMeshLab/Instant Meshes remain asset preparation, not motion generators.

## Consumers: META Game Fusion and Hero Animator
Use `runtime/layer-sync.mjs` with existing rigify-hybrid runtime (preserve relative paths when copying). Each clip volume manifest must have the exact `layer_recipe_sha256` from the sampling configuration plus original hero_id, source_sha256, fps, exact frame numbers. No runtime blending or morphing of sprite frames: show complete approved RGBA volume poses, and use the sampled 3D sword transform from same frame. Hero Animator imports only newly approved, full, independently rendered 2D frames, with its existing no-deformation lock unchanged; do not modify old GIF/PNG. Rapier owns movement and grounded state. Existing Effekseer combat adapter receives authored hit/takeoff/land cue after real input and state reconciliation; unique occurrence ID. Mantaflow continuous fire, Quarks ambient ash/embers, GLSL/PostFX light and distortion; no duplicate simulation, loop, hit or action. Black Screen Guard remains active and fallback uses the same approved frame recipe.

## Quality: Animation Quality
Run `python scripts/compare_contacts.py baseline/rig-motion.json layered/rig-motion.json` for the same hero/source, same action ranges, events, fps, contacts and expected root velocities. Fail if final contact drift exceeds default 4cm or worsens. A metric is not proof of good walk: compare front/back/side/8 yaw, foot lift and plant, shoulder/pelvis timing, sword alignment, jump arc, air strike, costume and hair silhouette, same-source volume/GLB pose match and real browser rendering. No artistic percentage without comparable actual data. Missing runtime/asset = blocked. Source integration only until native execution and visual approval.
