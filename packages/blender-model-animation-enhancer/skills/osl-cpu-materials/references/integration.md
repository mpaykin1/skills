# OSL CPU material bridge — cloth and steel
Upstream: https://github.com/AcademySoftwareFoundation/OpenShadingLanguage/tree/0bb50787ac5510d2f2aac771f74641a76821600e (v1.14.12.0, BSD-3-Clause, LICENSE.md blob a7b3c6275fd7c368358a3be32723bddf6143ee9d). Use the OSL version bundled in a reviewed Blender 4.5 LTS build with Cycles OSL CPU support; upstream tag is a reference, NOT a claim of Blender's embedded version. No ABI substitution, no paid/cloud service, no GPU required. Official instructions https://docs.blender.org/manual/en/4.5/render/cycles/osl/index.html . Blender and oslc are external and must actually be installed on an isolated CPU worker. No native compile or rendering claim without execution. The original `meta_surface.osl` shader is included, not third-party binaries. CPU Cycles must have OSL enabled; fail on missing runtime or missing outputs rather than substitute another shader.

## Producer — Blender Model Animation Enhancer
Use on a NEW material candidate for an authorized 3D model only. Preserve approved meshes, weights, textures, UVs and costume/sword design, source hashes. OpenSubdiv refines topology first with edge protection; Material Maker supplies existing textures (e.g. authored seams, ornaments and blade marks). OSL supplies a stable irregular cloth/steel surface detail candidate, not new geometry, ornaments, physics, or animation. Do not replace approved maps or cover existing details automatically. No camera/time-dependent noise, repeated decorative patterns or frame-to-frame random seeds. Base RGB values are explicitly chosen in linear color; don't assume original colors. For a material candidate in a fresh worker:
```
blender --background --factory-startup --python-exit-code 1 --python scripts/bake_material.py -- --preset cloth --base .12 .10 .09 --size 1024 --threads 4 --out /new/cloth-linear
python scripts/pack_material.py /new/cloth-linear /new/cloth-pbr --strength .12
python scripts/audit_material.py /new/cloth-pbr
blender --background --factory-startup --python-exit-code 1 --python scripts/material_library.py -- /new/cloth-pbr /new/cloth.blend
```
Steel variant `--preset steel`, choose appropriate linear steel color. The generator actually compiles OSL through `cycles.osl.update_script_node`, renders three emission-only maps from a UV plane in CPU Cycles, reads linear EXR, exports numpy arrays. It never modifies the source model. Fixed texture sizes 256..2048, bounded threads. Packer exports sRGB baseColor, linear tangent-space normal (+Y, height-derived gradient), ORM (R=1 neutral AO, G=roughness, B=metallic 0 cloth/1 steel), linear height PNG. No AO bake is implied, no true displacement or anisotropic BRDF. Maps are non-tileable until real seam review; UV clamp, appropriate UV scale, no unreviewed repetition. Library creates a new packed Principled material, not a modification of approved assets. Apply to a copy of the correct material slots only after comparison; retain Material Maker and source textures, blend detail only under explicit approved masks, do not globally overwrite. For more complex clothing or metal, bake mesh-specific UV maps in reviewed workflow. OSL does not run in glTF/Three.js, do not export Script nodes. Export ordinary Principled texture maps, glTF Validator then safe glTF Transform/meshoptimizer; preserve material IDs, normal orientation, UVs and color spaces. No OIDN on PBR maps or actual RGBA volume slices. OIDN may improve newly ray-traced preview images only, after OSL/Cycles lighting; protect alpha and details.

## META Game Fusion + Game Style Forge
Render all approved complete Rigify/NLA poses with same material recipe and UVs. Generate genuine aligned RGBA volume slices with existing volume baker using the material's base color and consistent source mesh; a normal map on a GLB does not magically appear in voxel slices. To preserve fine material relief use approved 3D geometry/real volume detail or existing normal-aware shading pipeline where supported. Do not call rendered projections true volumes. Match color/lighting across eight directions, especially rear garment and sword, preserve source and recipe hashes across GLB, volumes, preview and fallback. Three.js uses standard PBR textures or pre-baked slice colors; no OSL runtime, no GPU compute dependency for offline path. Canvas2D uses approved pre-rendered full frames with same clock. Do not change gameplay, Rapier or event clocks. Mantaflow/OpenVDB/NanoVDB continuous fire remain separate; OSL materials may react to approved lighting but cannot substitute a flame animation. Quarks/Effekseer retain their roles. Black Screen Guard and living-world guard remain active.

## Animation Quality
Audit PNG hashes, actual format, color spaces, normal lengths and roughness/metallic channels via `audit_material.py`. These are structural checks, not proof of visual quality or OSL execution. Compare actual original/new front/rear/side shots, motion, sword edge, garment seams, stable UVs, texture shimmer, illumination and material identity. Check material recipe hashes and original animation timing/pivot; no automatic approval, no fabricated percentage. Reuse existing rig/contact/identity gates and browser check. `approved:false` candidates need explicit visual approval. If native OSL is not installed, keep source unchanged; do not treat synthetic map fixtures as real OSL renders. No game publication by this skill update alone.
