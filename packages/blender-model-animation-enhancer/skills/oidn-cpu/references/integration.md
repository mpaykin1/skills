# Intel Open Image Denoise — CPU offline render chain
Pinned upstream: https://github.com/RenderKit/oidn/tree/49a0a43bdab45fbb6bec7b084d743387634da9c3 (v2.3.3, Apache-2.0, LICENSE.txt Git blob d645695673349e3947e8e5ae42332d0ac3164cd7). Official release: https://github.com/RenderKit/oidn/releases/tag/v2.3.3 . Install an independently reviewed matching CPU release on the worker, verify archive and executable hashes and notices; use `oidnDenoise --list_devices` to verify actual CPU availability. This adapter does not bundle OIDN or model weights. No GPU/CUDA/Metal/SYCL dependency, no cloud/paid service; OIDN is an offline ray-tracing denoiser, not an animation generator, texture super-resolution tool or fluid solver. If runtime is absent, preserve the raw render; never report OIDN execution. Use Blender Cycles CPU with OIDN CPU built-in when installed (`scene.cycles.device='CPU'`, `scene.cycles.denoiser='OPENIMAGEDENOISE'`, `denoising_use_gpu=False` if available); choose one denoising path, not both. For exact-alpha gated standalone path render noisy RGB with raw alpha and optional aligned albedo/normal guides, denoising disabled in Cycles. Blender and native OIDN are external.

## Producer
Maintain original approved asset and all prior source hashes/rig/materials. OpenSubdiv refines true approved 3D source; Material Maker handles texture detail; Rigify/FreeMoCap/Rokoko and NLA provide motion; Mantaflow CPU simulates fluid; OpenVDB/NanoVDB keep physical grids unchanged. Denoise only newly generated ray-traced **image candidates**, before artistic approval and atlas packing. Never denoise approved PNG/GIF, hand-painted/INK/pixel-art grain, true volume cross-sections or voxel occupancy, motion guides, maps, normal maps or authored patterns. For transparent/emissive plume silhouettes the guard may protect almost all pixels; prefer native Cycles denoising on a separate preview, never claim improvement by hiding detail. Keep raw frames immutable. No temporal interpolation/warp of hero, no synthetic motion.

Use `scripts/oidn_cpu.py config.json NEW_DIR --exe /reviewed/oidnDenoise --sha256 VERIFIED_EXECUTABLE_SHA256 --threads 8`. Input config: `source_kind: unapproved-raytraced-render`, `asset_id`, `color_space: srgb`, `alpha: straight`, `fps`, optional `blend` (default .5, <=.7), `frames:[{frame:0,file:"raw/000.png",sha256:"...",protect:{file:"mask/000.png",sha256:"..."},guides:{albedo:{file:"guide/000.npy",sha256:"..."},normal:{file:"normal/000.npy",sha256:"..."}}},...]`. Protect and guides optional; mask aligned L PNG nonzero=protected (sword, costume details, eyes). Guides aligned float HxWx3 arrays linear albedo 0..1, normal -1..1 from same rendered frame/camera. No `clean_aux` assumed. CPU CLI verified against pinned upstream `apps/oidnDenoise.cpp`: `--device cpu --filter RT --ldr ... --alb ... --nrm ... --threads ... --maxmem 512 --quality high --output ...`. Convert sRGB to linear before PFM, no --srgb flag; preserve alpha byte-for-byte and all translucent/edge/protected pixels. LDR-only path; for HDR use native CPU Cycles with reviewed linear EXR workflow, not clipped PNG as HDR. Guard max 2048² pixels/frame, 240 consecutive frames and 1..32 threads, sequential processing and timeouts. Isolate worker; only verified local binary, trusted source files. Native denoiser can still lose detail or flicker; keep blend conservative and compare both versions in motion.

## Consumers and quality
Use `scripts/audit_denoise.py config.json OUTPUT_DIR` before using candidates. Verify alpha, source hashes, frame order/dimensions, protected pixels, bounded RGB changes and sampled temporal variation. Those checks are not noise-reduction or artistic proof. Compare actual front/rear/side rendered animations with same camera, pose, light, seed, samples and color management; inspect steel edges, seams, hair, cloth grain, fire motion, smoke opacity, flicker. Reject softening or lost motion. Preserve original complete approved frames in Hero Animator; new frames require explicit art approval before replacing. Same rig/action/pose/source identity and timing in all generated assets. Do not treat rendered images as true slices: existing Sprite Stacking derives actual aligned volume slices from geometry or VDB only. Approved 2D projection/fallback uses the same source/timestamp. MaxRects/Basis only after art approval, NanoVDB lossless volume chain unchanged. Runtime has no OIDN, no extra loop or GPU compute; CPU-only offline creation and Canvas2D fallback, WebGL only optional if supported. Effekseer combat, Quarks ambient, Mantaflow/OpenVDB continuous flame, GLSL/PostFX optional hardware renderer; no static fire or duplicated effects. Black Screen Guard remains mandatory. No native installation or improvement claim until actually executed, and no GPU required for CPU workflow. No new game publication from this skill update alone.
