# Rigify hybrid motion bridge v1
Upstream: https://docs.blender.org/manual/en/4.5/addons/rigging/rigify/index.html ; https://developer.blender.org/docs/features/animation/rigify/ . Rigify is GPL; only our original integration scripts are shipped. Blender 4.5 LTS + an independently reviewed compatible Rigify release are external dependencies. The old extension listing is marked disabled by staff, so do not auto-install from it or bypass review. Use a trusted official release ZIP, verify licence, manifest version and independently obtained SHA256. `python scripts/install_rigify.py --blender blender --zip /approved/rigify.zip --sha256 <verified> --version <reviewed> --profile /new/isolated/profile` invokes Blender's documented extension CLI. No online install from an unreviewed source. Native Blender CLI is supported; Nexus CLI-Anything may dispatch only if actual backend and its documented arguments support this task. No fake installation or PASS.

## Producer — Blender Model Animation Enhancer
Only on a copy of a user-approved, authorized true 3D mesh, not on approved PNG/GIF art. Preserve UVs, costume, sword geometry, materials and old rig. Material Maker provides surface maps; PyMeshLab/Instant Meshes may modify pre-rig geometry only after explicit approval; do not automatically retopologize or simplify skin. Use fitted metarig aligned to hips, shoulders, feet, hands; preserve original source hash. Rigify generation is not skinning or automatic good animation. `blender --background /approved/source.blend --python-exit-code 1 --python scripts/rigify_bridge.py -- --config config.json --out /new/output` using the isolated profile. For generation config: mode=generate, source_sha256, metarig (object name). Review generated controls and bind approved mesh/weights manually or using the existing authorized weighting pipeline. Never auto-replace old skinned rig. Author actual clips via IK/FK, existing Open Mocap/Rigger where approved, correct foot lock, counter-rotation of shoulders/pelvis, follow-through sword. No new mocap tool installed by this bridge.

Sampling config: mode=sample, source_sha256 (current approved .blend), hero_id, rig (object name), meshes (array of bound mesh names), bones mapping foot_l, foot_r, hip, sword to actual pose bone names, clips dictionary. Each clip defines action (Blender action name), slot (explicit Blender 4.5 action slot identifier), start/end (inclusive integer frames), contacts {foot_l:[[start,end]],foot_r:[[start,end]]}, root_velocity_mps (three-vector in glTF Y-up world axes; zero for authored root motion, explicit expected velocity for in-place walk), events [{frame,cue,bone}]. Required clips idle, walk, run, jump_start, jump_loop, jump_land, light_attack, heavy_attack, air_attack. Distinguish walking away (rear camera) from backward walking; add backward walk, strafes, turns, three ground combos, jump variants when tasked. Required cues light_hit/heavy_hit/air_hit/takeoff/land; contacts from actual authored poses. Mute NLA for isolated evaluation. Script generates rig-motion.json with source SHA, per-frame bone positions, sword orientation, action cues, contact intervals. It does not automatically author motions, bind skin, export GLB or bake RGBA volume. For those use the existing Blender export and approved real per-pose volume baker; sample identical source, action slot, frames, units and pivot, full volume for every frame. Verify GLB via Khronos Validator before safe glTF Transform/meshoptimizer, verify pose/skin/events survive optimization. Never simplify approved costume or sword to fake quality. Keep source immutable.

## Consumers — META Game Fusion / Hero Animator
In Fusion use runtime/rig-sync.mjs only after actual volume packs exist. Each clipVolumes[clip] has hero_id, source_sha256, fps, poses array of {frame,...actual approved volume references}. applyPose displays full corresponding volume; applySword uses local sword and sword_quaternion_xyzw with same pivot and scale. Do not render duplicate body. Shared clock from existing controller, no second RAF. Rapier remains authority for movement and takeoff/landing; call cue only for authorized events at their actual authored frame, with unique action-occurrence id and world transform, pass to Effekseer emit; never trigger an attack/damage from VFX. If physics event and authored frame differ, reconcile timeline and block visual approval until aligned. Mantaflow continuous flame/smoke; Quarks ambient particles; Effekseer combat VFX. Black Screen Guard stays active. Hero Animator receives only newly approved complete independently rendered frames via its existing character frame gate; never use Rigify to deform existing 2D frames or bypass its no-deformation lock. Do not substitute missing approved frames with generated ones. No double animation controller.

## Animation Quality
`python scripts/motion_gate.py rig-motion.json --max-drift-m 0.04` measures world-space foot drift during explicit contact intervals, adjusted for expected in-place root movement. Threshold is a configurable starting point in metres, not a visual quality guarantee. Review full body front/rear/side and eight yaw views, foot contact, hip/shoulder counter-rotation, weapon grip/orientation, costume deformation, jump ascent/apex/landing, distinct air attack and actual VFX hit sync. Do not report a percentage improvement without real comparable baseline and final renders. Missing assets or runtime = blocked, not PASS. Preserve existing approval gates and no reports unless requested.
