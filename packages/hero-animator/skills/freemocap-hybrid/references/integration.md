# FreeMoCap hybrid capture bridge v1
Upstream https://github.com/freemocap/freemocap/tree/18901a2f4a1007aee25184de8ba37e7c535356b3 ; AGPL-3.0, verified LICENSE and pyproject. Separate offline capture application; no AGPL code copied into the browser or proprietary game. Use an isolated CPU worker and the official release https://github.com/freemocap/freemocap/releases/tag/v2.0.0-alpha.25 (reviewed candidate; installation/runtime not confirmed). Verify release checksum/provenance and dependencies before execution. Do not record people without permission. Do not upload captures to public GitHub; keep source footage local. Native Blender export currently requires MediaPipe, not RTMPose. See https://docs.freemocap.org/guides/blender-export/ and https://docs.freemocap.org/reference/data-arrays/ .

1. Capture authorized real human movement with synchronized calibrated cameras, or import a licensed processed recording. Use FreeMoCap/SkellyForge gap processing and calibration, retain original recording and metadata. Do not infer 3D mocap from the game reference video. Do not imply installing a GUI package from this adapter. No footage supplied means no new captured movements. Open Mocap remains alternative for licensed preexisting motion.
2. Run `python scripts/prepare_capture.py output_data/mediapipe_body_3d_xyz.npy capture.json targets.json` with NumPy. Config: rights_confirmed true, source_sha256, hero_id, tracker mediapipe, clip, explicit marker_names in source array order (from tracker metadata; 33 or 37), start/end inclusive, actual fps, units mm or m, proper orthonormal source_to_blender 3x3 rotation, calibrated floor_z_m. Output contains complete named control targets in Blender Z-up metres. Reject bad units, long gaps, unbounded endpoints, missing names. Only <=2-frame internal gaps are interpolated, count retained; no invented motion beyond measured positions. No automatic smoothing across impact or takeoff. Validate capture visually before retargeting. Script is original, independent of upstream package.
3. Use `blender --background approved.blend --python-exit-code 1 --python scripts/retarget_ik.py -- --capture targets.json --config retarget.json --out new_capture.blend`. Config: source_sha256, targets_sha256, hero_id, rig, action (new), ik_mode_reviewed=true, controls mapping hip/left_ankle/right_ankle/left_wrist/right_wrist to approved non-deform Rigify IK controls, optional shoulder/elbow/knee targets with separately reviewed controls, reference_frame (matching first pose), capture_to_character_scale, start_frame, root_mode world/in_place. Capture and Blender FPS must match. Produces location keyframes from measured displacement. This is NOT full rotational retarget: IK/FK switch, pole targets, twist, spine/shoulder counter-rotation, sword grip/orientation, fingers and cloth remain authored and visually corrected via existing NLA Animation Layers. Do not publish IK draft or overwrite existing action. Retarget only actual approved 3D rig; never deform approved 2D artwork. Use existing Rigify sampling and Animation Layers composition after reviewing feet, axes, root trajectory and constraints. No false claim of fully automated mocap or sword choreography.
4. Required actions: idle/walk/run (front/back/side/8 yaw from same pose; rear view not reversed motion), jump_start/jump_loop/jump_land, light_attack/heavy_attack/air_attack. Add authored hit/takeoff/land cues from reviewed frames; no event inference by motion threshold. Rapier owns root/grounding; choose in_place for player runtime, avoid double motion. Use existing rig-motion-v1 and layer_recipe_sha256 contract, same complete baked RGBA pose frames and sword transform; no interpolation/deformation of approved sprite frames. Existing Effekseer listens to authored cues after real inputs and game physics; Mantaflow fire, Quarks ambience, GLSL/PostFX remain separate. Keep Black Screen Guard.
5. Animation Quality: `python scripts/prepare_capture.py` can validate capture independently; check gaps, scale, calibration, FPS, complete markers, rights. Then existing rigify motion_gate and Animation Layers compare_contacts on actual evaluated target. Check foot placement, back view, silhouette, root motion, jump arc, hit timing, sword alignment and full pose identity visually. No percentage from synthetic data. Missing capture/runtime blocks production, not an artistic PASS. Native install and capture not confirmed in current environment.
