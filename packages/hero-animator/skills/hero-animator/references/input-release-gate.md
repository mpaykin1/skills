# Обязательный выпуск управления — ПК и телефон

Эта инструкция имеет приоритет над прежними примерами управления жестами на всей правой половине экрана. Применяется к каждой игре и ремонту Hero Animator. Не заявлять, что «управление работает», по одному тесту WASD или синтетическому вызову FSM.

## Контракт

- ПК: четыре стрелки и WASD — движение в 3D относительно камеры. ↑ идёт вперёд, ↓ назад; они не включают атаку, прыжок или присед. Для старого 2D режима отдельная явно согласованная схема. Названия left/right относятся к взгляду на экране.
- Игровой canvas получает tabindex=0 и фокус при открытии/касании. Приём mapped keydown/keyup в capture phase с preventDefault для стрелок предотвращает прокрутку и потерю ввода контейнером. Не захватывать ввод текстовых полей и системные Alt/Meta сочетания.
- Распознавать физический KeyboardEvent.code, а при его отсутствии key=ArrowLeft/Right/Up/Down, старые Left/Right/Up/Down и соответствующие keyCode. Отпускание одного из двух источников одного действия не снимает второй источник.
- Атака/прыжок/перекат/уклонение/взаимодействие/пауза/рестарт запускаются только фронтом конкретной клавиши или соответствующей явной кнопки. Повтор keydown при удержании НЕ порождает новый фронт. Не привязывать click после pointerup повторно. Зажатая атака не создаёт автокомбо.
- Запрещено назначать атаку на касание сцены, касание для возврата фокуса, обзор, отпускание пальца или таймер. Запрещены скрытые long-press/double-tap боевые действия. Неподвижный палец на джойстике не приседает автоматически. NPC атакуют автономно по своему FSM; действия игрока учитываются отдельно от NPC.
- Телефон: невидимый плавающий джойстик СЛЕВА (радиус56, deadzone9, аналоговая сила), явные кнопки действий СПРАВА, как принцип управления в «Острове сумерек». Прозрачность кнопок 25% означает CSS opacity:0.75. Не opacity:0.25. Метки действий читаемые, вся цель не менее44×44 CSS px, safe-area, portrait и landscape, кнопки не заходят в левую половину.
- ПК: мобильные кнопки display:none, независимо от узкой ширины окна. Показывать панель только `(pointer:coarse) and (hover:none)`, не по одному размеру экрана и не по наличию maxTouchPoints у ноутбука.
- Один pointerId владеет джойстиком, другие — своими action-кнопками. Отпускание/отмена кнопки не обнуляет джойстик; отпускание джойстика не снимает удерживаемый захват. Для grab/crouch удержание, для attack/jump — один фронт. Кнопка не должна одновременно проходить в обработчик сцены. На blur/hidden очищать keys, pointers И ещё не выполненные edges. pointercancel/lostpointercapture также освобождают владельца.

## Обязательные фактические проверки перед выдачей HTML

1. Запуск без ввода: герой не начинает атаки, прыжки, приседания, ходьбу или подбор. Отличать причинный hurt/death от attack; атака NPC не является атакой игрока.
2. Настоящие ArrowLeft, ArrowRight, ArrowUp, ArrowDown в браузере: координаты меняются в нужную сторону, выбран правильный рисованный вид; после отпускания остановка. Проверить click-to-focus и возврат фокуса. Отдельный unit regression проверяет key-only/legacy события.
3. Одно нажатие J, включая автоповторы ОС при удержании, даёт ровно одну атаку. После отпускания/blur новых атак нет. Клики/касания по пустой сцене и камерные движения не создают attack.
4. ПК с узким и обычным окном — ноль видимых touch-кнопок. Телефон390×844 и844×390 — панель справа, opacity0.75, размер>=44, без перекрытий/выпадения за экран.
5. Реальный мультитач: удерживать левый джойстик и нажать правую кнопку; правую отпустить — левый остаётся активным. Отменить любой указатель — его действие перестаёт удерживаться. Проверить несколько jump, roll, dodge, crouch, pause/resume, restart; grab/throw проверять с реальной достижимой целью, не вызывать state напрямую.
6. Автономность: HTML содержит собственные JS/изображения, нет CDN/import/fetch. Если инструменты запрещают file://, не обходить запрет: тестировать страницу в менее привилегированном origin на loopback HTTP и честно указывать эту область проверки. Сервер выдаёт только конкретный игровой файл; внешние запросы блокируются.

Исполняемые проверки: `scripts/test_input_regressions.mjs` (code/key, ownership, repeat, blur) и `scripts/test_controls_game.mjs GAME.html OUTPUT_DIR` с установленным Playwright через HERO_PLAYWRIGHT_MODULE. Вторая проверка обслуживает только /game на127.0.0.1. Для существующего автономного infinite HTML: `python scripts/repair_infinite_controls.py OLD.html NEW.html`; ассеты ASSETS и HERO_PACK проверяются на неизменность. Для исходного legacy HTML продолжать `infinite_ash_game.py` с реальным пакетом. Не выдавать техническую проверку ввода за новое художественное одобрение кадров.
