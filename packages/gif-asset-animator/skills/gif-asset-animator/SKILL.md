# GIF — Живой ассет

## Цель и вход
Получить готовые игровые анимации, а не инструкцию пользователю. Вход: изображения, GIF, спрайтшиты или модель пользователя и описание действий (либо только объект, тогда самостоятельно выбрать подходящие действия). Любой художественный стиль; стиль всегда берётся из конкретного референса, а не из шаблонного хоррора. Имена, количество, размеры, направление, ракурс, скорость и режим повтора, явно заданные пользователем, приоритетны. Не требовать ручной работы, если исходник уже доступен. Не редактировать оригиналы.

## 1. Паспорт внешности и план движений
- Открыть точные исходные файлы, декодировать все GIF-кадры с учётом disposal, прозрачности и длительности. Не заменять исходную GIF одним скриншотом. Найти исходники всех ракурсов и сопоставить их с объектом.
- Зафиксировать силуэт, пропорции, анатомию, число конечностей, костюм, руки, узоры, материалы, характерные повреждения, цвет, освещение, живописную фактуру, масштаб, ракурс и точку привязки. Для неподвижных деталей (рама, корпус, декор) сделать защищённую маску.
- Для каждого движения определить начало, ключевые позы, завершение, направление, длительность, неподвижные области, траекторию, режим повтора и необходимую область холста. По умолчанию 12–16 кадров, 80–100 мс на кадр, постоянный холст, прозрачный фон.
- Различать экранное движение, изменение перспективы и анимацию на месте. Увеличение при броске к камере разрешено как намеренная перспектива, но не как замена самого броска. Не менять базовый масштаб или pivot между разными действиями без необходимости.

## 2. Источники кадров и движение
Приоритет: исходные полные кадры нужных поз > исходная 3D-модель с настоящим рендером поз > новые полноразмерные согласованные ключевые кадры из того же референса с помощью доступной генерации/редактирования изображений. Для новых ракурсов нужны действительно разные изображения геометрии; поворот плоского изображения, зеркалирование асимметричного объекта и масштабирование не являются новыми ракурсами. При генерации использовать одинаковый референс и паспорт внешности на каждом кадре, равные ячейки без надписей и рамок, целый объект в каждой ячейке. Не генерировать независимых случайных персонажей.
- Для персонажей обязательны читаемые анатомические фазы движения. Атака: подготовка, перенос веса, выпрыгивание/удар, кульминация, завершение. Отступление: реальные шаги назад, разворот, уход; исчезновение только если запрошено. Ходьба/бег: смена опорных ног, согласованность рук, без скольжения. Для полного изменения позы запрещены резиновое деформирование, растягивание пикселей, сдвиг частей плоской картинки вместо суставной анимации, покачивание всего спрайта вместо ходьбы или атаки.
- Для неподвижных предметов сохранить точные исходные пиксели в защищённых областях на всех кадрах. Движение внутри зеркала, экрана или проёма композить только внутри маски. Для жёстких предметов движение всего объекта допускается, когда это действительно запрошенное перемещение.
- Эффекты: самостоятельные кадры частиц/дыма/света, распределение по времени и затухание, сохранение основной формы до момента разрушения. Допустима компоновка из исходных слоёв для физически корректного движения и исчезновения, но не для имитации отсутствующей анатомии или ракурса.
- Интерполяция допустима лишь между согласованными ключевыми кадрами при отсутствии двоения, морфинга и деформации. Не повторять одну статичную картинку ради числа кадров. Не выдавать кроссфейд за полноценную анимацию движения. Не утверждать, что движение создано, если генератор или модель недоступны.

## 3. Прозрачность и GIF
Сохранить исходный alpha-канал. При непрозрачном фоне создать маску объекта, для однородного фона удалить только фон с учётом связности с границей; сохранить совпадающие цвета внутри объекта. Устранить matte/цветной ореол, проверить на светлом и тёмном фоне. Не удалять тёмные части монстра, глаза, тонкие рога, дым и прозрачные края. Не рисовать шахматку. GIF имеет только бинарную прозрачность; для мягкого тумана использовать стабильный пространственный alpha-dither, при необходимости дополнительно APNG по запросу. Каждый GIF: 10–16 кадров по умолчанию, если пользователь не назначил другое; единый холст, корректная задержка, настоящий прозрачный индекс, без текста. Для цикла — плавный переход последнего кадра в первый без дублирования крайних фаз. Для одноразовой анимации — нет NETSCAPE loop extension; последний кадр сохраняет заданную позу либо полностью пустой, если требуется исчезновение. Не делать одноразовую анимацию бесконечной ради демонстрации.

Используй `scripts/gif_pipeline.py` с Pillow и NumPy в доступной вычислительной среде: это локальный экспортёр, не генератор поз. Он принимает готовые RGBA PNG-кадры, сохраняет каждый физический кадр даже при совпадении соседних, прозрачный индекс, правильный disposal, проверяет декодированные кадры и режим повтора. Если файл скрипта недоступен напрямую, прочитай его через инструмент чтения bundled skill files, материализуй и запусти. Не считать работу завершённой только потому, что скрипт существует.

```
python gif_pipeline.py extract source.gif frames_source
python gif_pipeline.py encode frames_motion/ attack.gif --duration 90 --once
python gif_pipeline.py encode frames_fade/ vanish.gif --duration 90 --once --empty-last
python gif_pipeline.py encode frames_idle/ idle.gif --duration 90 --dither
python gif_pipeline.py pack game_anim.zip attack.gif vanish.gif idle.gif
```

## 4. Внутренний визуальный контроль и исправления
Перед публикацией открыть реальные декодированные кадры и проверить последовательность движения (первый, ключевые, промежуточные, последний и шов цикла). Сравнить с референсом. Проверить чистые края на двух фонах, сохранение идентичности и защищённых областей, отсутствие лишних конечностей, текста, скачков, клиппинга, изменения масштаба без причины, неподвижных фальшивых GIF, смещения pivot, соответствие заданным позам. Сначала исправить обнаруженные дефекты и повторно проверить, затем показать. Числовая проверка формата не доказывает художественное качество. Если ошибка неустранима текущими инструментами, не выдавать дефектный файл за готовый; назвать только оставшийся блокер.

## 5. Выдача и продолжение
- Сразу по готовности каждого ассета показать настоящий анимированный GIF в чате (inline Markdown на реально созданный путь либо анимированное изображение встроенного инструмента). Под ним только имя, размер в пикселях, фактическое число кадров, режим повтора. Никогда не заменять GIF статичной PNG, листом кадров или одним ZIP. Если клиент отображает первый кадр, честно указать ограничение: нельзя гарантировать воспроизведение в UI. Предоставить сам GIF и при необходимости просмотрщик с кнопкой повторного запуска; это не считается подтверждением, что пользователь видел движение.
- По завершении основного списка предложить или создать два дополнительных тематических движения, если пользователь поручил их или не ограничил список. Не откладывать запрошенные элементы ради дополнительных.
- Собрать один ZIP с теми же показанными GIF; имена и байты совпадают, архив содержит только готовые ассеты. Проверить CRC и состав. Ссылка на реально созданный ZIP. Не подменять анимацию описанием, не писать отчёты, тестовые журналы и handoff без запроса.
- При повторном запросе проверить текущий чат и доступные артефакты: пропустить уже предъявленные корректные файлы, продолжить с отсутствующих. Если пользователь не увидел движение или файл дефектный, повторно показать/исправить именно его, не объявлять автоматически выполненным. Не перегенерировать утверждённый ассет без запроса.
