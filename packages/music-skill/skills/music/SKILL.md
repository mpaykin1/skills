# MUSIC — Piano Engine

Используй настоящий MIT-движок https://github.com/stmn/piano-music-generator, не подменяй его случайными нотами или готовой записью. Сначала запусти `python3 scripts/fetch_upstream.py` из каталога этого скилла (или получи указанные файлы через GitHub connector и сохрани без изменений в `scripts/vendor/`). Проверяй blob SHA по списку скрипта. Не исполняй непроверенный код. Для автономной сборки включай скачанные модули и LICENSE. Если недоступны исходники или Node.js, явно сообщи об этом; не заявляй, что музыка создана.

## Возможности и ограничения
20 реальных пресетов upstream: nocturne, prelude, ballade, sonatina, march, chorale, elegy, etude, tango, minimal, ragtime, waltz, minuet, mazurka, polonaise, gymnopedie, barcarolle, lullaby, tarantella, blues. Лады: major, minor, dorian, mixolydian, lydian, phrygian. Тоника, seed, melodySeed, leftSeed, tempo. Темп 6/8 измеряется в пунктирных четвертях. Иные жанры и формы (джаз, рок, рапсодия) пока не реализованы как самостоятельные стили; адажио — темп, можно использовать с любым подходящим пресетом. Не выдавай аппроксимацию за полную форму. Блюз имеет специальную 12-тактовую структуру, остальные пресеты преимущественно текстурные.

## Создание музыки
Выполни `node scripts/compose.mjs --style nocturne --root D --mode minor --tempo 60 --seed 123 --out /mnt/data/nocturne`. CLI создаёт MIDI, MusicXML и JSON нот. Для аудио используй исходный интерфейс https://stmn.itch.io/piano-music-generator либо интегрируй лицензированный рояль с Web Audio/Tone.js; не утверждай, что MIDI является WAV. CLI compose.mjs выдаёт ноты; отдельный Open Music рендер (см. ниже) выдаёт WAV. Сохраняй темп, тональность, seed, стиль, партии рук. Отдавай готовые файлы, не проси пользователя вручную вставлять код.

## Адаптация к игре
Модуль `scripts/engine.mjs` экспортирует compose, performance, AdaptiveMusic. Связывай состояние игры calm/explore/danger/combat/victory с параметрами интенсивности. `request(event)` меняет только ожидающее состояние; `next()` вызывается на границе законченного произведения. Планируй следующее произведение заранее, не перезапускай звучащую музыку на каждом действии. Сохраняй общую тональность, воспроизводи ноты с естественными временами, педалью и динамикой из performance(). Не называй это непрерывным развитием одного мотива: upstream создаёт отдельные законченные пьесы. Для дальнейшего расширения требуются переходы на уровне фразы, сохранение мотивов между формами и настоящие жанровые правила. Не обещай мгновенные смены внутри такта. Ограничивай полифонию и освобождай ресурсы после проигрывания; не делай генерацию в каждом кадре. В SYMPHONIA действия игрока управляют характером музыки, а не фиксированным плейлистом.

Сохраняй MIT-атрибуцию исходного кода. Используй только оригинальные генерируемые темы; лицензии тембров и семплов проверяй отдельно. Не изменяй защищённые проекты пользователя без запроса.

## Второй движок: NotaGen-X + процедурные вариации (v0.2)
Оригинальный проект MIT: https://github.com/ElectricAlexis/NotaGen ; веса с MIT-меткой: https://huggingface.co/ElectricAlexis/NotaGen . NotaGen-X генерирует классическую партитуру по доступной комбинации эпоха–композитор–инструментация. Выбирай соло фортепиано, проверяй реальные комбинации из upstream `gradio/prompts.txt`. Используй официальный https://huggingface.co/spaces/ElectricAlexis/NotaGen либо локальный `gradio/demo.py` по upstream `gradio/README.md` (Python 3.10, PyTorch 2.3, GPU около 8 GB VRAM; веса не включены). При программном обращении к Space сначала проверь фактическую схему API через gradio_client, не выдумывай endpoint. Используй только разрешённые бесплатные ресурсы; не жди нейросеть в игровом цикле. Сохраняй подлинный MusicXML результата. Без доступа к инференсу честно используй только первый движок, не выдавай процедурную пьесу за NotaGen.

Связка реализована в `scripts/notagen_motif.py` и `scripts/hybrid.mjs`. Получи XML соло фортепиано из NotaGen, затем `python3 scripts/notagen_motif.py original.musicxml motif.json`; это извлекает интервальный и ритмический контур шестизвучных мотивов верхнего стана, с SHA256 источника. Далее `node scripts/compose.mjs --style nocturne --root D --mode minor --seed 123 --motif motif.json --out /mnt/data/hybrid`. Генерируются 8 полноценных кандидатных произведений первого движка, выбирается наиболее близкое к банку мотивов по интервалам и относительному ритму; исходные гармония, бас, фактура, педаль и нотная разметка не ломаются. Это выбор по сходству, не буквальное продолжение темы и не гарантированное точное цитирование мотива. Не скрывай большую дистанцию; при низком сходстве оставляй оригинал или пробуй другой seed. Сохраняй исходную партитуру отдельно. Для SYMPHONIA передавай один и тот же `motifBank` в `new AdaptiveMusic({root,seed,motifBank})`, чтобы разные игровые состояния выбирали родственные вариации; готовь их заранее вне игрового кадра, переключай на границах пьес. Без банка остаётся прежнее поведение. Не заявляй, что появилось управление произвольной сонатной/симфонической формой: NotaGen не гарантирует форму, рок или джаз. Для релиза проверяй лицензии кода, весов, семплов и оригинальность результата отдельно. Не добавляй отчёты без запроса.

## Третий движок: Open Music 0.3.0 (v0.3)
Оригинал https://github.com/jdsalasca/open-music (MIT), Node >=22, без сторонних npm-зависимостей. Скачай оригинальные модули и LICENSE через `python3 scripts/fetch_open_music.py` (проверка Git blob SHA каждого файла). Если сеть недоступна, получи именно эти файлы через GitHub connector и проверь SHA перед выполнением. Не подменяй оригинал синтезатором-заглушкой.

Единая цепочка трёх движков:
1. NotaGen-X создаёт оригинальную классическую партитуру вне игрового цикла; `notagen_motif.py` извлекает банк мотивов.
2. Piano Music Generator через `compose.mjs --motif motif.json --style nocturne --root D --mode minor --seed 123 --out /mnt/data/theme` выбирает родственную процедурную пьесу и экспортирует MIDI, MusicXML, JSON с выразительными таймингами и педалью. Без банка работает как раньше.
3. `node scripts/render_open_music.mjs /mnt/data/theme.json /mnt/data/theme.wav` использует настоящий Open Music Studio.piano и DSP для WAV; `--orchestra` добавляет тихие струнные и флейту на выдержанных нотах, сохраняя высоту, ритм и гармонию исходной партии. Это синтетический тембр, не семплированный концертный рояль. Не выдавай MIDI исходной фортепианной партии за оркестровую партитуру. JSON и MusicXML сохраняй рядом. Если рендер невозможен, сообщи и сохрани исходные ноты.

Нативные крупные формы Open Music — отдельный дополняющий режим: `node scripts/open_music/src/cli.js presets`; `node scripts/open_music/src/cli.js form --preset symphony`; `node scripts/open_music/src/cli.js generate --preset symphony --out /mnt/data/symphony.wav --midi /mnt/data/symphony.mid --seed 7`. Пресеты: symphony (сонатная форма: grave, exposition, development, recapitulation, coda), dark-fantasy (семь разделов), galactic, bound-soul, soviet-march. Можно менять длительность `--duration` в рамках оригинального CLI; для MP3 нужен ffmpeg. В нативной симфонии тематический материал задан самим upstream; она пока не принимает мотив NotaGen, не заявляй обратного. Open Music предоставляет готовую форму и тембры, а не универсальный сочинитель всех музыкальных форм.

Для игры генерируй и рендери музыку вне игрового кадра; используй банк мотивов для разных состояний, готовь следующие аудиофрагменты заранее. Переключай на музыкальных границах с коротким кроссфейдом без обрезания фраз; текущий адаптер меняет состояние на границе пьес, а не произвольно внутри такта. Не запускай Node Studio в браузере. Браузер воспроизводит подготовленные WAV/сжатые аудио или существующие ноты. Сохраняй прежние 20 пресетов, все функции NotaGen и экспорт MIDI/MusicXML. Не добавляй платные зависимости.

## Четвёртый движок: HarmoniaTextor 2.5.0 (v0.4)
Оригинал MIT: https://github.com/xhdlphzr/HarmoniaTextor, проверенная ревизия `a631407b026c7f9934c900988de7eb93ffb1a68f`. Подключай настоящие upstream `genres.build_default_registry`, `techniques.helpers.invert_notes`, `checker.CheckEngine`, не выдавай самодельную проверку за него. Upstream требует Python 3.14+ и music21; установка в отдельном окружении с uv, исходный репозиторий закреплён на указанной ревизии. Не подключай платный API, desktop, голосовые модели и необязательные звуковые зависимости для этой связки. Установи только необходимые зависимости символического ядра (music21>=10, pydantic>=2.6, PyYAML при необходимости) в Python 3.14 venv, добавь `src` закреплённого checkout в PYTHONPATH; при ошибке импортов не имитируй движок. Проверь доступность оригинальных модулей. Лицензия MIT относится к коду, не к сторонним voicebank или иконкам; их не распространять.

`python scripts/harmonia_bridge.py plan symphony` возвращает настоящие четыре шаблона частей upstream; `plan sonata` и `plan concerto` — по три. `develop motif.json developed.json` вызывает оригинальную инверсию темы; `--technique augmentation` или `diminution` преобразуют интервалы времени по той же математике (это адаптация для формата мотивов, не полный вызов upstream техники). Мотивы остаются совместимыми с `hybrid.mjs` и `compose.mjs`. `check piece.musicxml --genre sonata --tonic d` использует настоящий CheckEngine с контекстом выбранного жанра и финальной каденцией. Проверка может отвергнуть фортепианные фактуры; не ослабляй правила ради прохождения.

Единый маршрут четырёх движков: NotaGen-X MusicXML → `notagen_motif.py` → `harmonia_bridge.py suite --genre sonata --motif motif.json --root D --mode minor --seed 123 --out /mnt/data/sonata` → шаблоны частей и тематическая инверсия HarmoniaTextor → выбор целых процедурных пьес Piano Music Generator → проверка партитур HarmoniaTextor → Open Music WAV каждой принятой части. Сохраняются MIDI/MusicXML/JSON и отдельные WAV, упорядоченные через suite.json. Все части сначала генерируются во временном каталоге; если нет принятого кандидата, не публикуй непроверенный набор. Не выдавай эту компоновку за строгую сонатную форму внутри части или полноценный концерт с солистом и tutti: она соблюдает шаблон частей, а мотивы подбираются по близости, не являются гарантированно тождественными. В оркестровом режиме действует существующее осторожное удвоение нот, не полный оркестр. Для нативной одночастной сонатной формы сохраняется отдельный пресет Open Music. Игровые состояния могут выбирать прежние и преобразованные банки мотивов вне кадра. Сохраняй предыдущие три движка, команды и форматы. Не выдавай наличие адаптера за проверенный инференс: доступ к Python 3.14, оригинальному коду и весам NotaGen обязателен для полной цепочки; при недоступности честно укажи ограничение. Не добавляй отчёты без запроса.


## MMA — пятый движок: жанровый аккомпанемент (v0.5.0)
Источник: https://github.com/infojunkie/mma/tree/c52943c31aa1e64fa9b5313620d5065f91c22773 (GPL-2.0-or-later). Использовать отдельным процессом, не копировать GPL-код в MIT-модули; при распространении самого MMA соблюдать GPL. Установить upstream отдельно (без оплаты), зафиксировать commit, выполнить его `mma.py -G` для базы groove при необходимости, `MMA_HOME` должен указывать на checkout; Python с `mido` требуется для адаптера. Не выдумывать доступность установки или результат. Не скачивать платные зависимости.

- Джаз SwingWalk, блюз Blues, рок 8Beat, босса-нова BossaNova (4/4), вальс Waltz (3/4). Это подлинные upstream groove, а не новый генератор мелодий. Для рока/джаза сначала выбирается подходящий 4/4 фортепианный пресет; не выдавать аккомпанемент за самостоятельную полноценную форму.
- Передавать JSON и MIDI от `compose.mjs` (с выбранным/развитым мотивом NotaGen-X/HarmoniaTextor при наличии). Адаптер `mma_bridge.py` строит MMA-партитуру из точных pitch classes и гармонических смен; отклоняет несовместимый размер или неизвестные аккорды. Не менять исходную мелодию, не использовать произвольные независимые аккорды.
- `python scripts/mma_bridge.py piece.json --genre jazz --out jazz --mma /absolute/path/to/mma.py` создаёт `.mma`, объединённый `.mid` и `.json`; передавать полный путь установленного upstream. Для просмотра партитуры без MMA: `--chart-only`. При ошибке не подменять результат синтетическим фейком. Исходные MusicXML, MIDI и JSON сохраняются. Аккомпанемент добавляет бас и ударные, избегая второго конкурирующего клавишного сопровождения. MIDI сохраняет исходную карту rubato и темпа; события MMA пересчитываются по этой карте. Для результата с нотами исходный MusicXML описывает лишь фортепиано, не новый ансамбль.
- `node scripts/render_open_music.mjs jazz.json jazz.wav` синтезирует исходное фортепиано и слой MMA через Open Music. WAV использует редукцию ударных на поддерживаемые голоса; объединённый MIDI сохраняет все исходные события баса/ударных. Не заявлять точное GM-воспроизведение всех инструментов в WAV. При переходах между жанрами заранее подготовить совместимые по размеру и тональности фразы, переключать их на границе фразы, не запускать Python на игровом кадре. Не утверждать, что это уже бесшовная генерация в браузере.
- Общая цепочка: NotaGen-X → HarmoniaTextor → Piano Music Generator → MMA (ритм по той же гармонии) → Open Music (общий синтез). Если тяжёлые компоненты недоступны, первый движок работает как прежде; ни один предыдущий режим не удалён. Проверка контрапункта применяется к исходной классической партитуре; правила строгого контрапункта не навязывать джазовой или роковой ритм-секции.


## Magenta.js — шестой движок (v0.6.0)
Источник https://github.com/magenta/magenta-js, пакет @magenta/music 1.23.1 (Apache-2.0 для кода), официальная модель chord_pitches_improv. Проверь отдельные условия весов перед распространением, не включай их без проверки. Подключение без оплаты, в браузере, с загрузкой пакета и весов по сети. Не выдавай выбор вариации за точное продолжение и не имитируй нейросеть при ошибке.

`scripts/magenta_bridge.mjs` принимает JSON `piece` от compose.mjs, извлекает верхнюю монодическую линию одного такта, квантует в 4 шага на четверть, передаёт точную гармонию из pitch classes (один символ на шаг) и вызывает настоящий MusicRNN.continueSequence. Поддерживаются простые 3/4 и 4/4, не 6/8. При неподдерживаемой гармонии, пустом мотиве или переполненном банке оставить прежнюю музыку. Для 1–4 тактов продолжения выбирай диапазон внутри исходной пьесы. Не утверждай, что chord conditioning гарантирует отсутствие диссонансов.

Используй `scripts/magenta.html` и соседние `magenta_bridge.mjs`, `hybrid.mjs` через локальный HTTP-сервер или размещение в разрешённом веб-превью (не file://). HTML загружает фиксированную версию библиотеки; в релизе локально закрепляй и проверяй все зависимости и лицензии. Встраивание: импортировать MagentaMotifs из bridge, создать экземпляр с настоящим объектом mm, вызвать generate(piece,{bar:0,bars:2,previous:motifBank}), получить bank и continuation. Нейросетевое продолжение извлекается в совместимые шестизвучные мотивы, прежний банк не удаляется. Не запускать инференс в каждом кадре; один экземпляр модели, максимум одна активная генерация; при недоступности сети использовать прежний банк.

Единая цепочка: NotaGen-X → HarmoniaTextor → Piano Music Generator (тема и гармония) → Magenta.js (нейросетевые продолжения по этой гармонии) → общий банк мотивов → новый выбор целой пьесы через compose.mjs --motif → MMA (аккомпанемент по её аккордам) → Open Music (синтез). Проверяй новые классические партитуры HarmoniaTextor при доступности. Мотивы могут быть развиты HarmoniaTextor и переданы AdaptiveMusic. Сохраняй исходную пьесу и MIDI/MusicXML. Magenta не заменяет готовую партию напрямую, чтобы не разрушить гармоническую/нотную разметку, и не гарантирует тождество тем. Само обучение, скачивание весов и воспроизведение не заявлять выполненными без реального запуска. Все предыдущие режимы сохранены.


## Modular Riffs — седьмой движок (v0.7.0)
Оригинал MIT: https://github.com/philoking/modularriffs. `python scripts/fetch_modular_riffs.py` загружает пять оригинальных модулей и MIT LICENSE по проверенным Git blob SHA. Не подменять upstream генератор самописным и не заявлять загрузку без реального результата. Node 22 или браузер ESM, без Web MIDI и дополнительных платных зависимостей.

- `node scripts/modular_cli.mjs styles` — реальные 24 стиля upstream. `node scripts/modular_cli.mjs live /mnt/data/riffs.json jazz 32 symphonia` — оригинальные generateSong, extendSong, JamGenerator.generateBar; JSON с четырьмя партиями pad/bass/arpeggio/lead и нормализованными событиями performance. `node scripts/render_open_music.mjs /mnt/data/riffs.json /mnt/data/riffs.wav` — синтез через Open Music. Это фортепианная редукция, не точное воспроизведение модульного синтезатора.
- Для бесконечной игры импортируй `loadModular, LiveRiffs` из modular_bridge.mjs, создай `new LiveRiffs(await loadModular(), {style:'cinematic',seed:'chapter-1'})`. Вызов `next()` производит очередной такт, `request({style:'rock',energy:.85,bpm:130})` меняет фактуру и темп на следующем ещё не запланированном такте. `evolve` влияет на вариации и будущие блоки; уже построенная гармония не заменяется немедленно. Планировать звук с lookahead вне кадра, не запускать отдельную музыку на каждое событие. Это генератор событий, не готовый WebAudio-транспорт; браузерный аудиопланировщик подключается в игре. Состояние upstream сохраняет историю тактов, поэтому бесконечность не означает постоянное потребление памяти. Не обещай отсутствие повторов для всех seed.
- `node scripts/modular_cli.mjs motifs /mnt/data/motif.json /mnt/data/riffs.json` извлекает шестизвучные мотивы lead; необязательный последний аргумент — предыдущий банк. Далее тот же `harmonia_bridge.py develop` и `compose.mjs --motif`, Magenta принимает новую пьесу. Не заявлять, что мотивы гарантированно тождественны.
- `node scripts/modular_cli.mjs locked /mnt/data/layered.json /mnt/data/piano.json cinematic` — исходная фортепианная композиция не переписывается: в режиме 4/4 и одного аккорда на такт оригинальный генератор строит тихий pad по точным pitch classes и карте времени Piano Music Generator. Дополнительные партии задаются через addRiffs API; бас нельзя добавлять при наличии MMA, lead выключен для защиты исходной мелодии. При сменах аккордов внутри такта или другом размере режим отклоняется без упрощения гармонии. Open Music рендерит общий performance; прежние MusicXML/MIDI описывают исходную партию, не новые слои. С MMA сохраняется backing.
- Общая цепочка: NotaGen-X → HarmoniaTextor → Piano Music Generator → Magenta → банк мотивов; Modular Riffs добавляет альтернативные живые мотивы и непрерывную форму, либо сопровождает согласованные исходные аккорды; MMA и Modular Riffs не дублируют бас; Open Music синтезирует общий результат. Старые шесть режимов сохранены. При отсутствии сети сохранять прежнюю музыку; не подделывать новые события Modular Riffs. Проверять воспроизведение реального upstream перед заявлением готовности.

Не запрещает хроматику, задержания, проходящие и заимствованные звуки; не выдумывает аккорд при несовпадении pitch classes. Без `--motif` оценивает только гармонические метрики. - Используй проверенный `analyzed.json` как исходник MMA и Modular Riffs locked mode: обе программы по-прежнему получают оригинальные pitch classes, без смены аккордов и времени. ## Tone.js — девятый модуль (v0.9.0)
Оригинал MIT: https://github.com/Tonejs/Tone.js ; закреплён `tone@14.9.17` в scripts/package.json. Tone.js — браузерный звуковой выход, а не новый композитор. Open Music сохраняется для офлайн WAV и оркестрового рендера. Браузерный выход использует синтезированные тембры, не семплированный рояль. Не обещай идентичное WAV звучание.

- `npm install --prefix scripts --ignore-scripts --no-audit --no-fund` устанавливает Tonal и Tone.js. Закрепляй lockfile и локальный bundle `node_modules/tone/build/Tone.js` при поставке; демонстрация `scripts/tone_player.html` использует фиксированный CDN. Открывать через HTTP-сервер, аудио запускается только после пользовательского жеста. Для режима живой музыки предварительно нужен оригинальный Modular Riffs (`fetch_modular_riffs.py`). Не выдавай HTML без зависимостей за автономный файл.
- `ToneMusic(Tone)` из `scripts/tone_bridge.mjs`, `await player.start(source)` принимает JSON от compose, MMA, Tonal, Modular Riffs или объект `{notes,totalSeconds}` из AdaptiveMusic. Исходные `start/end` в секундах и velocity не переписываются, включая rubato и pedal. Партии pad/bass/arp/lead маршрутизируются отдельно; ударные MMA редуцируются до kick/snare/hat, остальные остаются в MIDI. Дублирование bass MMA и Modular Riffs запрещено. - Живой режим: `const live = new LiveRiffs(await loadModular(), {style:'cinematic',seed:'chapter-1'}); await player.start(live,{live:true}); player.request({style:'rock',energy:.9,bpm:132});` — новые события планируются по абсолютному аудиочасу Tone.js с ограниченным lookahead, изменения вступают на следующем ещё не запланированном такте. Не перезапускай плеер при каждом ударе. `player.setVolume(0.8)` плавно меняет громкость; `player.stop()` очищает таймер, очередь и звуковые узлы. Нет гарантии отсутствия разрывов при фоновом throttling; просроченные ноты пропускаются, при отставании на целый такт живой поток может сдвинуться вперёд. При недоступности библиотеки сообщить, а не заменять реальное воспроизведение фиктивным результатом. Не вызывать тяжёлый ML на аудиопланировщике. Долгие партии upstream сохраняют историю, её память не ограничена этим адаптером.
- Единый pipeline: NotaGen-X/HarmoniaTextor/Magenta → мотивы → Piano Music Generator + Tonal → MMA/Modular Riffs → общий performance → Tone.js (игра) или Open Music (WAV). Лимитер защищает выход от пиков, но синтезатор ограничивает полифонию. Полное реальное браузерное звучание проверять отдельно от проверки адаптера. Все прежние восемь интеграций сохраняются.

## FluidSynth — двенадцатый модуль, v0.12.0

Upstream: https://github.com/FluidSynth/fluidsynth (LGPL-2.1-or-later); API: https://www.fluidsynth.org/api/group__audio__rendering.html. Используй настоящую системную библиотеку libfluidsynth 2.x через ctypes в `scripts/fluidsynth_bridge.py`; не подменяй результат синусами. SoundFont имеет отдельную лицензию: не распространяй банк без проверки прав, укажи автора/лицензию в игре. Банк Salamander SFZ/FLAC не является SF2 и не передаётся FluidSynth напрямую; его отдельный Tone.js путь сохранён.

### Единая цепочка
- NotaGen-X, Magenta.js, HarmoniaTextor, music21 и Tonal формируют/проверяют мотивы и гармонию, Piano Music Generator создаёт партитуру.
- MMA экспортирует MIDI с аккомпанементом и исходной картой темпа. Modular Riffs добавляет партии в performance JSON; не дублируй бас MMA.
- FluidSynth рендерит MIDI (форматы 0/1, PPQN, темп, программы, CC включая sustain, pitch bend, aftertouch) либо общий JSON (фортепиано, pad, bass, arp, lead и GM percussion). MIDI сохраняет программы исходника; JSON использует явные GM программы и общий секундный таймлайн. Перекрывающиеся одинаковые ноты JSON повторно атакуются, отпускание последней освобождает клавишу. MIDI SysEx и SMPTE не поддержаны.
- Open Music остаётся процедурным рендерером. Tone.js + Salamander остаётся браузерным интерактивным путём. FluidSynth предназначен для офлайн-рендера главы или коротких фраз до 360 с, не запускай его в игровом кадре. Для аудиоконтента из MIDI сохраняй оригинал; проверяй, что ноты/темп не изменены. Для JSON не теряй MMA backing; уже объединённый MIDI повторно не смешивай.

### Готовый экспорт
```sh

python3 scripts/fluidsynth_bridge.py /mnt/data/chapter.mid /mnt/data/chapter.wav
python3 scripts/fluidsynth_bridge.py /mnt/data/chapter.json /mnt/data/chapter-live.wav --rate 32000
# При необходимости указать другой лицензированный GM банк:

```

Не добавляй платные зависимости. 16-bit stereo WAV, ограничение полифонии 128, потоковые буферы до 4096 кадров, хвост реверберации 1.5 с. Не перезаписывает существующий файл. Если движок или банк недоступен, явно сообщи, что рендер не выполнен, и используй существующий Open Music/Tone.js путь при наличии. Не выдавай синтезированный GM рояль за Salamander.

## FFmpeg — тринадцатый модуль, v0.13.0

Используй установленный FFmpeg/ffprobe отдельным процессом; лицензия сборки зависит от конфигурации (LGPL/GPL), не включай бинарники без соблюдения их лицензий. Адаптер `scripts/ffmpeg_bridge.py` работает с реальным FFmpeg, не подменяет аудиорендеринг. Исходные партитуры и исходники звука не перезаписываются.

- `python scripts/ffmpeg_bridge.py chapter.json --out chapter.ogg` либо `chapter.mid` — вызывает уже существующий FluidSynth адаптер, затем мастеринг и экспорт. `--soundfont` выбирает законно установленный SF2/SF3. Для точного Salamander звучания сначала используй отдельный семплерный путь, FluidSynth GM его не заменяет.
- `python scripts/ffmpeg_bridge.py chapter.wav --out chapter.m4a` — мастеринг WAV из Open Music, FluidSynth или записанного оригинального Tone.js/Salamander исполнения. Альтернативные полные рендеры одной партитуры не смешивай: выбирай один.
- `python scripts/ffmpeg_bridge.py piano.wav backing.wav --weights 1 .65 --out chapter.ogg` — сведение только взаимодополняющих, заранее синхронизированных с нулевого времени партий; длительности должны совпадать в пределах 100 мс. Не удваивай бас MMA/Modular Riffs и не смешивай полный микс с его же составляющими. Скрипт не определяет автоматически музыкальную синхронизацию, её обеспечивает предыдущий общий таймлайн. Для динамических слоёв игры сохраняй оригинальные стемы и их общий таймлайн; не нормализуй каждый независимо, иначе нарушится баланс.
- Двухпроходная EBU R128 нормализация: по умолчанию -18 LUFS, максимум -2 dBTP (контроль после кодирования с допуском 0.35 dB), LRA 20, линейный режим при возможности, динамический при необходимости. Целевая громкость проверяется с допуском 2 LUFS; тишина, несовпадение длин и нарушение ограничений отклоняются. Все операции вне игрового кадра. Не обещай бесшовные петли в lossy форматах: это экспорт целых фраз/композиций, не loop редактор.
- WAV PCM16, OGG Opus 96 kbps VBR, MP3 128 kbps, M4A AAC 128 kbps; браузер выбирает поддерживаемый формат. Храни мастер WAV для повторной обработки, не перекодируй lossy повторно. Сохраняй атрибуцию семплов и SoundFont рядом с игровым аудио. При отсутствии FFmpeg оставь исходный WAV, не выдавай несозданный файл за готовый. Все 12 предыдущих модулей сохранены, включая интерактивное воспроизведение Tone.js и оригинальный экспорт MIDI/MusicXML. Не добавляй отчёты без запроса.


## Librosa — четырнадцатый модуль, v0.14.0

Оригинал https://github.com/librosa/librosa (ISC), `librosa==0.11.0`; установка `python -m pip install -r scripts/requirements-librosa.txt`. FFmpeg используется для декодирования исходных WAV/OGG/MP3/AAC. Обработка вне игрового кадра; до 360 секунд на фрагмент. Без реальной зависимости не заявляй анализ.

- `python scripts/librosa_bridge.py profile chapter.wav --out profile.json` — измерение спектрального chroma, восьми относительных сегментов, плотности атак, спектрального центра и приблизительного темпа. Темп может быть кратным реальному или неопределённым при rubato; chroma не равен точному определению тональности. Точная гармония остаётся в Tonal и Music21.
- `python scripts/librosa_bridge.py rank original.wav variant1.wav variant2.wav --out ranking.json` — выбирает близкие по слышимой гармонии, структуре, ритму и яркости варианты. Использовать только собственные/разрешённые оригинальные темы и сопоставимые фрагменты; минимум два кандидата для осмысленного выбора. Это не субъективная оценка качества, не определение жанра и не проверка плагиата. Не подменять контроль партитуры этой эвристикой. Выбранный аудиофайл должен сохранять связь с исходным JSON/MIDI/MusicXML и seed.
- `python scripts/librosa_bridge.py master chapter.wav --out chapter.ogg` — реальная цепочка FFmpeg двухпроходного мастеринга, затем проверка сохранения длительности и близости спектральной гармонии/структуры. При превышении порогов экспорт отклоняется, исходник остаётся. Пороги эвристические; не заменяют прослушивание и контроль LUFS/true peak FFmpeg. Не выдавать проценты сходства за проценты качества.
- Совместный контур: генераторы NotaGen, Piano Music Generator, Magenta и Modular Riffs → HarmoniaTextor, Tonal, Music21 → аккомпанемент MMA → рендер FluidSynth/Open Music или запись Tone.js + Salamander → Librosa сравнивает звучащие варианты → FFmpeg + Librosa проверяют мастер. В SYMPHONIA готовить новые главы/переходы заранее; победивший seed использовать для следующего поколения вариантов, сохраняя банк мотивов. Живой браузерный режим остаётся прежним, без анализа в аудиопотоке.
- Не смешивать альтернативные полные рендеры; не нормализовать независимые стемы порознь. При отсутствии сети сохранять прежние инструменты. Все 13 предыдущих модулей сохранены.

## Rubber Band — пятнадцатый модуль, v0.15.0

Оригинал https://github.com/breakfastquay/rubberband; https://breakfastquay.com/rubberband/license.html — GPL-2.0-or-later / коммерческая лицензия. Используй только отдельно установленный FFmpeg с `--enable-librubberband`, как офлайн-инструмент подготовки оригинальной музыки. Не включай GPL-библиотеку или соответствующую сборку FFmpeg в закрытую игру, не покупай лицензию. В игру передаются только подготовленные аудиофайлы с соблюдением лицензий исходного звука. Наличие фильтра проверяется `ffmpeg -hide_banner -filters`. Не подменяй его обычным resampling при недоступности.

`scripts/rubberband_bridge.py` использует настоящий фильтр `rubberband` FFmpeg с pitch=1, сохранением стереосвязи и смешанной обработкой транзиентов. Вход — оригинальный lossless WAV/FLAC/AIFF; выход — новый стерео WAV 48 kHz (float для промежуточного stretch, PCM16 после мастеринга перехода). Все исходники неизменны. BPM берётся из партитуры/авторского таймлайна, не из приблизительной оценки Librosa. Диапазон изменения темпа 0.75–1.33 от исходного, большие изменения делать повторной генерацией нот. Для rubato это только глобальное масштабирование карты темпа, не выравнивание всех отдельных ударов.

```sh
python scripts/rubberband_bridge.py stretch chapter.wav --source-bpm 100 --target-bpm 120 --out chapter-fast.wav
python scripts/rubberband_bridge.py transition overture-cut.wav adagio-cut.wav --left-bpm 100 --right-bpm 120 --target-bpm 110 --beats 2 --compatible-boundaries --out bridge.wav
python scripts/ffmpeg_bridge.py bridge.wav --out bridge.ogg
```

- Используй реальную последовательность FluidSynth/Open Music/запись Tone.js+Salamander → Rubber Band → Librosa → FFmpeg. Librosa проверяет chroma и структуру каждого изменённого фрагмента относительно исходника; проверка эвристическая, не доказательство абсолютной идентичности высоты каждого звука. При превышении допусков результат не публикуется. Длительность проверяется относительно заданного темпа. Сохраняй JSON/MIDI/MusicXML отдельно: темп исходной партитуры не меняется.
- Для переходов HarmoniaTextor/Tonal/Music21 заранее согласуют последние и первые аккорды, генераторы создают совместимые фразы. Точно отрежь их на музыкальных границах (без лишнего хвоста реверберации). `--compatible-boundaries` означает, что это уже проверено вызывающим кодом; адаптер не определяет автоматически совместимость или битовую фазу. Он приводит две фразы к общему BPM, накладывает 1–8 долей с equal-power crossfade и запускает существующий двухпроходный мастеринг. Не смешивай альтернативные полные рендеры в качестве стемов. Для исходной партии с меняющимся темпом подготовь отдельный метрически пригодный фрагмент.
- Для SYMPHONIA подготовь короткие переходы между игровыми состояниями заранее и переключай их по авторским границам в Tone.js; для настоящей бесконечной музыки сохраняй LiveRiffs и существующий браузерный таймлайн. Rubber Band не запускается в кадре, не устанавливается на клиент и не изменяет звук живого генератора автоматически. При необходимости заранее рендери нужные состояния с разным BPM. Все предыдущие 14 модулей сохранены.

## SoundFile / libsndfile — шестнадцатый модуль (v0.16.0)
https://github.com/bastibe/python-soundfile (BSD-3-Clause), libsndfile (LGPL-2.1-or-later). `python -m pip install -r scripts/requirements-soundfile.txt` в отдельной среде. Не включать Python и libsndfile в браузерную игру. Это точная нарезка и упаковка дорожек, не новый генератор мелодий.

`python scripts/soundfile_bridge.py piano.wav bass.wav --out /mnt/data/loop-pack --bpm 120 --bars 4 --beats 4 --start-frame 96000 --weights 1 .5 --compatible-boundaries` создаёт lossless PCM24 WAV на каждую партию и общий manifest с точным числом кадров, частотой, темпом, длительностью, SHA256 и общим безопасным усилением. Все дорожки должны исходить из одного музыкального времени, иметь одинаковую частоту и число каналов. Начало задаётся точным кадром, с действительным pre-roll (по умолчанию 30 мс); конец музыкально совместим с pre-roll. Скрипт сглаживает конец в pre-roll без изменения числа кадров и без независимой нормализации партий; не исправляет несовместимую гармонию или фазу. Темп — четверти в минуту; `--beats` — четверти на такт, не числитель сложного размера. Использовать только там, где фиксированный темп и точные границы действительно известны. Rubato исходной пьесы не превращать автоматически в метрический цикл. Повторение конечного цикла не равно бесконечной генерации.

Сначала получить оригинальные ноты, гармонию и дополняющие партии от предыдущих движков; использовать FluidSynth или Open Music для раздельных рендеров, Rubber Band при необходимости согласования темпа вне игры, затем точно выровнять общую сетку. Не складывать альтернативные полные мастеры одной пьесы. Librosa проверяет профиль до/после, FFmpeg используется для общих мастеров и превью, не для независимого изменения длительности/громкости готовых циклов. Не перекодировать lossless loop pack в MP3/AAC без повторной проверки точности декодирования. Сохранять лицензии исходных инструментов.

`loop_player.mjs` экспортирует `loadLoopPack(ctx, manifestUrl, destination=ctx.destination)`: Web Audio, общий контекст (например `Tone.getContext().rawContext`), проверка SHA256, загрузка и декодирование до сцены, общий момент старта всех слоёв, `setMix([1,.25],.15)` плавно управляет долями дорожек, `stop()` и `dispose()` освобождают узлы. URL обслуживать через HTTPS/localhost. Для смартфонов ограничивать число/длительность слоёв; не держать все главы в памяти. ToneMusic остаётся режимом непрерывной генерации, а loop pack — подготовленным музыкальным слоем; не воспроизводить одновременно одну и ту же композицию обоими способами. Не утверждать, что проверено браузерное воспроизведение, пока не проверено в настоящем браузере.

## Семнадцатый модуль: Mido — единый MIDI-обмен (v0.17)

Mido 1.3.3 (MIT), https://github.com/mido/mido, уже применялся внутри MMA и FluidSynth. Теперь отдельный общий адаптер `scripts/mido_bridge.py` использует настоящий Mido для экспорта канонического MUSIC JSON (`performance.notes`, опциональный MMA `backing.notes`) в многодорожечный GM MIDI format 1. Установка: `python -m pip install -r scripts/requirements-midi.txt`.

- `python scripts/mido_bridge.py final.json final.mid --conductor piano.mid` переносит tempo/meter/key map исходного MIDI (не его ноты), в том числе rubato; секунды событий переводятся в PPQN через кусочно-постоянный темп. Сохраняется финальная длительность с точностью до тика. Без `--conductor` используется постоянный темп из piece (или 120 BPM по умолчанию); это не реконструкция rubato-карты. Сами времена нот из JSON сохраняются с округлением до тика.
- Используется существующий `fluidsynth_bridge.json_events` для общей валидации, GM-программ, каналов, динамики и предотвращения двойного баса MMA/Modular Riffs. Повторяющиеся перекрывающиеся одинаковые ноты на одном канале ретриггерятся через note-off/note-on и держатся до конца объединённого интервала; это ограничение MIDI, а не независимые голоса. Результат не заменяет исходный MusicXML.
- Пайплайн: NotaGen/Magenta → HarmoniaTextor/Piano Music Generator/Tonal → MMA или Modular Riffs → MUSIC performance JSON → Mido MIDI → Music21 (анализ) или FluidSynth (WAV) → Rubber Band/FFmpeg/Librosa/SoundFile → Tone.js/loop player. MIDI и JSON — альтернативные входы FluidSynth; не складывай их как два аудиослоя. Для экспорта исходной нотации используй исходный MusicXML, а для обмена исполнительскими событиями — этот MIDI.
- В MIDI сохраняются ноты, velocity, GM-программы и conductor, а не произвольные CC/педаль/питчбенд исходного файла; длительности педали уже выражены в performance JSON. Не выдавай этот экспорт за побайтовое копирование оригинала. Не экспортируй неопределённые партии, не используй тип 2/SMPTE MIDI. Не перезаписывай исходники.
- Офлайн-проверка с реальными Mido 1.3.3 и FluidSynth: фортепиано, бас и GM-ударные, две установки темпа, перекрывающиеся повторы, 4 секунды MIDI (ошибка 1.5 микросекунды в примере), стерео WAV с хвостом. Проверка на синтетических нотных событиях, не всей цепочке нейрогенерации. Не выполнять экспорт в игровом кадре.
