# Open-source admission — правила отбора

Для каждого кандидата сохранять URL репозитория, точный commit SHA (а не `main`), дату проверки, лицензию SPDX с ссылкой, проверенный интерфейс, поддерживаемые ОС/архитектуру, доступность offline-бандлинга, зависимости, стоимость памяти и сборки.

Классы лицензий:
- MIT/BSD/Apache-2.0: совместимость обычно проще, но сохранять notice и проверить ассеты/модели отдельно.
- MPL-2.0: файл-уровневые обязательства; не объединять слепо исходники.
- GPL/AGPL: запускать как отдельное самостоятельное средство при допустимых условиях и проверять обязанности распространения; не копировать автоматически код в игровой runtime.
- NOASSERTION/UNKNOWN/нет LICENSE: отказ от интеграции до проверки.

Технические условия:
- Одна версия Three.js и один animation loop в финальном HTML.
- Никаких сетевых загрузок во время работы заявленного offline HTML.
- Доказать реальную пользу на авторских исходных данных, сравнить исходные и итоговые байты и визуальные ракурсы.
- Источник полной 3D формы: исходные volume/GLB/VOX, не повтор одного плоского изображения.
- Загрузка чужого кода в текущую среду или GitHub Action только после предварительной оценки и проверки хэша; не запускать произвольный install.sh автоматически.

Мера успеха: точное устранение узкого места без потери оригинальной графики, FPS или контроля игрока. Открытый PR, лог установки или новый список зависимостей сами по себе НЕ интеграция.
