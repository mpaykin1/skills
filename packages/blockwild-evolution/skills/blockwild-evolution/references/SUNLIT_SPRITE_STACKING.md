# Sunlit Courtyard — verified sprite stacking workflow (BLOCKWILD v12)

- **Source:** user-supplied BLOCKWILD v11 autonomous HTML (45 MB), with original world data retained byte-for-byte in a new output. No original Unity models or game C# claimed restored. The 3D diorama is an **authored alternate art direction**, not the original Unity game.
- **Renderer/ownership:** original BLOCKWILD HTML retains its renderer and input; default Sunlit Courtyard is a separate Canvas2D isometric scene, using baked source-derived volume slices. One existing RAF and original player state. Source world remains togglable.
- **Actual source-volume stage:** `build_sunlit_volume_sprites.py` creates independent connected voxel volumes (tree, masonry, arch, flowerbed, actors) and horizontal alpha layers with distinct full-body animation poses (no fake image warp). Each result is a real RGBA cross-section stack baked to game images. Do not replace approved original actors with these authored example actors.
- **Source-stacking strip interoperability:** `stackstrip_bridge.py` accepts `danielwh2/sprite-stacking` horizontal bottom-to-top PNG slice strip; it emits alpha-preserving isometric PNG + `base`, `size`, SHA256 metadata. One tree in shipped v12 was rendered through this bridge from a genuine 64-layer sprite strip generated from the source 3D volume. This proves **PNG slice format interoperability only**, not successful execution of the upstream four-view reconstruction code.
- **Upstream reference:** https://github.com/danielwh2/sprite-stacking — MIT license. Verified code file GitHub blob SHA `73972c1019988dcdb119bc8d9ba0ad55c0fcfd2d` at `skills/sprite-stacking/scripts/views_to_slices.py` as of 2026-11-26. The upstream source file is not vendored in this plugin; install/pin it in a trusted local sandbox to generate source slices from original approved TOP/FRONT/SIDE/BACK views. Do not assert the `4-view` tool ran as part of v12.
- **Upstream source acquisition gate:** before using `views_to_slices.py`, confirm Git blob SHA, repository MIT LICENSE and the exact four-view input; never run unreviewed remote scripts automatically. Source integrity before/after by SHA256.
- **Skill synergy:** `godot-game-to-html` for authorized original Unity model recovery; `blender-model-animation-enhancer` for multi-view original GLB exports; `hero-animator` for identity-locked character pose stacks; `sprite-stacking-grunge` and `meta-game-fusion` for layer/sorting and 3D authoring; `voxel-atmosphere-engine` / `game-style-forge` for rays, water, lighting; `blockwild-visual-benchmark` / Playwright + OpenCV for matched screenshots and reference palette comparison; Skill Nexus for version/route gating.
- **Build:** First run `python scripts/build_sunlit_volume_sprites.py`, then `python scripts/assemble_sunlit_html.py --source ORIGINAL.html --assets GENERATED_SPRITES.json --out GAME_v12.html`. The sprite generator currently writes its generated outputs to `/mnt/data` by default; change the output paths locally on a copy when running in other workspaces. Do not claim an automatically installed external Unity exporter.
- **Performance:** pixel-space atlas cached; 32 baked sprite images, animated actor poses and water motion. Portrait and landscape Chromium screenshot runtime were verified; actual WebGL2 runtime for original source renderer was not verified. Mobile GPU FPS unknown.
- **Measured aesthetics:** CIE Lab 3D-histogram Bhattacharyya distance to the provided portrait style reference declined from 0.659463 (v11) to 0.540731 (v12), i.e. `(0.659463-0.540731)/0.659463 *100=18.0%` relative reference **palette distance** reduction. Not 18% universal improvement in graphics quality. LPIPS weights unavailable, no LPIPS score.
