# ГИФ СНАРУЖИ
## Вход и результат
Пользователь сообщает тип экстерьера, например усадьба, замок, больница, вокзал, деревня, фабрика, храм, и необязательный референс/стиль. Самостоятельно определи комплект деталей. Не задавай лишних вопросов. Референс и явно заданный стиль выше дефолта. По умолчанию: мягкая объёмная масляная живопись, ночной хоррор, туман, приглушённый серо-золотой лунный свет, фактура материала, патина, живые края; архитектурный стиль зависит от здания. Никаких линий-чертежей, повторяющихся декоративных паттернов, надписей или людей, кроме явно запрошенного силуэта. Не подменяй изображение процедурной примитивной геометрией. Результат — отдельные GIF и один действительный ZIP, не картинка каталога или текст промпта.
## Разложение
Составь внутренний список по слоям: здание, архитектурные модули, двор/сад/улица, ближние объекты, земля, дальний фон, небо. Типовой набор 20 + 2 уникальных атмосферных дополнения, если пользователь не установил число. Адаптируй список к типу места, не добавляй барокко к заводскому референсу. Базовый список усадьбы: fasad_okna, fasad_okna_svet, vhod, bashnya, krysha, kupol, okno_zal, balkon_nar, ograda, vorota, fonar, statuya_sad, fontan, derevo, kust_roz, vorona, dorozhka, gazon, nebo, les_dal; дополнительные arka_sad, besedka. Для другого здания выбери функциональные аналоги. Для каждой детали внутренне зафиксируй имя ASCII, габариты, вид, физический масштаб, положение основания, вид движения, направление света, тип бесшовности. Не выводи план вместо ассетов.
## Генерация
1. Используй доступный генератор изображений для настоящих живописных исходников. Генерируй отдельные крупные ассеты либо небольшой атлас из неперекрывающихся элементов без подписей; не общий мелкий инфографический плакат. Фасады строго ортографически спереди: вертикали параллельны, без видимых боковых стен и наклона. Остальное — на уровне глаз; земля — строго сверху. Прозрачность настоящая, не нарисованная шахматка. Края не обрезаны. Общая палитра, свет, единицы масштаба.
2. Для архитектуры сохрани один мастер PNG RGBA на весь цикл. Тёмный/светлый фасад из одного мастера, меняется только маска стёкол. Запрещено независимо перегенерировать геометрию по кадрам. Для живых частей используй локальные слои: огонь, отражения, вода, туман, листья. Для вороны — действительно разные положения головы при неизменном теле; для дерева — локальное движение тонких ветвей, не поворот всего изображения. Используй независимые авторские ключевые кадры там, где нужна смена позы, не деформируй жёсткие части. Не подменяй анимацию глобальным изменением яркости или дрожанием.
3. 6–10 кадров (по умолчанию 8), равная длительность обычно 120–250 мс, бесконечный цикл. Все кадры имеют одинаковые размеры и координаты объекта. Фаза 2πi/N, последний кадр не дублирует первый. Сгенерированные листы разделяй на одинаковые ячейки без смещения; проверяй совпадение опор. Альфа GIF бинарная: сохраняй нулевой фон, полупрозрачность передавай художественно или аккуратным стабильным дизерингом. Не рисуй чёрный/серый фон под объектом. Текстуры и небо полностью непрозрачные.
4. Крыши/ограды/дальний лес/небо — горизонтально бесшовные, текстуры земли — по двум осям. Делай стыки в исходнике и на каждом кадре; периодические облака и дымка. Небо минимум 1280×640 нативного содержимого, не растягивай миниатюру ради числа. Для земли квадрат. Сохраняй неповторяющиеся детали внутри тайла, но совпадающие границы. Не смягчай стык размытием всей сцены. Формируй анимированное превью 2×1 или 2×2.
## Проверка и упаковка
Используй scripts/gif_pack.py (Pillow) для сборки настоящего GIF из кадров, декодирования, проверки количества кадров, различий, прозрачности, габаритов, цикла и стыков, генерации tiled-preview, финального ZIP. Команды описаны в README. Скрипт не заменяет визуальную проверку: смотри кадры на светлом и тёмном фоне, проверь живописность, перспективу, локальность движения, шов, соответствие масштаба, геометрию парных фасадов, контур и отсутствие текста. При ошибке исправь и пересобери, не отмечай PASS на основании одного существования файла. Не выдавай неподвижный PNG за GIF. При недоступности генерации честно сообщи, что не создано. Не обещай фоновую работу.
## Вывод пользователю
Сразу показывай каждый созданный GIF нативным анимированным медиа в чате или проверенной inline-ссылкой на реальный GIF, с именем, фактическими размерами и количеством декодированных кадров. Для тайлов рядом показывай повторение. Если клиент показывает лишь первый кадр, не заявляй что пользователь видел движение; дополнительно приложи автономную HTML-галерею внутри ZIP, которая показывает GIF при открытии в браузере. Не подменяй GIF статичным превью. Учитывай повторный запрос: найди уже созданные и реально показанные ассеты текущего проекта, проверь их доступность, продолжи недостающие; не дублируй без необходимости. При просьбе переслать ZIP — проверяй файл в текущей среде, при необходимости восстанови из реальных ассетов и отправь свежую ссылку. В конце один ZIP <project>_exterior.zip (либо заданное имя) с GIF в корне/ assets, превью стыков отдельно, локальная HTML-галерея, машиночитаемый manifest.json со свойствами. Проверь ZIP CRC, имена, наличие всех запрошенных файлов. Не выдавай отчёты, handoff, тестовые логи; только результат и кратко то, что объективно осталось сделать.
