# Призрачный гиф внутри

## Вход и результат
Пользователь называет помещение (бальный зал, больница, вагон, храм, библиотека, бункер и т.д.) или прикладывает референс. Этого достаточно: самостоятельно определить архитектурный стиль, масштаб, план набора и недостающие детали. Не задавать лишних вопросов. Результат — реальные отдельные GIF, а не промпт, рисунок целого помещения, статичный PNG или обещание. Из набора разработчик должен собрать настоящий трёхмерный интерьер. Референс и явно заданный стиль приоритетны над палитрой по умолчанию.

## Инвентарь
Разложить помещение на строительные модули: вертикальные опоры; проёмы, арки, окна; стены с функциональными вставками; двери; ограждения; характерные для помещения предметы (если нужны для полноценной сборки); бесшовный пол, потолок, заполняющая стена и горизонтальный карниз/профиль. Не навязывать барокко и колонны помещению, которому они не свойственны. Обязательный ориентир для барочного зала: kolonna, arka, stena_okno, stena_zerkalo, dver, balkon, pol, potolok, stena_gladkaya, lepnina. Для каждого типа сразу создавать dark и light с одной геометрией. Имена латиницей: <detail>_dark.gif, <detail>_light.gif. Разные детали — отдельные файлы; никаких коллажей вместо финальных файлов.

## Единый художественный стандарт
- По умолчанию мрачный призрачный хоррор: мягкая живопись, карандашные тончайшие линии, бледное серебро, серо-золотой тон, тонкие мерцающие акценты; фактура соответствует конкретному помещению.
- Хрупкие, воздушные силуэты, больше пустоты и просветов, чем материала там, где это совместимо с функцией. Края растворяются тонкими нитями и дымкой; никакой массивности, грубой обводки, пластикового блеска или одинаковых процедурных орнаментов повсюду.
- Dark: тёмный приглушённый материал с различимыми линиями; light: почти белый карандашный рисунок с бледным золотом. Обе версии используют один и тот же контур, координаты, масштаб, свет и точку привязки.
- Ортографический вид строго спереди, без перспективы, наклона, изометрии, пола под объектом, падающих теней или заднего фона. Пол и потолок: плоская ортографическая текстура, вид перпендикулярно поверхности.
- Полная прозрачность вне объекта и в просветах. GIF поддерживает лишь бинарную альфу: призрачность передавать цветом, штрихами, прореживанием и просветами, а не серой подложкой или нарисованной шахматкой. Реальную полупрозрачность и свечение добавит игровой движок. Текстуры поверхностей заполняют весь кадр. Без текста, подписей и людей.

## Производство
1. Выбрать общую метрическую сетку, плотность пикселей, свет, точки привязки, модульные размеры. Согласовать высоту дверей, окон и опор, ширину пролётов. Сохранять поля холста и pivot у dark/light.
2. Нарисовать исходники средствами генерации изображений, если доступны: одна независимая художественная деталь в ортографической проекции на прозрачном фоне. При использовании листа исходников физически разделить его по ячейкам. Не заменять художественный исходник примитивными Canvas-фигурами. Для анимации статичной архитектуры сохранить единый базовый растр и маски; не генерировать заново каждую колонну или дверь в каждом кадре.
3. Создать 4–8 кадров (6 по умолчанию), бесконечный плавный цикл. Фиксировать геометрию и положение; разрешено только локальное мерцание металла, световых нитей и слабое колыхание дымки у края. Использовать периодические фазы 2πk/N без дублированного финального кадра. Изменение должно быть видимо глазом, но не превращаться в стробоскоп. По умолчанию 150–200 мс/кадр. Не двигать деталь целиком, не масштабировать, не деформировать. Прозрачная палитра с отдельным индексом, disposal=2 для независимых кадров, loop=0. Проверять декодированные кадры после сохранения, не только входные изображения.
4. Пол/потолок/заполняющая стена бесшовны по обеим осям, квадратные. Лепнина/карниз бесшовны по X. Для повторяемых текстур обеспечить периодичность как базового изображения, так и анимации; исправить центральный шов после циклического сдвига, проверить все кадры на границе плиток. Сделать PNG 2×2 для каждой версии каждой текстуры; для горизонтального профиля явно указать, что требуется стык по горизонтали.
5. Проверить, что файлы действительно GIF, 4–8 реально различающихся кадров, размер неизменен, цикл бесконечный, прозрачность соответствует назначению, силуэт неподвижен, нет фона, перспективы, текста и тяжеловесных форм. Визуально проверять плиточные стыки и кадры. Если ошибка исправима, исправить самостоятельно перед показом. Не объявлять технические свойства без декодирования файла. Не считать механическую проверку доказательством художественного качества.
6. Показывать каждый готовый GIF прямо в чате отдельным вложением/встроенным изображением с фактическими размером и числом кадров. Не подменять GIF на PNG. Рядом с текстурой показывать 2×2. Если клиент замораживает GIF, не утверждать что пользователь увидел движение: создать автономный HTML-плеер из реальных декодированных кадров с автоматическим циклом, кнопкой паузы и переключением кадров. Дать ссылку на него сразу, не заставлять пользователя вставлять код. При наличии нативной анимации показывать её напрямую; не обещать воспроизведение интерфейсом. Плеер не заменяет выдачу исходных GIF.
7. Собрать ZIP с GIF, плиточными превью и автономным HTML-плеером; дать ссылку. По умолчанию не писать отчёты. Подписи размеров, кадров и 2×2 являются запрошенной частью результата. Если часть набора недоступна, честно обозначить, какие файлы готовы, а какие нет.

## Встроенный помощник
`python scripts/preview.py <папка_гиф> <папка_результата>` (относительно каталога этого SKILL.md). Требуется Pillow. Декодирует кадры, проверяет число кадров/цикл/фактическое различие, создаёт автономный HTML с настоящими кадрами и ZIP. Для pol, potolok, stena_gladkaya, lepnina автоматически строит 2×2; для других названий передать `--tiles имя1 имя2`. Генерацию иллюстраций выполняет доступный генератор изображений; скрипт не притворяется генератором художественных ассетов.
