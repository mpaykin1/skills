# BlenderProc integration
Upstream https://github.com/DLR-RM/BlenderProc (GPL-3.0); external offline dependency, not redistributed or shipped with the web game. API reference https://dlr-rm.github.io/BlenderProc/docs/tutorials/renderer.html and https://dlr-rm.github.io/BlenderProc/docs/tutorials/camera.html. Install in a separate compatible Python environment (`python -m pip install blenderproc numpy`), record installed version and Blender version, and run `blenderproc --help`. BlenderProc manages its compatible Blender; ensure .blend compatibility and packed/resolvable textures. Never silently install conflicting versions into Infinigen's environment. If the upstream Blender download or runtime is unavailable, report that the actual render was not run.

1. Generate a layout using the existing Infinigen adapter, or use an existing authored .blend. Run director.py to create directed.blend and staging.json. Use the exact name of a focal mesh and existing camera names (include CSD Preview Camera plus gameplay route views). Existing gameplay transforms and assets remain untouched by the refinement.
2. Run `python scripts/refine.py --scene /path/directed.blend --focus Piano --cameras 'CSD Preview Camera' 'Gameplay Camera' --out /path/new-refinement --blenderproc /path/env/bin/blenderproc --blender /path/blender --frame 1`. This calls real BlenderProc for 7 recipes, each at identical camera poses and fixed animation frame. Base recipe disables only director lights; original lights remain. Existing compositor is disabled only inside diagnostic passes. Keep camera exposure, world, materials and geometry consistent. Complex volumetrics, alpha masks and compositing may require manual comparison in native renderer.
3. RGB, depth, normals, focal mask and selection are emitted into the new folder. The selection is a conservative heuristic: edge contrast, clipped highlights and shadows on the focus, focus coverage and finite depth; a candidate must improve the worst view relative to both the base and director recipes. Selection is not proof of beauty, navigability, FPS or fidelity. If no selection, preserve input. Visually inspect original and candidate renders using the original gameplay camera and full animation, then ship only the actually improved scene. For new spaces, repeat across Infinigen seeds under the same artistic brief; compare corresponding views and reject collisions, blocked routes and changed assets independently.
4. Selected recipe applied by separate Blender invocation to a new refined.blend; only CSD light energy and size are changed. Three.js should use calibrated/baked lighting, not run BlenderProc. For Sprite Stacking, use approved RGBA slices and preserve identity; compare native runtime frames and apply light changes with the appropriate shader or bake. Use the previous runtime and living-world checks.
