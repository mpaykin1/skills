# OpenSubdiv hybrid detail — source integration
Upstream reference: https://github.com/PixarAnimationStudios/OpenSubdiv/tree/7d0ab5530feef693ac0a920585b5c663b80773b3 (v3_6_0; modified Apache 2.0, LICENSE.txt). This is a reference pin, not a claim about the library version compiled into Blender. Blender 4.5 LTS Subdivision Surface uses OpenSubdiv as its backend: https://docs.blender.org/manual/en/4.5/modeling/modifiers/generate/subdivision_surface.html . No separate OpenSubdiv build is necessary for this route; require an actual trusted Blender 4.5 installation. No third-party binary bundled. Native runtime unavailable until checked; CLI-Anything may dispatch only if its documented Blender backend is installed. Do not install arbitrary packages or use paid services.

## Producer
Material Maker supplies actual cloth weave, seams, metal and roughness maps; PyMeshLab/Instant Meshes only on explicitly approved pre-rig meshes. OpenSubdiv smooths existing geometry, does not create embroidery, folds, blade ornament or good animation by itself. Author these in geometry/textures before refinement. Rigify/FreeMoCap/Rokoko/NLA preserve animation and evaluate the original rig first. Use only an approved true 3D source, not generated substitute pixel frames. On an isolated copy, `blender -b SOURCE.blend --python-exit-code 1 --python scripts/refine.py -- config.json /new/output`. Config: `source_sha256`, `approved_source:true`, `hero_id`, `rigs` (armature object names), `sample_frames` (integers representing the active composed action), `meshes` (objects with `object`, `role` cloth/body/hair/armor/blade/hilt, `levels` 0–2, optional `approved_hard_edges:true`), `max_total_triangles` (default 500000), `max_bounds_shift_m` (default .015). Metre scene scale required. Repeat review across all authored action ranges using the same Rigify/NLA recipe; do not treat one sampled pose as coverage. Hard surfaces default level 0; only use reviewed crease/support geometry. The script rejects duplicate existing subdivision, enforces a conservative pre-allocation and evaluated triangle budget, checks sampled world bounds and bone matrices and saves a new blend and manifest; it does not apply modifiers or edit the original weights, UVs or rig. Check silhouette, UV, seams, normals, blade tip and guard, cloth intersections, grip and rear walk/jump/air slash. Approve derived art explicitly; do not self-approve. Existing original PNG/GIF identity is unchanged.

## Export and consumers
Use refined.blend SHA as new source for the existing Rigify/NLA motion sampler, weapon attachments and genuine full-pose volume baker. Keep original parent SHA and recipe SHA in provenance. Bake from evaluated geometry after rig/NLA/subdivision, not a static model. Do not blindly apply subdivision on a skinned mesh or export post-armature evaluated mesh as a rigged GLB. Prefer refined mesh offline for true RGBA slices and high-poly texture/normal bake, preserve approved low-poly rigged GLB for attachments and physics; if exporting derived rigged GLB, verify actual skin, animation, UV and appearance with Khronos validator, then safe glTF Transform/meshoptimizer. Rapier colliders unchanged. Game Style Forge uses Material Maker, normal maps and selective lighting to bring detail into the same visual style; Mantaflow/Quarks and Effekseer keep their existing roles. No second physics or animation clock. GPU and memory budget; fallback shares identical approved full poses. Black Screen Guard remains mandatory. For consumers `pack_gate.py subdiv.json volume-manifest.json` validates provenance and recorded budget; manifest must be explicitly visually approved by the owner and pack must include `hero_id`, `source_sha256` (derived blend), `subdiv_recipe_sha256`. This is metadata validation only, not geometry/image proof. Keep existing rig sync and contact gates; compare front/back/side and actual game frames before claiming improvement. Do not claim installation, render or quality PASS if Blender is absent. No reports without request.
