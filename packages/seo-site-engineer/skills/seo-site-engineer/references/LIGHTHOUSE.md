# Lighthouse CI + SiteOne + Web Performance
Upstream: https://github.com/GoogleChrome/lighthouse-ci ; docs: https://googlechrome.github.io/lighthouse-ci/docs/configuration.html . Pin @lhci/cli 0.15.1 (known release, not a latest claim), install in an isolated npm workspace with lockfile/integrity review, use trusted Chrome. Run the local executable via --binary; no automatic install or public upload. Keep Chrome version, environment and throttling constant for comparisons.

1. SiteOne first: discover critical and representative canonical URLs; check HTTP status, indexing directives, links and content. Choose homepage, RU/EN discography and one representative album; after production transfer add all changed URLs if needed. Do not audit nonpublished pages as production.
2. Run `python3 scripts/lighthouse-audit.py https://mpaykin1.github.io/meta6/killklan/ --url https://mpaykin1.github.io/meta6/killklan/ --output /tmp/killklan-lh-before.json --binary /path/to/node_modules/.bin/lhci`. After deployment specify all desired live URLs; baseline must cover identical URLs. Three mobile runs per URL; median metrics. Save files locally; no account, API credits or upload. Use `--baseline /tmp/killklan-lh-before.json --gate` for same-scope comparisons.
3. Web Performance skill uses reported audit IDs, LCP, CLS, TBT to optimize resources and rendering without changing gameplay. Initial gate budgets: SEO >= 0.90, accessibility >= 0.90, performance >= 0.80, LCP <= 2500ms, CLS <= 0.1, TBT <= 200ms. These are project laboratory goals, not Google ranking guarantees; real INP is not measured. Compare medians only under matching environments; report blocked or incomplete runs honestly.
4. Rerun SiteOne after fixes to detect broken links, canonical and robots regressions; repeat Lighthouse with same URL set and environment. The adapter rejects incomplete runs and redirects. Existing repository checks remain mandatory; no modification of protected workflows. A passing score does not demonstrate indexing or organic traffic. Search Console and real-user metrics remain separate.
