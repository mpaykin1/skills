# Google Web Vitals + SiteOne + Lighthouse CI
Upstream: https://github.com/GoogleChrome/web-vitals ; thresholds: https://web.dev/articles/vitals . Known pinned release 5.1.0 (Apache-2.0); do not claim latest. Install `npm install --save-exact web-vitals@5.1.0` in an isolated authorized project, review lockfile and integrity. Bundle locally with the site's bundler; no external script/CDN and no auto-install from the skill. The client uses the documented onLCP/onINP/onCLS API.

## Integration
1. SiteOne provides canonical URLs and crawl errors. Lighthouse CI establishes repeatable mobile lab baselines per representative page; real-user p75 is independent. Web Performance maps the slowest URL/metric to an actual trace, then fixes the cause without degrading graphics or gameplay.
2. Copy `scripts/vitals-client.mjs` into the approved site's build. Call `startVitals({route: 'home', device: 'mobile', release: 'release-id', allowedRoutes: ['home','discography','release'], enabled: () => consentGranted, sink: yourApprovedSink})` after obtaining permission. Use explicit fixed route categories, not arbitrary paths, and device classification consistent across releases (desktop/mobile/unknown). Use a validated same-origin or approved first-party collector with retention and access controls; implement sink separately. No default network, cookies, localStorage, raw URL, user ID, IP, query, referrer, attribution or interaction target in client payload. Collector must avoid storing IP/user agent or full URLs; deduplicate by ephemeral metric ID. Never silently enable telemetry. GitHub Pages cannot receive POSTs; no collector means no field telemetry deployment. For local debugging only use `sink: console.debug`, with explicit opt-in; this is not field data.
3. Export **final** field observations as NDJSON using the client schema. Partition into independent equal-length comparable date windows; use release-specific files, exclude synthetic/lab sessions and bots at ingestion. Collector must enforce schema/size limits, prevent arbitrary payloads, and separate debug from production. No fabricated samples. Run `python3 scripts/vitals-aggregate.py field.ndjson --release release-id --output field-summary.json`. Optional `--baseline prior-summary.json` compares only route/device/metric with >=75 distinct metric IDs on both sides. Minimum sample count is a project heuristic, not Google's eligibility rule. Compare cohort and time windows separately; raw p75 not proof of causal change. Unknown device is not pooled with known devices. Missing INP means no observed qualifying interaction; never fill zero. P75 goals LCP <=2500 ms, INP <=200 ms, CLS <=0.1.
4. CrUX / Search Console may provide independent field data with eligible volume; use page-level when available and label origin-level separately (GitHub Pages shared origin is not a single project). Use free permitted sources only, no unapproved API billing. Lighthouse TBT is not INP. Never claim ranking lift from metrics alone.
5. Re-crawl SiteOne after publication, repeat Lighthouse under same configuration, compare actual p75 as observations accumulate. If network, dependency, consent, collector or samples missing, explicitly mark BLOCKED/insufficient. Do not delay permitted publication of already green SEO changes or override repo protection.
