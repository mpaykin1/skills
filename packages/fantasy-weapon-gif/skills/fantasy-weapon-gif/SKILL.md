# FANTASY WEAPON GIF — 4 ракурса

## Результат
Готовый анимированный GIF с прозрачным фоном, без подписей, сетки и посторонних объектов. По умолчанию оригинальный нереальный фантастический предмет со стрелами, примитивный 3D pixel/voxel art, мрачный хоррор, тёмное железо, кость, потёртые материалы, сдержанные световые акценты. Стиль, предмет, вид, наличие рук и фон меняются только по указанию пользователя. По умолчанию две руки в кадре, вид от первого лица, предмет направлен от зрителя наружу. Если референс без рук и пользователь просит сохранить его без изменений, руки не добавлять. Не создавать рабочие инженерные схемы или реальную конструкцию: только вымышленные визуальные игровые ассеты.

## 1. Неизменная идентичность в сессии
- Зафиксировать руки на первом запросе: канонический RGBA-референс с двумя руками, перчатками, манжетами, пропорциями, швами, материалами, освещением, палитрой, асимметричными признаками, правой и левой рукой. Если пользователь прислал руки, взять их за основу. Не заменять руки при смене предмета. Не зеркалить асимметрию, не менять пальцы, рукава и перчатки. При изменении хвата допустима другая нарисованная поза этих же рук.
- Сохранить `session.json` с хешем исходного референса через `scripts/gif_gate.py lock`. Один раз создать; не перезаписывать при каждой новой модели. Использовать в последующих запросах текущего чата; если файл недоступен, восстановить из исходного референса текущей сессии или явно отметить блокер. Не подменять референс и не объявлять идентичность проверенной по одному текстовому ID. Пользователь может явно сменить руки и начать новую серию.
- Зафиксировать один референс предмета, форму, стороны, цвета, декоративные элементы и стрелы. В пределах одного GIF предмет не изменяется; между GIF меняется только предмет, если пользователь не попросил иное.

## 2. Пять ключевых положений, четыре обязательных крайних ракурса
Камера неподвижна. В координатах камеры X вправо, Y вверх, Z наружу от зрителя (в Blender камера смотрит по локальной -Z). Положение CENTER: предмет направлен наружу, вид сзади от первого лица. Поворот означает изменение оси предмета в объёме, а не наклон изображения в 2D, не приближение и не поворот камеры.

| Поза | yaw | pitch | Что должно быть видно |
|---|---:|---:|---|
| CENTER | 0 | 0 | нейтраль, от зрителя |
| UP | 0 | +90 | предмет направлен строго вверх, полностью виден |
| DOWN | 0 | -90 | предмет направлен строго вниз, полностью виден |
| RIGHT | +90 | 0 | предмет направлен вправо, полный боковой профиль |
| LEFT | -90 | 0 | предмет направлен влево, полный противоположный профиль |

Строгий порядок: CENTER → UP → DOWN → CENTER → RIGHT → LEFT → CENTER. UP→DOWN через центр; RIGHT→LEFT через центр. Полный силуэт предмета и стрел не обрезан ни в одном ракурсе. Крайние ракурсы выдержать примерно 200–300 мс для различимости. Поворачивать медленно, без рывков, сохраняя направление от зрителя: при боковом направлении допускается 90°, но не 180° на зрителя. Никаких выстрелов, перезарядок, самостоятельных движений и смены предмета без запроса. Петля без скачка. Цель 25 FPS (40 мс на кадр, без учёта задержек на крайних позах).

## 3. Получение настоящих ракурсов
1. Если доступно создание изображений: создать нейтральный референс и отдельные полные RGBA-рисунки для UP, DOWN, RIGHT, LEFT, сохраняя референсы рук и предмета. Запрашивать промежуточные независимо нарисованные позы в небольших листах (не более 4×4, равные клетки, без текста, предмет помещается в ячейке с полями). Привязывать все генерации к одним и тем же исходникам. Не считать обещанные в запросе углы реально полученными. При отсутствии нужных ракурсов дорисовать только недостающие позы по тому же референсу. Не использовать предыдущий ошибочный GIF как эталон полного диапазона.
2. При наличии проверенного 3D исходника или доступного Blender: использовать один авторский визуальный 3D-ассет из Voxel Atmosphere Engine (Blockbench/Blender), неподвижную ортографическую камеру, один свет, прозрачный фон, подлинные вращения по двум осям. Допустимы отдельно отрисованные полные позы рук с тем же дизайном. Для 2D рук не применять warp, affine, перспективную деформацию, optical flow, RIFE или зеркалирование; не превращать руки в другое изображение. Для 3D предмета разрешены только настоящие пространственные жёсткие вращения. Сохранить низкое разрешение рендера и nearest-neighbor масштабирование. Не подменять сложный утверждённый референс примитивными фигурами.
3. Переиспользовать существующие скилы, если доступны: Hero Animator (full-frame RGBA, неизменная идентичность, anti-jerk), Voxel Atmosphere Engine (Blockbench, Blender, Pixelorama). Новые движки не нужны. rembg из Hero Animator допустим только для аккуратного удаления фона, не для создания ракурсов. Не применять RIFE к рукам или предмету, не выдавать геометрическую деформацию за поворот.

## 4. Проверка и сборка — обязательно
- Создать план `python scripts/gif_gate.py plan plan.json`. Он задаёт порядок, целевые углы и плавную траекторию; это НЕ подтверждение фактических ракурсов.
- Экспортировать отдельные полные PNG на одинаковом холсте, в том же масштабе, с альфа-каналом. Составить manifest по `manifest-example.json`; перечислить фактические кадры в порядке воспроизведения, их углы (из реального рендера или визуальной оценки), длительности и позиции ключевых поз; пути относительно manifest. Указать метод определения углов, референсы и session lock. Для рисованных спрайтов заявленные углы — визуальные оценки, не измерения геометрии. Не заполнять манифест выдуманными данными из плана.
- `python scripts/gif_gate.py sheet manifest.json contact.png` создаёт лист всех пяти ключевых поз. Открыть лист средствами просмотра изображений. Проверить направления UP/DOWN/RIGHT/LEFT, полный силуэт, одинаковые руки, один предмет и отсутствие подмен/зеркалирования. Просмотреть ВСЕ промежуточные кадры в последовательности и петлю, включая оба направления перехода через центр. При недостаточной плавности дорисовать промежуточные кадры; не дублировать одну позу вместо движения. Только после фактической проверки заполнить `review` в манифесте, все пункты должны быть истинными. Не спрашивать пользователя о технических проверках, выполнять самостоятельно. При невозможности просмотра не выставлять PASS.
- `python scripts/gif_gate.py build manifest.json final.gif` проверяет порядок углов, полный диапазон, шаг, прозрачность, границы, количество уникальных кадров, совпадение session lock, наличие подписанной фактическими хешами визуальной проверки; собирает GIF с одной глобальной палитрой и проверяет реальный декодированный GIF. Повторно просмотреть итоговый GIF и исправить артефакты квантования. Скрипт проверяет структурные свойства, но не доказывает визуальную идентичность или пространственный угол сам по себе.
- При любом пропущенном ракурсе, обрезке, подмене рук, скачке, повторном кадре на движении, движении на зрителя или недостатке подтверждения — BLOCKED; не выдавать как готовый. Исправить дефект и повторить. Если исправить невозможно, честно сообщить, чего не хватает. Не требовать ручной работы пользователя.
- Итог: показать сам GIF в чате, дать готовый файл там, где поддерживается. Не публиковать отчёты, тесты, handoff, evidence или исходники без запроса; проверка выполняется внутри процесса. Если пользователь отдельно просит игровые кадры, добавить прозрачные PNG/APNG и manifest по направлениям, не заменяя GIF.
