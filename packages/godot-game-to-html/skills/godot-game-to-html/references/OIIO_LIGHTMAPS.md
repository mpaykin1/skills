# OpenImageIO — CPU lightmap color pipeline and metadata inspection

Upstream: https://github.com/AcademySoftwareFoundation/OpenImageIO (Apache-2.0). CLI documentation: https://openimageio.readthedocs.io/en/stable/oiiotool.html. No OIIO binaries are bundled; the external native `oiiotool` must be installed from the official project. The Python adapter makes a direct subprocess call, not a mock replacement.

## Place in the pipeline

Godot/Unity source → original WebGL baseline; approved static GLB → xatlas UV2 → Blender Cycles CPU AO PNG → optional Intel OIDN CPU AO denoise → **OpenImageIO** validation. OpenImageIO also handles additional EXR/HDR/TIFF lighting maps generated by DCC tools; unlike OIDN, it performs metadata inspection and color-space conversion, not denoising. Oxipng losslessly compresses the accepted PNG derivative. glTF-Transform and gltfpack optimize separate approved geometry assets; none of these substitutes for original engine shaders, volumetric snow or gameplay.

## Commands

```bash
python scripts/oiio_lightmaps.py inspect --input atlas/ao/wall_AO.png
python scripts/xatlas_lightmaps.py original_static.glb --out atlas --bake-ao --denoise-ao --oiio-inspect
python scripts/oiio_lightmaps.py convert --input lighting_linear.exr --out sidecars/lighting_web.png --kind color --from-space lin_rec709_scene --to-space srgb_rec709_scene
python scripts/oiio_lightmaps.py convert --input wall_AO.exr --out sidecars/wall_AO.png --kind data
```

Optional `--oiiotool /trusted/path/to/oiiotool` finds an already installed executable. `--oiio-inspect` requires `--bake-ao` to avoid inspecting unrelated resources and checks both original Blender AO and OIDN candidates when both options are enabled. The audit is additive to `atlas-manifest.json`.

## Fidelity and safety guardrails

- Never transform original albedo, normal, roughness, UI, sprites, approved animations or material texture files. Color conversion applies only to explicitly requested *new HDR lighting maps*.
- `--kind color` **requires** a source color-space name; wrong color-space declarations cause wrong output. `--kind data` never calls `--colorconvert`: AO is scalar linear data, and the target Godot/Unity/Three.js importer must treat AO as non-color.
- 16-bit PNG is a precision-preserving **derivative** of HDR lighting maps, but cannot represent full HDR dynamic range. Keep the EXR original as the authoritative HDR reference. Output path must be new and disjoint from source; no overwrites.
- `oiiotool --info -v` only verifies readability and reports current metadata; it does not prove pixel-identical rendering or valid gamma/profile tagging in the browser. Compare screenshots and default to original if visual divergence occurs.
- No GPU or external network calls are necessary when `oiiotool` is installed; CPU-only processing. Missing binary must fail visibly, without invented image outputs.
