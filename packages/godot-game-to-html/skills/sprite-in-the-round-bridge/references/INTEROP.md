# sprite-in-the-round ↔ META GAMES — precise interop

- Official source: https://github.com/SoAp9035/sprite-in-the-round (MIT © 2026 Ahmet Burhan Kayalı), pinned at `1d842b4d6d4e7f26b13236dedaf5841ecbfec267`.
- Upstream `scripts/voxlib.py`: `stack_views(top,side,front=None,back=None,side2=None)` builds `[z,y,x,RGBA]`, bottom z=0. `save_sheet` places bottom slice at left and puts `slices` / `frames` in PNG metadata.
- Upstream `scripts/stack.py`: `--count H --frames F --ppm P --out folder --name sprite_stack --dirs 16 --gif --vox`. Outputs a real static GLB with Y-up and +Z forward, OBJ/MTL/palette, direction sheet, turntable and native HTML viewer. **Animated rows do not export a single animated GLB**. `--ppm` sets metres per art pixel. Upstream GLB is a block-meshed **derivative**, not identical geometry to a source-triangle GLB.
- Previous `danielwh2/sprite-stacking` module (MIT): source four-view drawings → `layers/000.png` ... `stack.json`; its carver remains the first choice for explicitly specified orthographic 4-view sheets.
- Previous Grunge format: `layers` bottom-first RGBA PNG paths, `spacing=[dx,dy,dz]`, `pivot=[x,y,z]`, axes +X right +Y forward +Z up. We repack **without image resampling** into a horizontal PNG strip accepted by the official exporter, preserving the original source files.
- When starting with a native slice strip, this bridge writes separate RGBA PNG files and a new `stack.json` without silently fabricating rotations or extra geometry; complete pose stacks use `scene-stacks.json` for existing Three.js WebGL2 volume animation.
- Anisotropic spacing is not compatible with uniform upstream GLB `--ppm`; reject it rather than distort. Source original GLB → existing `stack_from_glb.py` preserves original surface color sampling as closely as the supported voxel budget permits; skinned or animated GLB rejects rather than freezing hero identity.
- Source image cleaning (`pixel_grid.py`) and one-view inflation are **not** automatically applied: smoothing, invented back faces, palette reduction or outlines could violate source preservation. Invoke manually when artistic reconstruction, rather than source parity, is explicitly desired.
- Importability: three.js can load generated GLB; Godot 4 supports glTF and sprite stacks; Unity GLB may need glTFast or an established compatible importer. Unity/Godot native export is the only path preserving all original game logic.
- The upstream native HTML viewer uses a different 2D slice renderer from the built-in Three.js WebGL2 volume DDA. Both depict the same source voxels; pixel-perfect frame parity is not guaranteed and should be checked with the already installed Playwright/Pixelmatch tools before any replacement.
