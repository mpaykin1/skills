# Godot Shader-Stacker interoperability

Upstream: https://github.com/x3cca/Shader-Stacker, pinned SHA `21d86ab62140b0d08ea217982036e3cb184afed5`, MPL-2.0. Godot 4. Upstream plugin uses `@tool class_name SpriteStack` and `class_name StackCamera`, and draws a **single-column image** row-by-row, starting from the last row. Our existing format stores bottom-first individual RGBA PNG slices: `layers[0]` becomes the bottom row (not the first). No rotation, flip, smoothing, palette conversion or averaging is applied during repacking.

Project output has `addons/ShaderStacker` copied unchanged (including the upstream classes and icons), plus `project.godot` plugin enablement and `generated/Main.tscn`, `generated/main.gd` and one texture per stack. Each texture is referenced by a `SpriteStack` Node2D. Camera is an official `StackCamera` class with y zoom compression. Demo controls: Q/E or mouse drag yaw, WASD pan, mouse wheel zoom. Source metadata and hashes are retained in `generated/stack_manifest.json`.

Limitations: this is Godot 2.5D screen-space layering, not the GPU volumetric first-hit renderer. Source 3D transforms may only be approximated in the 2D demo view. Animation, physics, C#/GDScript and original gameplay are never claimed restored by this visual add-on. For actual playable Godot project integration, import the copied `addons/ShaderStacker` and generated scene into an authorized working copy, keep the game's original main scene unchanged, and verify on hardware. Do not alter protected reference projects.

For an existing game use `--project-template ORIGINAL_GODOT_PROJECT` to create a separate working copy. The copied `project.godot` keeps `application/run/main_scene`, other enabled editor plugins and original scripts. The copy gains original Shader-Stacker code and standalone `generated/SpriteStackAssets.tscn` for later instancing into gameplay; 2.5D camera sorting may require using `StackCamera` for the relevant viewport. No original game is overwritten.
