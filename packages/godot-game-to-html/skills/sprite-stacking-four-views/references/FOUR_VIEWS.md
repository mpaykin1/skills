# Original 4-view sprite stacking → `stack.json`

**Upstream:** https://github.com/danielwh2/sprite-stacking, MIT Copyright © 2026 Daniel White, pinned commit `0cce02efe6aa81fffcd05744d7ab65d40f412de2`. The real upstream CLI at `skills/sprite-stacking/scripts/views_to_slices.py` is downloaded into the user's cache once, not copied/modified by the META GAMES bridge; official `LICENSE` remains in the fetched repo. Source script is run only when authorized source images are supplied.

Input is one orthographic 1×4 or 2×2 sheet. For deterministic correspondence use `--order reading` and place TOP, SIDE, FRONT, BACK in reading order. All four need matching dimensions/pivots/shape. A single image is insufficient: never hallucinate top/back geometry and present it as recovered original. For art already extracted as GLB use source-authentic `stack_from_glb.py`/scene-level pipeline instead.

The official slicer emits `slices-strip.png` as a horizontal concatenation of `vol[z]`, `z=0` (ground) on **left**. Each layer has `height=strip.height`, `width=strip.width / layer_count`; pixels are already RGBA. The bridge crops the original slices exactly, one PNG per horizontal layer, and creates standard `stack.json` with `layers`, `spacing`, `pivot`, `size` and source SHA-256. Its `spacing=[1,1,1]` is a dimensionless voxel grid inferred from views, not physical game-world meters. Optional manual correction of scale/pivot may be needed to match game collisions.

The original slicer's emissive detection and normal estimation are written as **candidate sidecars**, not silently connected to game lighting. `--colours 0 --shade 0 --dark-thresh 0` preserves as much original artwork as the visual-hull approximation allows. 4-view intersection is not accurate around occluded interior shapes, rear texture not visible in views, silhouettes with difficult hair/rope details, or mismatched views; warn about low-fidelity conversions rather than claiming 100% identical reconstruction.

Output is disjoint from source and never overwrites an existing folder. PNG layers are exactly the same carved volume that the real upstream creates; `stack_to_html.py` runs only after layer checks. HTML is a **visual preview**, not a Unity/Godot gameplay port. Preview browser/Playwright parity may be used to validate, but remains distinct from claims of full-game parity.

Dependencies: NumPy, Pillow, git, and (for HTML) Node/npm plus locally installed pinned Three.js and esbuild. No 3rd-party binaries shipped; first-time upstream download is a network step; on offline systems supply `--upstream-script /path/views_to_slices.py` or use cached upstream with `--no-install-upstream`. The license of the upstream implementation is MIT; the adapter preserves copyright attribution and links to the source.
