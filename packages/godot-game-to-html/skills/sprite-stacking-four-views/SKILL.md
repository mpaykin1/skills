# Four-view sprite stacking — integration with Godot/Unity → HTML

This is an ADDITIVE module of the existing `godot-game-to-html` plugin, not another game converter. **Use the official upstream `danielwh2/sprite-stacking` algorithm**, pinned to `0cce02efe6aa81fffcd05744d7ab65d40f412de2` (MIT), for new game objects drawn as four orthographic views in a single PNG. The Python bridge fetches the original source into an isolated user cache at first use and calls its real `views_to_slices.py`; no placeholder geometry or stock assets may substitute for missing views.

## One command — actual 4-view art to original-volume HTML

```bash
python skills/sprite-stacking-four-views/scripts/views_to_stack.py /authorized/views-top-side-front-back.png --out /build/prop
```

The input contains top, side, front and back (in reading order, 1×4 or 2×2); source transparent PNG preferred. Output includes `stack-data/stack.json`, `stack-data/layers/000.png` ... from low to high, real RGBA slice strip, normal-map and emissive-map **candidates**, original-view contact sheet, and `sprite-stacking.html` made by the **already installed** `skills/sprite-stacking-priority/scripts/stack_to_html.py` (WebGL2 volume first-hit raymarch; not cards pretending to be 3D). Runtime HTML bundles JS/offline after Node dependency packaging. No CDN at runtime.

Dependencies: Python 3, NumPy, Pillow, git for first pinned source fetch, Node/npm/esbuild and Three.js in the existing stack renderer cache for HTML compilation. `--no-install-upstream` and `--no-install-js` enforce offline reuse; `--upstream-script PATH` uses an already installed real upstream script. **The first run needs network only if the official upstream is not cached.** Nothing touches the source sheet.

`--slices 64` by default (4..192); `--order reading` enforces known art layout. Default `--colours 0 --shade 0 --dark-thresh 0` to retain original authored pixel colors and contours; quantization/shading are opt-in. `--round` for approved rotationally symmetric props only, `--top-nose`/`--side-nose` when view orientation is explicitly known. `--no-html` creates real slices only, for downstream Godot, PixiJS or Grunge pipelines.

## Complementarity (not competition)

- **Upstream 4-view slicer:** creates a *visual hull estimate* when only consistent multi-view artwork exists. Top+side+front+back silhouettes determine occupied volume, not an actual recovered game mesh. Never claim this restores unseen depth or game code.
- **Existing `stack_from_glb.py` / scene-parts pipeline:** prefers actual authorized UnityGLTF/Godot 3D meshes and preserves separate object transforms. Do **not** voxel-carve 4-view art if authoritative original GLB geometry exists.
- **Existing `stack_to_html.py` and WebGL2 Three.js raymarch:** consumes the standard `stack.json` and all independently authored `layers/*.png`, not the upstream software preview or procedural demo props. Source sprite geometry stays stable at any yaw/pitch.
- **Sprite Stacking Grunge Horror:** same bottom-first RGBA layer contract/axes. Preserve distinctive weathering, silhouette and color palette; do not force a low-color pixel palette on authored Grunge art.
- **PixiJS and Hero Animator:** approved original full-frame characters remain frame-by-frame; do not animate a single sprite by body warping. For animated volume sequences, export a separate complete `stack.json` per approved pose; state transitions must follow input.
- **KTX2/Basis, oxipng, glTF Validator, Playwright/Pixelmatch:** optional compression/verification on derivatives only, with input unchanged. Normal/emissive sidecar strips are generated by upstream, not automatically wired to the current shader; don't claim dynamic lighting until renderer integration is done.
- **Native Godot/Unity WebGL:** original physics, scripts, triggers and gameplay remain authoritative. Four-view HTML is a visual asset viewer only.

See `references/FOUR_VIEWS.md` for format, origin, rights and failure conditions. Do not claim successful image reconstruction without actual four synchronized views and a real run.
