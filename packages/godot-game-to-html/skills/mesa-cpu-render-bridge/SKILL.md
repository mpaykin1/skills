# Mesa llvmpipe CPU renderer
https://docs.mesa3d.org/drivers/llvmpipe.html ; https://docs.mesa3d.org/egl.html . Use signed Ubuntu Mesa packages in isolated CPU workers. Canonical runner: https://github.com/mpaykin1/skills/tree/nexus/mesa-cpu-20261126/packages/skill-synergy-manager/skills/mesa-cpu-render-bridge/scripts .
Use `LIBGL_ALWAYS_SOFTWARE=1 GALLIUM_DRIVER=llvmpipe EGL_PLATFORM=surfaceless python3 cpu_probe.py` to verify actual native renderer and draw/readback. No hardware GPU necessary. This probe is a technical fixture, not game imagery. It validates desktop OpenGL, not browser ESSL. Mesa versions determined by signed distribution and recorded; no fixed version claimed.
For Blender use existing pinned native Blender worker and explicitly select Cycles CPU for final/offline render; llvmpipe is for OpenGL context/Eevee diagnostics only where supported, not a guarantee that Eevee works. For Godot use Compatibility in authorized copied project with native display/Xvfb where needed; headless Godot may use dummy rendering, not proof of visual rendering. Check actual renderer log and nonempty image. For browser use existing Playwright + Chromium SwiftShader; llvmpipe is not automatically Chrome's ANGLE renderer. For Vulkan use separate Lavapipe route only if installed and verified. Native RenderDoc captures require compatible replay API/version. Never equate CPU FPS with phone GPU FPS.
Pipeline: glslang validates actual ESSL source -> Mesa llvmpipe checks native GL context and raster output -> Blender/Godot native scene rendering where verified -> WebGL Lint + Spector in separate browser sessions -> uninstrumented browser and real-device measurements. Route shader/depth errors to Forge, geometry/animation to Blender, alpha/texture to Sprite Stacking/GIMP, export to Godot Game to HTML. Keep original source assets, rig, camera, lighting, animation phase, physics, controls and seed. Never substitute approved hero or alter meta6. No visual or FPS PASS without real scene output. No instrumentation in release.
