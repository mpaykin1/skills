# Grange — художественный стандарт и П0–П43
Для любой игры и любого заказа. Создавай настоящие GIF, не промпты, сетки или статичные картинки. Референс `references/car-style.png` — пример живописного автомобиля, не универсальная форма. Полные правила, примеры, декодер и актуальный чекер: https://github.com/mpaykin1/meta6-lab/tree/main/asset-packs/incoming/bullet-car-gif . Повтор запроса: сначала прочитай PROGRESS.md, не переделывай готовое.

## Неизменный стиль
Реалистичный 2.5D Grunge Horror, физически правдоподобные пропорции, выразительный трёхмерный объём, зернистая живописная фактура, нерегулярное естественное старение. Приглушённая серо-синяя, угольно-чёрная, землисто-коричневая палитра, тусклые локальные блики, глубокие чёрные тени с читаемым силуэтом. Металл: выцветшая краска, хаотичная ржавчина, грязь, царапины, вмятины, окисленные кромки. Ткань: потёртости, швы, грязь, складки. Камень: трещины, патина, сколы. Органика: правдоподобная анатомия, неоднородная кожа, влажный или матовый материал по назначению. Ржавчину не добавлять на неметаллическое. Единый мягкий низкоключевой свет без клиппинга деталей. Не мультфильм, не воксели, не pixel art, не пластик, не паттерны, не контурный рисунок, не случайный шум вместо фактуры. Реальный прозрачный фон без пола, шахматки, текста, рамок, внешней тени и мусора.

Транспорт/предмет без указанного действия: полный бесшовный оборот 360°, 16 кадров по 22,5°, 100–140 мс, без повторения 0°; транспорт сверху 65–90° к горизонту, предмет 3/4; строго сверху = 90°. Заданный ракурс главнее. Персонаж/монстр: idle 8–12 кадров по умолчанию, без самопроизвольной атаки; отдельные полные позы для каждого действия/направления. Окружение: независимые ассеты, локальная анимация дыма, пыли, ткани, растений, света, механизмов, статичные части закреплены. Одноразовые действия не зацикливать против задания.

Зафиксируй силуэт, пропорции, материалы, палитру, повреждения, свет, проекцию, масштаб, pivot и хронометраж. Используй реальные независимые кадры/генератор GIF, одинаковые ячейки без полей и сетки, объект целиком в каждой. Не подменяй объёмный поворот вращением плоскости, кроме физически эквивалентного строго верхнего ортографического ракурса с неизменным светом. Не растягивать корпус, колёса, тело, одежду, конечности; не зеркалить асимметричный объект. Повреждения закреплены на объекте, без дрожания камеры и обрезки. При необходимости сборка `scripts/assemble.py`, не генерация рисунка. Не вырезать фон грубым порогом цвета. Единая палитра, прозрачный индекс, disposal=2, loop=0 для циклов. GIF — бинарная альфа; мягкие края/дым при необходимости также APNG. Не выдавать апскейл за детализацию. Проверить декодированные кадры, альфу на светлом и тёмном фоне, реальное движение и силуэт. ZIP отдельных GIF по заказу, без ручной обработки. Не обещать, что клиент проиграл анимацию, если это не подтверждено.

## ЗАЩИТА ОТ ПОДМЕНЫ И РЫВКОВ
П0. Каждый прозрачный GIF показывается прямо в чате отдельно, без текста на рисунке. По умолчанию 12–24 кадра, сторона до 320 px, ≤1,5 МБ, если заказом не оговорено иное.
П1. Эталон — закон: выпиши 5–7 признаков, визуально сравни каждый GIF с кадром того же ракурса. Нет совпадения — переделай, не показывай. Скрытые признаки проверяй в видимом ракурсе.
П2. Бери исходный кадр нужного ракурса, не перерисовывай его. Новый ракурс только если отсутствует. Фиксируй исходный индекс и идентичность байтов. Без эталона — базовый кадр нового объекта. Нет обязательного исходника — не подменяй.
П3. По каждому кадру отклонение среднего RGB непрозрачного объекта от соответствующего эталона ≤10 на канал.
П3а. Масштаб bbox ≤3%, единый свет, маски корпуса отдельно от эффектов. Для жёсткого ракурса после компенсации действия bbox ≤2% (минимум 1 px), центр ≤2 px, IoU ≥0,95. Проверяй обрезку, кайму, альфу. Исключения размера только явно заданные.
П4. Шов последнего к первому ≤ максимума соседних переходов по П22, не ноль. Синусоида с периодом цикла. При ремонте только шва сохранить исходные декодированные RGBA (скрытый RGB не учитывается) и длительности точно, вставлять кадры только на шве, переходы ≤ исходного max по П22. Не ослаблять П8 ради ремонта; не замедлять последний кадр.
П5. Под каждым прошедшим GIF вывод кода: признаки, ΔRGB, масштаб, шов/max, min/max, действие, размер, кадры, вес. Любой FAIL/BLOCKED — не показывать как готовый.
П6. Ошибку исправляй сам до выдачи.
П7. Новый тип ошибки — новое правило, исполняемая проверка и пример.
П8. По П22 min ≥ max/3, включая шов цикла. Без повторов. Исключение только заранее заданная вершина прыжка ≤2 кадров, суммарно ≤2 обычных кадров. Длительности min/max ≥0,8, не обходить ритм замедлением.
П9. По П22 max соседних кадров ≥2,0.
П9а. Вторичное движение с задержкой, без телепортов, визуальный контроль.
П10. Действие заметно сразу: прыжок — bbox +12–18% по обеим осям на вершине, земля в пределах 3% эталона, возврат, отдаляющаяся бледнеющая тень, посадка/грязь; свет — лучи ≥ длины корпуса, ≥10% светящихся пикселей в каждой из 10 продольных полос, постоянные огни во всех кадрах, вспышка ≥40% (max−min)/max; повреждения — выраженные в нескольких независимых зонах (борта, детали, каркас), сравнение с зарегистрированным целым объектом, минимум 3 непересекающиеся зоны, в каждой ≥10% пикселей с RGB MAE ≥12; поворот — заметный крен, занос, плавный возврат. Не читать действие — переделывать.
П12. Запускай Pillow/NumPy checker по фактическому GIF: число кадров, размер, вес, прозрачность, ΔRGB, bbox, min/max, шов, длительности. Не выдумывать числа. В `scripts/check_gif.py` передай эталон, индексы, маски и action JSON; --rigid и --preserve-prefix по назначению. JSON stdout и exit code обязательны. Numeric PASS не заменяет П1, П9а, П10. Локальный замер только предварительный.
П13. Количественно проверяй П10 по маскам и эталону; без нужных масок/ракурсов BLOCKED. Исключение размера холста для эффекта не уменьшает корпус.
П14. Качественную подмену сохраняй отдельно other/ или other-cars/ с назначением, не выдавай за эталон.

П16. Публикация = ссылка на готовый файл, 40-символьный SHA коммита, зелёный прогон Actions, совпадение байтов и повторный замер raw по П22. SHA-256 файла не доказательство загрузки.
П17. Сам перебери разрешённые способы (base64, части, GitHub API, ветка+PR); если все недоступны, точный блокер, без ложного PASS.
П18. Перед отчётом доделай всё доступное; отчёт только об остатке.

## КОНВЕЙЕР
П19. Один GIF: создать → проверить/исправить → показать в чате с кодовым выводом → загрузить → записать номер, файл, commit SHA, Actions в PROGRESS.md. Только затем следующий (если ждёт Actions, допускается начать следующий, строка сразу после зелёного прогона). Не пакетировать исправления/показ.
П20. Максимум 3 GIF за ответ, затем только остаток. Продолжение с первого несделанного.
П21. Найди эталон и старые GIF один раз, точные пути в первую строку PROGRESS.md. При повторе брать оттуда. Если путь недоступен — один поиск в репозитории и Library, исправить путь; не придумывать исходники.
П22. Единая метрика: средняя абсолютная разница R,G,B по ВСЕМУ кадру 0–255 после `frame.convert('RGB')`, `sum(ImageStat.Stat(ImageChops.difference(a,b)).mean)/3`. Без масок, альфы, обнуления скрытого RGB, подложки, частичного кадра. П4, П8 и П9 (2,0) только так, без округления до порогов. Для публикации скачай сам файл обратно с GitHub raw URL (предпочтительно закреплённый commit SHA), не локальную копию. `--raw-url` обязателен для подтверждения. Сохрани URL и вывод. Старые дефектные версии проверять отдельно, не заменять их новыми.

## ЕДИНЫЙ КОНВЕЙЕР OPEN SOURCE — П23–П28
П23. **Идентичность, не только средний цвет.** Используй `scripts/synergy_gate.py` и настоящий Mapbox Pixelmatch 8.0.0: сравни защищённые детали корпуса с точно соответствующим утверждённым ракурсом. Регистрация только явная, без свободной подгонки формы; масштаб прыжка компенсируется только после независимой проверки П10. IoU корпуса после регистрации ≥0,85, защищённая область ≥70% корпуса эталона, Pixelmatch changed/protected ≤3% (threshold 0,10, includeAA). Это дополнительные блокирующие проверки, не замена П1, П3/П3а или П22. Маски разрешённых изменений (локальные повреждения/эффекты) зафиксированы до проверки, не исключать обнаруженные расхождения задним числом. Новый ракурс требует отдельного утверждённого эталона.
П24. **Антирывок Hero Animator, адаптированный к коротким GIF Grange.** Независимый анализ центров маски и скоростей с реальными длительностями, включая шов. П22 остаётся единственной метрикой разницы кадров. RIFE только как необязательное создание кандидатов для одного ракурса/действия жёсткого транспорта или эффектов: официальный ECCV2022-RIFE и совместимые веса, чёрная/белая подложки для восстановления alpha, исходные PNG неизменны. Запрещён RIFE для персонажей/животных/монстров, разных ракурсов, разных действий. Никакого автоматического PASS после интерполяции. Пройти весь конвейер заново, сохранить реальный хронометраж, не дробить шаги ради порогов.
П25. **Маски взаимно контролируются.** Реальные MobileSAM ViT-T (из ЛОКАЦИЯ) и SAM 2 (из Living Image Animator) получают одни и те же явно заданные box/positive-negative points на каждом декодированном кадре. IoU двух моделей и каждой с маской корпуса ≥0,90; спорные маски исправить, не выбирать удобную. Маски идут одновременно в P3/P3a/P10, Pixelmatch и антирывок; эффекты, дым, свет, зоны повреждений отдельно. Не обнулять RGB и не подставлять маски в П22. Для готовой прозрачной графики допускаются исходные отдельно утверждённые маски (фиксировать hash и явно указывать, что модели не запускались). rembg только при непрозрачном источнике — генерирует отдельную alpha-маску без замены исходных RGB, после него всё равно проверить согласие сегментаторов или утверждённые маски. Нельзя выдавать автоматически вырезанный фон за проверенную идентичность.
П26. **Регрессии и независимое декодирование.** Перед публикацией прогони неизменные исторические 11–13 Bullet Car (архив `Bullet-Car-GIF-Pack-01-13.zip`, папка actions, точный источник в PROGRESS.md) через тот же канонический чекер: 11 — FAIL П10, 12 — FAIL П9, 13 — FAIL П8, П10 отдельно проверить с настоящими масками; BLOCKED по П10 не считать доказанным числовым FAIL действия. Скрипт сверяет hashes исторических файлов лишь для защиты регрессии, не доказательство GitHub. Каждый новый тип ошибки — новый неизменный отрицательный пример. FFprobe независимо декодирует конечный GIF, сверяет кадры и длительность Pillow; несовпадение блокирует. Не перекодировать проверенные байты после проверки.
П27. **Один канонический чекер.** `synergy_gate.py --publication` загружает checker строго из GitHub на закреплённом commit, сверяет git blob и выполняет его, затем проверяет именно raw GIF с закреплённым commit SHA. Локальный `check_gif.py` только предварительный. При изменении канонического чекера явно обновить pin+blob в скилле после регрессий, не использовать плавающий main. Сравнить локальные и опубликованные байты. Не смешивать результаты разных версий. Привязка к hash означает целостность, а не визуальное одобрение или факт публикации.
П28. **Блокирующий выпуск.** Один GIF: утверждённый источник → при необходимости `prepare_candidates.py` (rembg/RIFE) → раздельные маски MobileSAM+SAM2 / утверждённые исходные → P22 + П0–П21 → анти-рывок → Pixelmatch → FFprobe → визуальный осмотр тех же байтов → предварительный PASS → загрузка кандидата в отдельную разрешённую staging-ветку → повтор `synergy_gate.py --publication` по raw → только PASS_PUBLICATION_GATE разрешает перенос в итоговый путь; после переноса снова проверить raw байты и записать commit/Actions в PROGRESS.md. Ни FAIL, ни BLOCKED не разрешают замену ассета, отчёт о готовности или обход инструмента. Если зависимость отсутствует — не имитировать результат. Установка реальных бесплатных OSS при доступной сети, без весов/бинарников в архиве скилла. Прежний стиль, П19–П20 и все пороги неизменны. Инструкция запуска и формат входов: `references/synergy-pipeline.md`.

## П29–П30 — структурная идентичность и реальное движение
П29. **SSIM + Pixelmatch, не вместо друг друга.** `scripts/texture_motion_gate.py` использует настоящий `skimage.metrics.structural_similarity` (RGB, data_range=255, window=7). Тот же зарегистрированный эталон и защищённая маска П23–П25; SSIM только по окнам целиком внутри защищённой области. Среднее ≥0,94, 10-й перцентиль ≥0,85, доля окон SSIM <0,80 ≤5%; недостаток окон — BLOCKED. Не подгонять изображение дополнительно, не исключать новые зоны задним числом. Pixelmatch остаётся обязательным. SSIM ловит смазывание и потерю фактуры, а не доказывает художественное совпадение. П22 не изменяется.
П30. **OpenCV pyramidal Lucas–Kanade + локальный SSIM.** На тех же утверждённых масках тела отслеживай углы GFTT между всеми кадрами и на шве, с обратной проверкой трека ≤1,25 px. Для жёсткого объекта или одного ракурса транспорта/прыжка/света/повреждения: ≥8 надёжных точек и ≥65% отслеживаемых; >25% локальных компенсированных 7×7 патчей с SSIM <0,75 — FAIL (мерцание/подмена фактуры); ≥45% надёжных треков с резким разворотом двух существенных шагов — FAIL. Скорость использует действительные задержки GIF. Для подлинной смены ракурса/сложной позы треки могут исчезать, optical flow диагностический; П23, П29 и все старые блокирующие проверки по-прежнему обязательны. Не выдавай смещение камеры/частиц за движение тела. Не менять пороги для конкретного неудачного ассета. Ни flow, ни SSIM не генерируют и не исправляют кадры; при FAIL вернуться к авторским кадрам/допустимым кандидатам RIFE и перепроверить. П28 включает П29–П30; отсутствие scikit-image/OpenCV блокирует выпуск. `python scripts/texture_motion_regression.py ORIGINAL.gif` — контроль на исходном прозрачном кадре: оригинал/плавное смещение, размытие, рывок, мерцание. Сохраняй оригиналы. П26 неизменен.

## SPRITE STACKING FIRST — П38–П43
П38. **Основная технология для максимального числа ассетов:** транспорт, оружие, предметы, механизмы, мебель, архитектура, монстры и персонажи при наличии полных объёмных поз. Используй один утверждённый текстурированный 3D-источник (Blender/авторские сечения, существующие совместимые стеки), настоящие XY RGBA срезы по Z и `scripts/stack_pipeline.py`. Не заменять этим уже утверждённые оригинальные GIF, не перерисовывать их. Для неизвестных сторон реконструкция — только кандидат, не точная копия. Сохрани исходную фактуру, цвет, масштаб, свет, отверстия, решётки, асимметрию; запрещены воксельный визуальный стиль, простые примитивы вместо искусства, плоские PNG на полосах, одинаковые экструзии, зеркальные ракурсы. Для дыма/огня/дождя, уже утверждённого 2D-источника, органических поз без качественного стека или явного запроса 2D допустим обоснованный согласованный 2D-путь без подмены; без согласования BLOCKED, а не искусственный стек. Не подменять художественную точность процентом использования технологии.
П39. **Один стек — все ракурсы.** Единые мировые координаты +X вправо, +Y вперёд, +Z вверх, общий pivot, ортографическая камера с неизменной областью обзора, реальные прозрачные срезы в одном масштабе. Срезы PNG RGBA снизу вверх, шаг по Z согласно минимальной детали (ориентир 64–128, XY 256–512 при достаточном бюджете; тонкие детали и отверстия не терять, AA). Раздельные стеки колёс, кузова, подвески, решёток, дверей, руля, оружия, рук и прочего — жёсткие преобразования относительно шарниров; тело органики — отдельные полные авторские объёмные позы, без растяжения и интерполяции конечностей. Все 8 направлений и повреждения происходят из одного источника; новые состояния меняют лишь разрешённые детали. `stack_pipeline.py` выполняет реальный DDA обход срезов и глубинное сравнение частей, включая боковые виды и полюса. GIF 12–24 кадра, ≤320 px, ≤1,5 МБ согласно Grange; отдельные обзоры с большей длительностью только по явно заданному исключению. Не заменять отрендеренный GIF независимым изображением. Манифест и каждый срез фиксируются SHA256, повторный детерминированный рендер обязан воспроизвести точные байты GIF.
П40. **Синергия проверок:** из того же depth-рендера получай видимые маски кузова, деталей и отдельно эффектов. MobileSAM + SAM2 проверяют эти маски или используют утверждённый исходный режим П25; для корпуса IoU с маской реального стека ≥0,95. Pixelmatch + SSIM сравнивают защищённую фактуру с утверждённым исходным ракурсом. OpenCV Optical Flow проверяет движение колёс/деталей и рывки в фактическом GIF; П22 не меняется. RIFE не нужен для рендера из 3D-траектории: увеличить число реальных поз в рамках лимита; rembg только при подготовке непрозрачного исходного искусства, не на уже прозрачных срезах. FFprobe и весь П0–П37 остаются обязательны.
П41. **Обязательный артефакт стека:** исходный арт/модель, раздельные PNG-срезы + `stack.json` (шаг, pivot, SHA всех слоёв), `recipe.json` (части, позы, камера, размеры и время), GIF, отдельные кадры и маски. По заказу ZIP со всем нужным для сборки; без отчётов по умолчанию. HTML/Three.js при запросе использует тот же исходный стек, корректную глубину, для ракурса вдоль плоскостей — depth-correct объёмный рендер или предрендеренные из него виды, а не один billboard. Бюджет памяти и мобильный FPS через LOD одного источника, не подмена.
П42. **Блокировка подмены маршрута:** в `synergy_gate.py` обязателен `production_route: sprite-stacking` и `stack_recipe`; шлюз повторно рендерит все срезы и проверяет точное совпадение байтов GIF и масок. Для допустимого 2D-исключения `production_route: approved-2d-exception` с причиной и фактическим утверждением, привязанным к эталону. Никакой ложной отметки approval. Отсутствие стека для объёмного объекта — BLOCKED_INPUT, не PASS. Старый серверный П0–П37 PASS не заменяет П38–П43: до синхронизации сервера отдельно запустить новый локальный шлюз по тем же байтам и проверить на сервере прежние правила. Если локальная проверка невозможна — не выпускать. Не утверждать, что GitHub workflow обновлён только по факту обновления плагина.
П43. Источник рендера — адаптация алгоритма из авторского Sprite Stacking Grunge Horror. Используй его в Grange как единый маршрут, а не вторую несовместимую версию. Схема и команда: `references/sprite-stacking.md`. Не считать программную демонстрацию доказательством сохранения конкретной машины. Утверждение исходника и полноценный художественный осмотр по-прежнему обязательны.
