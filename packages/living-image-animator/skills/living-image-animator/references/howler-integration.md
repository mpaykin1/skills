# Howler.js 2.2.4 — original spatial audio × PixiJS 2.5D

Source: https://github.com/goldfire/howler.js — MIT; `howler@2.2.4` *complete* browser distribution includes `howler.core` and its `howler.spatial` plugin. License is stored in `LICENSE.howler.md`. Requires no GPU, no speech synthesis, no paid services or remote sound servers. No sound recordings are generated. CPU/Web Audio handles playback.

## Unified visual and aural pipeline

`howler_delivery.py` executes the complete **unchanged** `pixi_culling_delivery.py` pipeline first: hand-painted separate full-body RGBA poses and original animation gates -> GIF+source ZIP -> authored Tiled/LDtk navigation and Godot/Blender -> real offline PixiJS + PathFinding.js + atlas -> viewport and parallax -> filters -> particles -> real @pixi/tilemap source tiles -> PixiJS 8 native CullerPlugin. Only then it adds `living_scene_pixi_audio.html` and `living_scene_pixi_audio.zip` and appends both original audio assets and browser package to the existing verified `living_scene_assets.zip`. It does not overwrite original outputs, tiles, physics HTML, GIF, APNG (if generated by its independent stage), avatar frames or layer ordering.

Audio files are **only author-supplied** `.mp3`, `.ogg`, `.wav` from scene-relative paths; their original bytes are preserved and SHA256 recorded. Max 8 MB/file, 24 MB across at most 12 sounds. No microphone, no external URLs, no CDN, no synthesized footsteps or fabricated effects. The complete Howler.js minified browser binary (with its spatial plugin) is embedded in the standalone HTML by vendoring `howler@2.2.4` once through npm; supplied `--howler-js` genuine pinned build also works. If unavailable, fail closed. User starts audio with a visible button because iOS/Android/desktop browsers block autoplay. It never plays on page load without a real tap.

Howler's 3D spatial positions use the *world-space camera center* from `pixi-viewport`, or a stable original actor ID, as listener. `pixels_per_unit` converts original illustration/world-pixel positions into Howler distance coordinates. World sounds use manually authored coordinates; actor sounds follow the **original already animated** avatar's root/box position. This only changes sound position; the original per-frame full-body pose textures, physics, character count, pathfinding and pixel content remain untouched. Ambience (rain, wind, drones, etc.) is nonspatial; mode `ambience` skips positional attenuation. Audio can complement existing screen-space rain, dust or light sources but does not infer sound cues from particles, pretend that 2.5D is full 3D acoustic simulation, or imply sound automatically exists without a source recording.

## Example source scene settings

```json
{
  "pixi": {
    "audio": {
      "pixels_per_unit": 100,
      "master_volume": 0.75,
      "listener": "camera",
      "sounds": [
        {"id":"sea_wind", "file":"sounds/wind.ogg", "mode":"ambience", "loop":true, "volume":0.3},
        {"id":"old_generator", "file":"sounds/generator.wav", "mode":"world", "position":[320,160], "ref_distance":1.5, "max_distance":30},
        {"id":"hero_gear", "file":"sounds/gear.mp3", "mode":"actor", "actor_id":"hero", "loop":true, "volume":0.2}
      ]
    }
  }
}
```

These are illustrative references to files **supplied by the user**, not provided by this skill. The `hero` ID must exist in the original verified actor inventory. Characters are never turned into music-trigger props, and audio activity does not replace pose-quality gate coverage.

## One-click/offline output

```bash
python scripts/howler_delivery.py source.png --scene scene.json --out output --fps 24 --seconds 48 \
  --fetch-pixi --fetch-viewport --fetch-filters --fetch-particles --fetch-tilemap --fetch-howler
```

Or use the actual already-installed `--pixi-js`, `--viewport-js`, `--filters-js`, `--particles-js`, `--tilemap-js`, `--howler-js` with `--pathfinding-js` when needed. The latter avoids network completely. This stage is **additive**, not a substitute for the other native art/editing and pose-annotation modules. Original editable source and `.kra/.pxo/.tnz` assets are preserved by their respective earlier stages. Audio works offline once packaged; no new DNS/network traffic during playback. A public game URL still requires actual hosting and browser testing.
