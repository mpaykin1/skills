# Original Shader Stacker × Living Image Animator — Godot 4 bridge (v0.40)

**Source:** https://github.com/x3cca/Shader-Stacker (original upstream now also associated with CoolDotty), pin `21d86ab62140b0d08ea217982036e3cb184afed5`; MPL-2.0. This source's `plugin.cfg` declares v4.0.4 whereas the README describes its most recent tagged v4.0.5: do not mislabel the pinned source files as v4.0.5. The original GDScript source is embedded at `vendor/ShaderStacker/{SpriteStack,StackCamera,Reset2D}/*.gd` plus `init.gd` and `plugin.cfg`. Three small local editor icons replace upstream icon artwork; the upstream game visual code itself is not replaced. License text is shipped as `LICENSE.shader-stacker.txt` and copied into every generated Godot addon.

**Distinct task:** The existing `danielwh2/sprite-stacking` performs source four-view-carving. The existing `Sprite Stacking Grunge Horror` pipeline provides true Z-section PNG stacks and persistent pivot/spacing. New adapter reads *those exact source files* with the existing validated `sprite_stack_bridge.stack` and packages them **bottom-to-top into a one-column Texture2D** (the bottom slice occupies the bottommost row), used by authentic Godot 4 `SpriteStack` draw commands. The shader stacker title notwithstanding, upstream Godot 4 uses `CanvasItem` / `draw_texture_rect_region`, not a general GPU raymarching shader; don't promise perspective 3D or automatic speedups.

**Projection and controls:** Godot source-registered scene coordinates and exported original `CharacterBody2D` physics remain authoritative. The addon uses `StackCamera` for screen position / Z sort, live yaw rotation on Q/E or drag, wheel zoom, and original intact `SpriteStack` draw behavior. The original `SpriteStack` draws at x2, so the custom scene node uses a reciprocal x0.5 uniform transform only for consistent pixels in the new Godot variant; original transparent RGBA PNG sheets are never resampled or changed. Pitch comes from source `dz/dx`, constrained to Godot native range. Rendering is still fundamentally 2.5D; use existing Three.js/GLSL volumetric exporter for true 360° occlusion and under-views.

**Character handling:** original `ActorScript` stays active, with all of its 2+ independent original hand-painted action clips, source-accurate frames and navigation. Only when every approved frame is backed by a separately source-authored, matching-sha `stack.json` is the old Sprite2D hidden in the new Godot variant and the stacked texture selected by the *same original frame index*. The original sprite frames remain in the project as the source of truth. No cutout mesh deformation or single-frame proxy movement is possible.

**No double imaging:** the new scene requires artist-created `sprite_stacking.background` PNG (or source `sprite_stacking_game.clean_plate`) for static objects that were visible in the original flattened source image. It is copied only to the additional Godot project, not written over the original GIF or asset ZIP. If art is missing or camera registration cannot be proved, fail closed.

**Command:** `python scripts/shader_stacker_delivery.py source.png --scene scene.json --out result --fps 24 --seconds 48` (optional `--godot` native Godot4 check). For validated existing assets: `python scripts/shader_stacker_bridge.py --approved-zip result/living_scene_assets.zip --godot-zip result/living_scene_godot.zip --scene scene.json --out result`.

**Distinct outputs:** Original `living_scene_godot.zip` is unchanged; the additional `living_scene_godot_shader_stacker.zip` contains authentic upstream Godot addon, original source atlas textures, new `StackWorld.tscn` and a camera/animation sync controller. Other separate runtime variants (Three.js GL raymarch, PixiJS/Matter/YUKA gameplay, Howler/Rhubarb, FFmpeg, APNG/WebP) remain intact rather than being falsely claimed as one game file. Always distinguish native project output from actual engine launch and performance verification.
