# Sprite Stacking FIRST — all eligible game visuals

When asked for a 3D/2.5D game, room, house, building, castle, vehicle, weapon, object, monster, creature, furniture, NPC or animated world, **FIRST** create the original four real orthographic transparent views and turn them into horizontal sprite-stacking layers. The default is `scene.sprite_stacking.mode="maximal"` with >=90% coverage of all declared eligible volumetric items. Exclude only far sky, flat floor, weather, post FX and UI from volumetric coverage. Architectural details, doors, gates, rails, bridges, trees, furniture, weapons, cars, robots, creatures and every suitable character should be 3D sprite stacks wherever authentic views exist.

**Mandatory:** Read `skills/living-image-animator/references/sprite-stacking-game-integration.md **and** the installed `skills/living-image-animator/references/sprite-stacking-integration.md` (original Three.js 3D GLSL volume mode)` and obey all existing full-body artist identity/motion/gait/collision rules in `skills/living-image-animator/SKILL.md`. Do not draw fake primitive 3D boxes, repeat the same top slice, forge unseen sides from one picture or substitute a monster/hero for another. Grunge Horror style: real painted rust, patina, dents, dirt, irregular metal texture, muted blue-grey, dark shadows, authentic transparency, no repeating patterns, no cartoon voxel grid. The author-approved character PNGs and sprites must remain byte-for-byte intact. Original 2D source+pose gate first, volume build second.

FIRST reuse the installed original `stack.json` + XY/Z PNG slice packs from the Three.js GLSL renderer. If a genuine pack does not exist, use `scripts/sprite_stacking_slicer.py` for top/side/front/back carving, `scripts/sprite_stacking_bridge.py` for original-cel source matching and seamless 360 pseudo3D rendering in existing real PixiJS8 + Matter.js + PathFinding A* + nipplejs + optional YUKA browser game, `scripts/sprite_stacking_delivery.py` for the complete finished extra standalone HTML + ZIP, and optionally `scripts/sprite_stacking_glb.py --approved-zip ... --scene ... --out ... --all-poses` for real glTF2 alpha-textured source-slice 3D assets for Blender, Three.js, Godot. Preserve all previous PixiJS, Howler, Rhubarb, APNG/WebP, FFmpeg and source editor routes as independent valid outputs; never fake a merge of pipelines that have not been actually run.

**Controls:** One stable actor/volume through all 360° yaw views. Arrow/WASD or fixed nipplejs gamepad physically moves the original actor, YUKA NPCs can chase/patrol along real A* with actual Matter collisions, Q/E and two touch buttons rotate source volumes 360°, R/F and elevation buttons adjust pitch; all action frames are complete distinct author-verified four-view volumes. For interactive gates, require authentic closed/open original four-view state art + genuine matching source Matter trigger and static collider; when opened, both visuals and collision change together. Screen UI is not a 3D asset.

**If source art is missing, say exactly what is missing; do not declare a finished 360 sprite stack or playable game.** Plugin update is a skill publication only; a hosted public game URL requires actual deployment and verification. Follow user's preference: only graphical outputs and playable links when they are requested, no unsolicited reports.

Two modes must reinforce one another without overwriting source files: `scene.sprite_stacking` feeds the existing authentic Three.js 0.187 GLSL full-volume renderer; `scene.sprite_stacking_game` feeds the new PixiJS8+Matter+YUKA playable sprite-stack scene and can reuse the exact same source `stack.json` and PNG cross-sections. The script `sprite_stacking_glb.py` uses real MIT trimesh to export the same actual slices as glTF2 GLB for Three.js/Godot/Blender asset reuse. Do not call the Pixi projector raymarching or claim that Three.js preview includes Matter physics.
