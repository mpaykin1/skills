# Intel Open Image Denoise — CPU cover rendering
Upstream: https://github.com/OpenImageDenoise/oidn ; Blender 4.5 LTS includes the Cycles integration (https://docs.blender.org/manual/en/4.5/render/cycles/render_settings/sampling.html). Use the official build; no separate GPU requirement, no paid compute. OIDN is Apache-2.0; Blender licensing is separate. This package configures the bundled denoiser; it does not ship Blender or OIDN weights/binaries.

1. Render the approved scene twice, with unchanged geometry, source hashes, camera, poses, materials, VDB, color transform and timing. Reference: `blender -b --factory-startup --python-exit-code 1 --python scripts/cycles_cover.py -- --scene /path/scene.json --out /path/raw --denoise off --samples 256`. Candidate: same command with `--out /path/oidn --denoise oidn --samples 64`. These sample counts are examples, not guaranteed quality or speed. Choose adequate converged reference and candidate per scene. Both use CPU fixed samples, fixed seed. OIDN explicitly uses RGB + albedo + normal, accurate prefilter, high quality. Default renderer mode is now off. Measure actual wall times; no claimed speedup before real rendering.
2. The denoiser is spatial, not a temporal animation model. Review every frame and loop seam, especially thin sprite edges, dark grain, emissive marks, translucent characters and moving fog. Do not remove intentional grunge or compensate with artificial sharpening. Compare only matched frames. Establish calibrated limits on approved/rejected examples; no universal LPIPS or temporal threshold. `oidn_review.py` requires exact alpha and checks maximum LPIPS over every pair plus maximum mean change of premultiplied RGB residual across successive frames, including last→first. This is a drift indicator, not proof of flicker-free animation. Provide actual reviewed calibration and visual-approval IDs, not invented values. The gate rejects changed input hashes, mismatched timing, dimensions, CPU settings and missing LPIPS weights. If rejected, preserve raw and increase samples/adjust lighting; never alter source geometry just to make denoising pass.
3. Run `python scripts/oidn_review.py --reference /path/raw-frames.json --candidate /path/oidn-frames.json --out /path/oidn-reviewed.json --max-lpips <calibrated> --max-temporal-drift <calibrated> --calibration-id <real-id> --visual-approval-id <real-id>`. Output is a hash-bound candidate manifest; `webp_cover.py` refuses unreviewed OIDN frames. Encode approved candidate or raw reference separately, then check playback and mobile rendering. Keep both original renders and all canonical assets. OIDN affects rendered cover only, never O-Voxel, RGBA stacks, KTX2 or GLB. Do not confuse denoised previews with source PBR maps or actual motion improvements. Missing Blender/OIDN/LPIPS is a blocker, not a successful denoise.
