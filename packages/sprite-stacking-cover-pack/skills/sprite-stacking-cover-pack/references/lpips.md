# LPIPS — visual feedback loop
Upstream: https://github.com/richzhang/PerceptualSimilarity (LPIPS 0.1.4, verify dependency and checkpoint terms before commercial redistribution). Use pretrained AlexNet, LPIPS v0.1 calibration, eval mode and RGB normalized to [-1,1]. The package includes only the adapter. Install lpips==0.1.4 and compatible torch/torchvision in a separate environment; acquire the official AlexNet weights through torchvision in an authorized environment, then place alexnet-owt-7be5be79.pth in the torch hub checkpoints directory. The adapter refuses missing/incorrect checkpoint; no random or proxy metric. CPU supported, CUDA optional.

The real rendered cover and original asset previews are inputs. Compare matched camera/view and explicit corresponding crops for fidelity; do not interpret different pose/perspective as reconstruction error. Separately compare every catalog cover for near duplicates. Preserve the approved sketch, uncompressed render, source geometry, material maps and animation. Compare before/after optimizations on identical frames. Alpha differences are reported separately; transparent objects are composited on light and dark backgrounds. Distances are not percentages, and a small distance cannot prove artistic quality, geometry, or semantic uniqueness. Use representative approved and rejected pairs to calibrate thresholds per fixed model and resolution; absent thresholds mean review only. Independently require distinct reviewed heroId, paletteId and architectureId, and visual review of silhouettes, composition, detail, identity and animation. Do not relabel repeated assets to evade review.

Example manifest (paths relative to manifest directory, use real files):
```json
{"identity":{"heroId":"harpist","paletteId":"sapphire-lavender","architectureId":"skybridge"},"catalogIdentities":[{"id":"other","heroId":"knight","paletteId":"copper","architectureId":"forge"}],"pairs":[{"id":"hero-detail","mode":"matched","kind":"silhouette","candidate":"render.png","reference":"approved.png","aligned":true},{"id":"catalog-other","mode":"catalog","kind":"cover","candidate":"render.png","reference":"other.png"}]}
```
Run `python scripts/lpips_guard.py --manifest comparisons.json --out perceptual.json --device cpu` with installed model. Optional thresholds `matchedMax`, `duplicateMax`, `alphaMax` and `calibrationId` must be derived from real approved/rejected examples. Add per-object crops `candidateCrop` and `referenceCrop` in pixel XYXY; require alignment and matching aspect ratios. For animation repeat comparisons on corresponding frames (including reference vs optimized frame) and retain maximum drift; no motion quality claim from LPIPS alone.

Feedback: silhouette drift → SAM masks / TRELLIS reconstruction; geometry drift → TRELLIS / Infinigen / Open3D and O-Voxel; material drift → Material Maker + O-Voxel; atmosphere drift → OpenVDB and lighting; repeat candidate → unique hero, architecture, palette and scene; compression drift → encoder settings, not source asset edits. Re-render from the same scene and compare again, preserve accepted version if worse. Do not mark ready based on the metric. Missing runtime is blocked, not a fake score. The structured comparison is internal workflow data, not a user-facing report.

For WebP candidates use [libwebp integration](libwebp.md): compare every decoded matching time interval with the same pretrained metric; preserve exact alpha and timing. No calibrated lossy mode without weights. Lossless visible-pixel equality requires no LPIPS score.
