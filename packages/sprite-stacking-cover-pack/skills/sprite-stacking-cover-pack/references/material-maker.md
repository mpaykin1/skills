# Material Maker: PBR surface enrichment

Upstream https://github.com/RodZill4/material-maker ; official CLI https://rodzill4.github.io/material-maker/doc/command_line.html . Material Maker must be installed separately (check exact executable/version and graph/node dependencies). Use the official exporter rather than fabricating node graph schemas or textures. Preserve the approved palette and source material; license-check graph and imported images separately. No paid runtime.

1. Author or use an approved original `.ptex` graph specific to the chapter's stone, cloth, metal or other surface. Export using `python scripts/material_maker_pack.py export --exe /path/to/material_maker --graph material.ptex --out maps`. The documented Blender target exports PNG maps. Review actual filenames and color spaces; do not assume export resolution or filename conventions. For externally exported maps keep their graph and provenance separately.
2. Choose a semantic surface region on the real native grid. Save a boolean `region.npy` (one entry per row of `coords` in `native_grid.npz`) and explicitly bind its SHA256 source grid. SAM masks are image-space guidance, not voxel masks: derive the region via reviewed mesh material IDs or spatial selection, not directly copying image mask pixels. For triplanar projection provide reviewed native-space surface normals, one Nx3 row per native sample. For planar architecture choose xy/xz/yz. Use native coordinate units and a fixed projection origin for all poses; animated meshes need rest-space mapping or separately baked maps to prevent texture swimming.
3. Create `material.json` next to maps and region, e.g.:

```json
{"sourceGridSHA256":"<actual digest>","region":"region.npy","projection":"xz","repeatWorldUnits":0.2,"projectionOrigin":[0,0,0],"detailStrength":0.25,"maps":{"baseColor":"stone_albedo.png","roughness":"stone_roughness.png","metallic":"stone_metallic.png","normal":"stone_normal.png"}}
```

`python scripts/material_maker_pack.py apply --asset original-pack --material material.json --out material-variant`.
The CPU adapter applies stable bilinear material detail in native 3D coordinates, preserving original slice spacing, geometry, alpha and original hue via bounded luminance modulation. It retains roughness/metallic in native channels when available, otherwise indexed sidecar samples. Normal, AO, height and emission maps are retained as source maps, NOT falsely baked into the PNG color or rendered automatically. No displacement or topology changes. No new geometry is produced. The source grid and original mesh/reference are preserved. The derived native mesh is the same geometry; source GLB textures are not rewritten. New volume color is authoritative for the variant. For animated surfaces use rest-space material bake upstream; this adapter alone does not solve deformation correspondence.

4. Reuse the existing Open3D geometry audit on the variant's bound grid/mesh, then OpenVDB RGBA archival and normal stack rendering. Keep atmosphere densities separate. Infinigen assets and TRELLIS.2/O-Voxel both use this same adapter; preserve source scene placements and do not confuse projected texture with recovered appearance. Include the actual variant stack in scene.json and render cover from it. Inspect against approved sketch and all previous covers before readiness. Material Maker executable not bundled; a CPU map import is not proof that its graph exporter ran.
