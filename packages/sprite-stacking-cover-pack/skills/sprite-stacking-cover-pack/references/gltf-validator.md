# Khronos glTF Validator
Upstream https://github.com/KhronosGroup/glTF-Validator (Apache-2.0). Official CPU JS package: https://www.npmjs.com/package/gltf-validator. Install an explicitly reviewed version in the scripts directory or an ancestor node_modules using npm, record the lockfile and version in the authorized runtime. No runtime downloads. `node scripts/gltf_validate.mjs asset.glb` calls validateBytes with unlimited issue count and refuses external resources. `python scripts/gltf_validation.py --source asset.glb --out validation.json` applies the strict gate.

Both meshopt_pack.py and gltf_transform_pack.py now require source and final candidate validation; the latter also validates intermediate dedup output. Zero errors and warnings, no truncated report, all used/required extensions must be supported by the installed validator. This is deliberately conservative: versions without meshopt support will block those candidates; never silence the warning or pretend to validate compressed accessors. Keep the canonical source, separately verify actual decoding, animation, material/alpha and visual comparisons before permitting an optimized asset. No external URIs; embed resources first. SHA256 and byte count bind validation to exact GLB, not to similarly named files. Runtime manifest carries both reports; existing approval hash remains mandatory. The manifest is trusted project data, not a cryptographic signature from Khronos. A valid GLB is not proof of animation fidelity, art quality, or performance. The independent canonical RGBA stack remains authoritative for cover rendering.
