# OpenColorIO — color management
Upstream https://github.com/AcademySoftwareFoundation/OpenColorIO ; processor API https://opencolorio.readthedocs.io/en/latest/guides/developing/usage_examples.html . Use actual PyOpenColorIO 2.x in a compatible Python environment, CPU processor. Do not redistribute unreviewed LUTs or run paid compute. Keep a reviewed dedicated config folder with all relative LUT dependencies; no external search paths, environment substitutions or symlinks. The bundle hash is not proof that an arbitrary config has no external dependencies; audit it before use. Preserve all source files.

For new scene.json add (example settings; choose the approved palette and an actual compatible Blender OCIO config):
```json
{"colorManagement":{"schema":"cover-pack-color/1","config":"color/config.ocio","bundleReviewed":true,"display":"sRGB","view":"AgX","look":"None","exposure":0,"gamma":1,"baseColorSpace":"sRGB","dataColorSpace":"Non-Color","outputEncoding":"sRGB","alpha":"straight","paletteId":"approved-unique-palette"}}
```
Use only view/look names actually provided by the config, and confirm the texture color-space and sRGB display transforms are genuine. Stock Blender OCIO configuration may be copied with all required dependencies when licensing permits. Set environment OCIO to the exact config absolute path before starting Blender, then run existing cycles_cover.py. Blender uses OCIO internally; the script records the settings and bundle hashes, not a substitute for real visual calibration. OIDN paired references must use the same settings. LPIPS and WebP receive display-referred sRGB PNGs, not HDR linear values; never apply AgX to those again. `webp_cover.py` checks the contract against the exact scene and config files. Existing scene without a contract stays legacy-unverified; new covers require one.

`python scripts/ocio_color.py --source raw-basecolor.npy --config color/config.ocio --source-space '<actual space>' --role base-color --out basecolor.png` uses float straight-alpha HxWx4 NPY and genuine OCIO CPUProcessor. Requires numpy, Pillow and PyOpenColorIO. Target is the reviewed config's sRGB space; already sRGB is rejected, data channels must bypass it, alpha is quantized once to 8 bits, out-of-gamut values are rejected for author review. Source and config hashes plus processor cache ID recorded. Never apply it to native O-Voxel attributes without a known encoding; Material Maker export encoding must be verified first. All canonical assets remain intact.

Use runtime_color.mjs with the game's exact Three.js version: sRGB color textures, NoColorSpace numerical maps, sRGB output. Static/animated display-referred cover uses unlit toneMapped=false. Basis atlas uses the same sRGB convention for color pages; non-color maps require a separate verified path. No promise of exact AgX/OCIO shader parity between Three.js and Blender; independently compare actual rendered views and do not claim quality/FPS gains without running. The previous renderer still uses constant per-object PBR values, not full per-voxel PBR shading. Missing OCIO/Blender is a blocker, not a fake color conversion.
