# TRELLIS.2 + O-Voxel

Official upstream: https://github.com/microsoft/TRELLIS.2 and https://github.com/microsoft/TRELLIS.2/tree/main/o-voxel . Model: https://huggingface.co/microsoft/TRELLIS.2-4B . Model/code MIT; dependencies have independent terms. Check licenses including nvdiffrast, nvdiffrec, and model preprocessing components before commercial use; do not automatically redistribute weights or run paid compute. Upstream Linux/CUDA 12.4, NVIDIA 24 GB class or higher. Install upstream with its official setup in an isolated environment, record exact commit and checkpoint revision; do not install unreviewed scripts or claim availability. The package ships an adapter, not upstream weights/runtime.

1. Isolate each approved object as RGBA (no background); retain approved full scene and exact crop/mask. Do not feed whole scene as one object. Keep characters, instruments, architecture independent. Use the SAM 2.1 adapter in [sam2.md](sam2.md), or verified externally authored masks. No regeneration of approved design.
2. In the upstream environment run `python scripts/trellis_stack.py generate --image object.png --out object-pack --up z --size 256 --glb` after verifying native orientation. Use `--up y` for Y-up grids. A real inference is required; no fabricated grid fallback. Separate GLB export optional. Save native sparse material coordinates, full attributes, layout and provenance. Preserve material opacity; GLB default opaque may require authoring correction. Unknown sides reconstructed, not exact.
3. On CPU use `python scripts/trellis_stack.py convert --grid object-pack/native_grid.npz --out rebuilt-stack --up z --size 256`. Requires numpy/Pillow only. Direct horizontal slices from sparse O-Voxel material samples, not filled interiors. Resolution can be 128/256/512/1024; preserve isotropic spacing. Downsampling loses thin details: compare 256/512 and keep the highest feasible resolution. Sparse grid contains surface samples; if a solid volume is required, separately reconstruct/check the mesh and use a proper slicer, never fill arbitrary holes. Retain source material attributes for PBR rendering; PNG RGB is base color, not baked lighting. Correct orientation, pivot, transparent holes and alpha before integration.
4. Run the existing Sprite Stacking Grunge Horror renderer from these exact layers. Render 360-degree preview and independent movement poses; import into scene.json with scale, bounds, collisions and lighting; render cover from the same scene, compare with approved sketch, then publish only if all original quality gates pass. Adapter outputs prototype, no automatic readiness. No model inference or animation is implied by CPU export.
