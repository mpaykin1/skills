# Infinigen — procedural environment branch (v0.6.0)

Upstream: https://github.com/princeton-vl/infinigen . Official exporter: https://github.com/princeton-vl/infinigen/blob/main/docs/source/ExportingToExternalFileFormats.md . Install an approved, isolated Infinigen/Blender environment using upstream instructions and record commit, seed, generator configuration, and source license. This package includes a bridge, not Infinigen, Blender or their assets. The CPU bridge uses NumPy, Pillow and trimesh (tested with 4.11.1). No paid compute or unreviewed installation.

## Two complementary asset sources
SAM 2.1 + TRELLIS.2 + O-Voxel reconstruct approved foreground objects; Infinigen generates supplementary natural assets, furnishings and appropriate indoor modules from explicit artistic constraints. It is not a Gothic architecture generator by default. Do not replace approved characters, landmark architecture, composition or palette. Select a distinct chapter's seed, architecture, materials and scene language; use only objects that visually match the approved reference. Keep hand-authored geometry when a suitable procedural generator is unavailable.

1. Generate independent objects or a small controlled scene in Infinigen's own environment. Preserve `.blend`, seed, configs, original geometry/materials and license. The upstream OBJ exporter does not support large instanced scenes efficiently; export individual objects, never a full large world. Procedural texture baking can lose unsupported material channels, transparency and fine details. Animation export is not a supported shortcut. For real animated objects retain original rig/poses and existing animation workflow.
2. Export baked objects with the official adapter: `python scripts/infinigen_pack.py export --python /path/to/infinigen-python --input-folder authored-blends --out baked --texture-size 1024`. The wrapper invokes `infinigen.tools.export` with `-f obj --individual`. Use a separate output. A compatible upstream environment and successfully generated blend files are required.
3. Create a reviewed selection JSON array, for example `[{"id":"balcony-west","file":"actual-export.obj","role":"architecture"}]`. Use actual exported relative filenames, keep every MTL and texture alongside them. Reject untextured objects unless deliberately authored with explicit materials. `python scripts/infinigen_pack.py pack --exported baked --selection selection.json --out environment --up z --size 256`. Confirm source coordinate convention; use `--up y` when needed. Sample actual triangle surfaces and baked UV/vertex/face colors deterministically. Store native mesh and sparse RGBA coordinates in the shared contract (these are sampled meshes, NOT native O-Voxel inference); export PNG layers with existing trellis_stack.export_stack. All source texture files remain in baked-source. Output is a base-color/alpha surface representation, not full PBR or a solid. If aliasing, missing textures or thin features occur, inspect and revise source/resolution. Never fill arbitrary holes.
4. `python scripts/infinigen_pack.py merge --generated reconstructed environment --out combined` joins reviewed sources with unique IDs; refuses duplicates and leaves originals intact. Run existing `python scripts/sam2_pack.py refine --generated combined --out refined` (audit by default; optional reviewed opaque solid IDs only). Open3D must pass geometry checks; OpenVDB archives RGBA with exact roundtrip, retains separate fog density. `python scripts/openvdb_stack.py batch --generated combined --refined refined --out vdb-pack`. No need to pass Infinigen meshes through TRELLIS again. Original PBR channels stay in the baked export, O-Voxel attributes stay in native NPZ.
5. Use the same approved stacks in `scene.json` for the 360° asset renderer and cover composition. Distinct hero/palette/architecture and actual motion remain mandatory. Verify silhouettes, materials and placement visually. A merged pack is still prototype until the original quality, animation and publication gates pass. No fake claims of upstream generation or visual parity.
