# Intel Embree CPU — static occlusion and lighting bridge
Pinned reference: https://github.com/RenderKit/embree/tree/5730b150471602d6dc02d9b7d8a4a6ce9ceffe16 (4.3.3, Apache-2.0; LICENSE.txt blob d645695673349e3947e8e5ae42332d0ac3164cd7). Use reviewed CPU-only release or build the pinned source in an isolated worker with `EMBREE_SYCL_SUPPORT=OFF`, no GPU required. Verify archive, runtime and dependency hashes; preserve licenses. Native C++ compiler, Embree 4 SDK and Python NumPy/Pillow required. `cmake -S native -B build -DCMAKE_PREFIX_PATH=/reviewed/embree && cmake --build build --config Release` builds our original adapter, not Embree itself. Blender Cycles CPU may already use its bundled Embree; retain the bundled ABI, never replace shared libraries or claim that enabling CPU proves an Embree speedup. Use actual Cycles logs/build configuration to verify. Do not add a second path tracer inside the game. Native Embree is not bundled; this adapter is not an installation or a measured acceleration.

## Producer
OpenSubdiv and existing approved geometry precede offline lighting; Material Maker/OSL supply surface maps and MaterialX preserves PBR channels. Use CPU Cycles for indirect lighting, shadows and reflections, OIDN only on newly rendered image candidates, never on AO/normal maps, approved artwork or true volume data. For supplementary static AO, use native `meta_embree_bake` on a verified scene, no Blender replacement. Inputs are a trusted worker-generated NPZ: vertices (N,3 float) and triangles (M,3 integer), positions/normals (H,W,3 float), mask (H,W bool). Position and normal maps must be rasterized from the same authorized static UV unwrap/evaluated mesh, world metre coordinates, consistent frame/axis, no overlapping UV islands, normalized geometric normals. The adapter does not rasterize UVs. Include actual static opaque blockers, not fire, transparent cloth, moving NPCs or physics proxies. Do not infer maps from unrelated source images. Preserve sample source and all material/source hashes. Explicitly review light position, AO radius, surface offset and sample resolution. A static bake must not be applied to dynamic world-space shadows on a moving hero; only local self-AO on an appropriate static/rest asset or per-pose recalculated candidates. Keep real animated fire lighting separate.

`python scripts/bake_ao.py INPUT.npz NEW_DIR --exe /reviewed/meta_embree_bake --exe-sha VERIFIED_BINARY_SHA256 --source-sha VERIFIED_NPZ_SHA256 --light X Y Z --radius 1 --epsilon .001 --samples 32 --threads 4` invokes real Embree rtcOccluded1, deterministic cosine hemisphere sampling and a point visibility ray. AO is fraction of unoccluded samples; visibility is binary and not illumination intensity, area-light shadow, indirect transport or reflection. It is not a path tracer. Output linear `ao.png`, `visibility.png`, `mask.png`, `ao.json` candidate, max 512² and 128 samples, bounded input and timeout. Missing native dependency is a hard stop, not a substitute result. `audit_ao.py` checks byte integrity, layout and mask; review UV seams, padding, aliasing, ray self-intersection, silhouette, normal mapping and coverage separately. `merge_orm.py` creates a NEW candidate ORM from a same-UV and same-size verified original ORM and AO map; preserves G/B bytes, neutral outside the sample mask, refuses to overwrite original. Requires explicit verified input hashes; do not silently relabel a modified OSL or MaterialX source package or bypass its validation. Use a new derived recipe and approval before any material adoption. Do not multiply baked AO twice or bake dynamic lighting into baseColor.

## Consumers and quality
META Game Fusion and Game Style Forge use approved static AO as a linear material channel only, retain MaterialX/GLB and true Sprite Stacking volume identity. Use existing PBR loader and texture UV contract, not a second raytracer. For Canvas2D use approved CPU-rendered projections with matched light and pose; no fake volumetric slices. Dynamic Mantaflow/OpenVDB/NanoVDB fire and its light curve remain separate, Quarks and Effekseer own distinct effects. Rapier is sole physical authority. Keep existing black-screen, mobile and living-world guards; optional WebGL, no mandatory GPU. Compare same source scene/camera/lighting/samples/seed before and after using actual worker wall-clock and memory. No inferred render speedup, no quality percent without real comparable renders.
