Use reviewed CPU build with Python/NumPy bindings and OpenEXR support, verify distribution hashes and dependencies. The Python package or native build is external; no bundled binaries, no GPU or cloud service. The adapter uses the actual ImageInput API, not a surrogate decoder. The native package could not be installed in this environment; no EXR execution or image improvement claim. If OIIO is unavailable, keep the existing approved render workflow unchanged, never relabel a fallback as OIIO.

## Producer: Blender Model Animation Enhancer
OpenSubdiv + Rigify/NLA evaluate authorized 3D geometry and poses. Material Maker/OSL/MaterialX prepare linear-data and sRGB texture maps; Embree/Cycles CPU calculate lighting, OIDN (native HDR Cycles path when appropriate) denoises newly rendered candidates before display conversion. Export actual scene-linear OpenEXR RGBA, no Blender display transform. Explicitly record channel names (including Blender layer/pass prefix if present), linear space, alpha association, frame index and source SHA. OIIO reads full data windows and a selected EXR part, preserving float HDR values. Deep EXR, cropped windows, negative RGB, additive zero-alpha emission, unsupported channels and inconsistent frame dimensions fail instead of silently clipping. Do not apply this bridge to approved art, PBR maps, normals, AO, physical volume fields or genuine RGBA slices. For emissive volume previews with incompatible alpha, use an opaque composited linear render upstream. OIIO is not a new animation generator or denoiser. Example input JSON:
```json
{"schema":"meta-oiio-exr-v1","source_kind":"unapproved-linear-render","asset_id":"hero-preview","source_recipe_sha256":"<actual SHA256>","source_space":"Linear Rec.709 (sRGB)","display":"sRGB - Display","view":"ACES 1.0 - SDR Video","alpha":"premultiplied","fps":24,"subimage":0,"channels":["R","G","B","A"],"frames":[{"frame":0,"file":"raw/0000.exr","sha256":"<actual SHA256>"}]}
```
Choose straight/premultiplied based on actual export, not this example. Run `python scripts/exr_bridge.py convert exr.json NEW_DIR`. Actual OIIO version checked; sequential read, max 2048², 32 channels, 240 frames, 4 threads, reviewed isolated worker with disk/RAM limits. Writes immutable derived straight float32 NPY frames and exact existing `meta-ocio-render-v1` `ocio-recipe.json` plus `bridge.json`; no tone mapping, resizing or source overwrite. Native audit: `python scripts/exr_bridge.py audit exr.json NEW_DIR --recompute`. Then use existing `ocio-cpu/scripts/ocio_cpu.py render NEW_DIR/ocio-recipe.json NEW_DISPLAY_DIR`. One final display transform only. NPY is an intermediate, not a compressed game asset; retain source and provenance and use existing atlas packing/PNG or verified KTX2 pipeline afterward. Do not claim smaller output from OIIO alone.
