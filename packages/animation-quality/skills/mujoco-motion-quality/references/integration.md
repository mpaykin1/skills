# Integration v0.12.0 — CPU MuJoCo
API: https://mujoco.readthedocs.io/en/3.3.7/python.html and https://mujoco.readthedocs.io/en/3.3.7/APIreference/APIfunctions.html. Chosen pinned version, not a latest-version claim.

1. Use only an approved self-contained MJCF physics proxy calibrated in metres, kg, seconds with Z-up gravity, original rig correspondence, dimensions, inertia, contact geometry and named sites. Explicitly review model against Blender/Rigify source and OpenSim reference, especially custom monster anatomy. No MJCF inferred from a GIF, no default human anatomy imposed on monsters. Model constraints/activation/mocap unsupported in this scoped bridge. No external XML assets/plugins. Preserve original assets and renderer. MuJoCo is an offline QA tool, Rapier remains runtime physics authority.
2. Export actual evaluated rig states using reviewed native joint order and quaternion convention (wxyz), to NPZ with `time` [N] and `qpos` [N,nq], finite CFR 10–120 fps. MediaPipe/DeepLabCut are diagnostics; calibrated FreeMoCap/OpenSim marker mapping supplies independent reference. No direct 2D-to-dynamics. Explicit authored support windows (inclusive indices), static floor, foot geom and same-body site. Use exact hashes, no automatic contact inference. Configuration JSON: rights_confirmed=true, model_sha256, baseline_sha256, contacts=[{start,end,foot_geom,floor_geom,site}], or explicitly confirmed no-ground-contact clip. Native `python scripts/mujoco_motion.py model.xml original.npz config.json` evaluates mj_differentiatePos, mj_forward and mj_inverse on actual submitted states. Outputs per-contact missing frames, slip, penetration, global penetration, COM trace, per-DOF inverse demand RMS/peak. DOFs not summed across mixed units. COM alone does not establish dynamic balance; inverse demand is not measured muscle force, actual actuator torque or feasibility. No forward rollout/controller certification. Native numerical heuristics are not artistic proof.
3. To improve only unintended jitter in one scalar hinge/slide coordinate, use existing `opensim-motion-quality/scripts/opensim_motion.py smooth` (bounded SciPy solver) on that coordinate in the native units, locking contact windows, endpoints and authored anchors. If SciPy rejects, keep source. Do not smooth attacks, deliberate acceleration, impacts, jumps or pose identity. Re-export candidate from approved rig with unchanged remaining qpos and timeline. Run prior OpenSim marker nonregression on calibrated corresponding trajectory first; never mix coordinates between OpenSim and MJCF without authored mapping. Add candidate_sha256, edited_joint (native name), max_delta_native (<=.05 rad/metres), anchors (frame indices) to config. `python scripts/mujoco_motion.py model.xml original.npz config.json --candidate edited.npz` requires exact other columns, anchors, bounds and same model, and rejects contact/penetration or inverse-demand regression (1% numerical tolerance per DOF). A pass means this limited nonregression only, never automatic correction/approval. Review original absolute contact quality separately; if both bad, reject. Inspect COM, foot contact, motion intent and torque feasibility with actual model-specific limits, not guessed thresholds.
4. After approved candidate, Blender/Rigify/NLA preserve all original skin, geometry, materials, weapon attachments, actions and timing. OpenSubdiv is optional existing non-destructive geometry refinement, not motion correction. Re-render actual same full poses or complete RGBA stacks from same volume at every angle, same pivot. No RIFE/Bitmapflow deformation on organic characters. Use existing glTF Validator, OpenCV/NumPy visual audits, Pillow assembly and FFmpeg verified lossless delivery. Keep all previous Mantaflow/OpenVDB/Effekseer and FreeMoCap/Rokoko integrations. Compare actual baseline and candidate visual clips; no metric-only global quality percentage. No test/report artifacts unless requested.
5. Local authoring limitation: pip could not obtain MuJoCo 3.3.7; no native physics executed. Independent contact/force nonregression and input checks can be exercised without native package but cannot replace it. No user-facing simulation PASS until real engine execution and visual review.
