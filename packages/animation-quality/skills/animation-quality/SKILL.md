# Animation Quality — оценка и улучшение анимации

## Обязательный процесс
1. Прочитать входные архивы; безопасно распаковать в отдельную папку без перезаписи оригиналов, traversal, symlink и zip bomb. Инвентаризировать модели, варианты, клипы, ракурсы, источники объёма и риги. Составить матрицу ожидаемых действий и ракурсов для каждого типа по заданию, не считать вращение камеры бегом. Не объявлять отсутствующую анимацию исправленной.
2. Выполнить `python scripts/quality.py audit PATH --flow` для GIF/APNG/WebP и папок. Режим `--mode loop` или `once` задаётся по семантике клипа, иначе auto проверяет бесконечные циклы по метаданным. Анализировать все кадры, alpha, FPS с реальными длительностями, повторы, пустые кадры, выбросы соседних кадров, шов, изменение скорости центра силуэта, forward/backward optical-flow error. Эти прокси не доказывают анатомию, foot contact или отсутствие мерцания; намеренные остановки, падения, исчезновения и ударные акценты не дефекты сами по себе. Проверить визуально на светлом/тёмном фоне и в одинаковом масштабе, с исходными ключевыми кадрами.
3. Маршрутизировать реальную правку через актуальные установленные скилы (обновить каталог): Sprite Stacking Grunge Horror — действительные объёмные срезы каждой позы, один pivot и единый источник, жёсткие части и многовидовой рендер; GIF Asset Animator — недостающие авторские RGBA позы; Hero Animator / anti-jerk — полные кадры персонажа, не деформировать и не интерполировать персонажей; Monster Anatomy 3D / Blender Model Animation Enhancer — настоящие риги, контакты, веса и корректирующие morphs при наличии исходника. Не делать липовый риг из GIF. Для 3D проверять оригинальные клипы, кости, quaternion, временные семплы, стопы, пересечения, root motion и bounding box, запускать Blender и Khronos glTF Validator при наличии. Никаких заявлений об их запуске без реального исполнения.
4. Единственная встроенная автоматическая правка v0.1: для явно равномерного клипа (вращение с постоянной угловой скоростью, равномерная фаза механизма), если визуально проверено, что длительности ошибочны, `python scripts/quality.py repair IN.gif OUT.png --profile uniform-loop` или `uniform-once`. Сохраняет каждую RGBA позу и общую длительность, исправляет только неравномерность интервалов, APNG без потерь, проверяет результат после декодирования. Не применять к атакам, смерти, специально замедленным фазам, удержаниям, неравномерному вращению, переменным позам и клипам с неизвестной семантикой. Не заменять GIF без согласованной поддержки APNG; для GIF экспортировать через отдельный проверенный encoder и повторно сравнивать alpha, цвет, тайминг. Не увеличивать FPS дублированием. Для реальных новых движений получать авторские позы или рендерить rig/volume, а не подменять форму. Для среды (не персонажей) опциональная интерполяция только если опенсорс реально установлен и alpha, шов, геометрия и идентичность проверены.
5. `python scripts/quality.py compare BEFORE AFTER --profile uniform-loop` или `uniform-once` — только для заранее определённой равномерной анимации. Технический индекс 0..100: uniform-once = 100*max(0,1-CV длительности); uniform-loop = 60% этого индекса + 40% штрафуемой величины шва относительно медианы соседнего изменения. Не использовать этот индекс для произвольных анимаций, не подменять им визуальное качество. Выдавать разницу в процентных пунктах и относительный рост (after-before)/before*100, при нулевой базе или неизвестных данных — нет оценки. Для сравнения обязаны совпадать модель, вид, действие и целевой профиль.
6. Общая оценка только после визуальной проверки до и после по одинаковой рубрике: идентичность/анатомия 25, правдоподобие и читаемость движения 25, плавность и тайминг 20, корректность циклов/завершений 15, ракурсы и полнота действий 10, alpha/артефакты 5. Баллы 0–100; неизвестные пункты не заменять догадкой, итог не публиковать пока не измерены все применимые пункты. Для пачки сначала среднее по клипам каждого ассета, затем среднее по ассетам одинакового набора; отдельно показывать охват, не раздувать вес дубликатами и вариантами. При критической смене идентичности, отсутствующей обязательной позе или разрыве движения — блокировать выпуск независимо от индекса. Показывать процент только по измеренной шкале, не придумывать процент художественного улучшения.
7. После всех этапов улучшения движения выполнять опциональный финальный FFmpeg export v0.7.0 (см. ниже), не менять формат без явного подтверждения поддержки в игре. Возвращать улучшенные ассеты и превью, а не отчёты/тесты без запроса. Не публиковать в чужом репозитории без разрешения. Если не удалось исправить — сохранить оригинал, явно отметить ограничение. Skill Nexus может использовать этот скилл для выбора узкого места, но не должен сам менять критерии для получения PASS.

## Зависимости
Установить зависимости `requirements.txt` в отдельное окружение. Реально используемые: Pillow (RGBA, durations, APNG), NumPy (метрики), OpenCV (CPU Farneback, forward/backward flow). Остальные — опциональные этапы, не bundled и не заявлять установленными. Bitmapflow подключён через мост внешнего PNG-экспорта (см. v0.3.0 ниже).
- https://github.com/Bauxitedev/bitmapflow — промежуточные кадры спрайтов: только для разрешённых эффектов/неорганических движений, соблюдать запрет на деформации персонажей.
- https://github.com/scipy/scipy — сплайны физических траекторий, не сглаживать намеренные акценты.
- https://www.blender.org/ — реальные 3D позы/IK/контакт; https://github.com/KhronosGroup/glTF-Validator — структура экспортируемых GLB.
- https://github.com/hzwer/ECCV2022-RIFE — опционально для неорганических эффектов; проверять веса, лицензии, CPU/GPU и прозрачность. Запрещено подменять авторские кадры героя.
- https://ffmpeg.org/ — инспекция таймингов, видео-превью и кодирование, без подмены реальных кадров.

## OpenCV CPU v0.2.0 — расширенная интеграция
Официальный OpenCV (Apache-2.0), https://github.com/opencv/opencv, API https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html. Использовать реально установленный `opencv-python-headless` из requirements.txt; не заявлять скачивание исходного репозитория. `audit --flow` теперь одновременно запускает прежний плотный Farneback и `opencv_motion.py`: Shi–Tomasi + pyramidal Lucas–Kanade, forward/backward отсев, alpha-маска, покрытие треков, скорость с учётом длительности кадров, пространственный разброс движения, ускорение и локализация выбросов, включая последний→первый для циклов. При слабом трекинге результат unknown, не ноль. Значения нормированы на диагональ уменьшенного кадра; FB error в пикселях уменьшенного кадра. Выбросы — кандидаты на визуальную проверку, не доказательство дефекта. Направление и скорость медианы не представляют все части персонажа; запрещено подменять этим анатомическую оценку.

Дополнительная реальная правка только для явно заданного одноразового прямолинейного движения жёсткого спрайта с постоянной скоростью: `python scripts/quality.py repair-rigid-travel INPUT.gif OUTPUT.png --confirm-constant-speed`. OpenCV boundingRect и точное RGBA сравнение требуют неизменённый силуэт и текстуру во всех кадрах, отсутствие обрезки, остановок, поворотов, цикла и деформаций. Времена переходов пропорциональны фактическому расстоянию, последний hold неизменён, длительность всего клипа и все исходные кадры сохраняются. Выпуск только при измеренном уменьшении CV скорости и точном повторном декодировании APNG. Это не художественный процент, не новые позы и не исправление бега персонажа. Для остальных клипов прежний workflow и скилы остаются обязательными. Не менять критерии для PASS.

## Bitmapflow + OpenCV bridge v0.3.0
Официальный MIT [Bauxitedev/bitmapflow](https://github.com/Bauxitedev/bitmapflow) (Godot/Rust GUI, SimpleFlow/DenseRLOF), [официальное описание и загрузки](https://bauxite.itch.io/bitmapflow). Нативный исполняемый файл и исходники не входят в пакет; сетевое скачивание в текущем окружении заблокировано. Не выдумывать CLI или заявлять, что Bitmapflow запущен. Реально встроен Python-мост для PNG-экспорта настоящего Bitmapflow. При наличии приложения на доступном компьютере использовать его GUI, а не синтетический заменитель. Если недоступно, оставить этап blocked и использовать прежние скилы. Bitmapflow не подходит для изменения ракурса, сильной окклюзии, морфинга, вспышек и изменения яркости. НЕ применять к людям, животным, монстрам, скелетным позам, объёмным 360° ракурсам или слоям Sprite Stacking; для них требуются полноценные новые авторские позы или рендер реального объёма.

Workflow только для явно подтверждённого неорганического жёсткого XY-перемещения:
1. `python scripts/quality.py audit SOURCE.gif --flow --mode once` (или loop), выбрать подходящий клип, проверить семантику и исходные позы. При необходимости отдельно исправить тайминг прежним `repair-rigid-travel` и использовать именно исправленный файл как вход, сохраняя исходник. Не делать выравнивание автоматически при намеренном ускорении.
2. `python scripts/bitmapflow_bridge.py prepare SOURCE.gif INPUT_DIR --mode once --confirm-nonorganic-translation` экспортирует оригинальные RGBA PNG, проверяет неизменность текстуры и силуэта при целочисленном переносе без обрезки. Импортировать все PNG в официальном Bitmapflow в числовом порядке, установить Inbetweens = 1 (или 2/3), Motion multiplier = 1x, Loop seamlessly согласно режиму. Экспортировать individual frames как PNG с прозрачным фоном в отдельный каталог, имена должны оканчиваться последовательным числовым индексом. Сохранить факт использования приложения и версию; Python-мост сам не удостоверяет происхождение экспортированных кадров.
3. `python scripts/bitmapflow_bridge.py import-export SOURCE.gif EXPORTED_DIR OUT.png --mode once --factor 2 --confirm-nonorganic-translation` (factor = Inbetweens + 1, 2/3/4). Мост требует все исходные RGBA кадры побайтно неизменными, одинаковый холст, точную текстуру и alpha каждого промежуточного кадра с допустимым только целочисленным переносом, монотонную траекторию, уменьшение максимального пространственного скачка на каждом отрезке, сохранение длительности каждого исходного интервала и последнего hold. Для циклов проверяет последний→первый отрезок. Pillow сохраняет APNG и проверяет повторным декодированием. OpenCV boundingRect/NumPy обеспечивают строгий контроль идентичности, прежний LK/Farneback аудит проверяет движение; мост требует покрытие LK >=80% переходов до и после, возвращает обе серии измерений. Метрика улучшения — сокращение максимального пространственного шага, не процент художественного качества и не доказательство отсутствия рывков. Сравнить ускорения и seam в выдаче и визуально просмотреть каждый кандидат перед использованием в игре. При ухудшении, недостоверности, мерцании, ghosting, clipping, изменении поз или провале любого обязательного критерия сохранить оригинал; не ослаблять gate. APNG не подменяет GIF без проверки поддержки движком.
4. Если Bitmapflow создаёт смешанные/искажённые пиксели, этот строгий мост отклонит экспорт. Не обходить это условие. Для подлинно объёмных ассетов передать задачу Sprite Stacking Grunge Horror, для персонажей Hero Animator/GIF Asset Animator. Для других эффектов отдельная визуальная авторская проверка, данный мост их автоматически не выпускает.

Интеграция проверяется локально на пронумерованных синтетических PNG как проверка именно моста, НЕ Bitmapflow. Не приписывать этому запуск upstream или улучшение Bullet Car.

## SciPy CPU constrained motion optimization v0.4.0
Official BSD-3-Clause [SciPy](https://github.com/scipy/scipy), `scipy==1.17.0`; uses actual `scipy.optimize.minimize(method='SLSQP')` with total-time equality and per-segment lower bounds. Not a spline-based pose generator. The same OpenCV boundingRect/NumPy exact RGBA translation guard runs first, and independent Lucas–Kanade diagnostics verify the candidate after optimization. Only use for explicitly confirmed continuous nonorganic rigid cruise with unintended timing irregularities (straight or smoothly turning XY paths). No characters, limb motions, volume yaw, intended attacks, acceleration/braking, holds, or sharp turns. For these keep the original or route to the authored pose/rig skills.

1. `python scripts/quality.py audit SOURCE.gif --flow --mode loop` (or once). Review motion semantics; no automatic uniform cruise assumption.
2. `python scripts/scipy_motion.py SOURCE.gif SMOOTH.png --mode loop --confirm-rigid-cruise --bitmapflow-factor 2` (or once). Factor 1 when not planning external interpolation. SciPy jointly minimizes exact path-vector acceleration RMS and speed variation while conserving total milliseconds. Minimum 10 ms per planned subframe, integer rounding preserves total, one-shot final hold unchanged. Last-to-first velocity change explicitly included in cyclic optimization. No pixel changes, no repositioning, no pose generation. Reject empty/held poses, clipping, sharp reversals, fewer than 4 or more than 256 travel segments, inadequate time budget, solver failure, and lack of measured improvement. Candidate must improve acceleration RMS by >1%, decrease speed CV, not increase exact acceleration p95; independent OpenCV LK coverage >=80% before/after and acceleration p95 cannot rise beyond numerical allowance max(0.001,3% of baseline), explicitly disclosed as measurement tolerance. Pillow round-trip guard checks every RGBA frame, order, durations and repeat mode. Never change thresholds to release a failure.
3. If using actual external Bitmapflow, feed SMOOTH.png (not the original) to `bitmapflow_bridge.py prepare` and `import-export`, same mode/factor. SciPy ensures sufficient timing budget before Bitmapflow subdivides original intervals. Bitmapflow's exact keyframe/texture/trajectory gate remains intact. Compare source, retimed clip and interpolated candidate with OpenCV; never ship a later stage that regresses motion or identity. The native Bitmapflow app remains external/unverified here. No fabricated integration claim.
4. Report acceleration RMS reduction and speed CV reduction separately, not an artistic quality percentage. No effect on path geometry; spatial jumps need actual approved intermediate frames, and no automatic pose fixes are implied. APNG output only; do not silently replace GIF in runtime without checking support. Keep original immutable and show actual visual before/after if used on user assets. SciPy stage tested on synthetic rigid sprites, not Bullet Car in this release.

## RIFE CPU optional bridge v0.5.0
Official [ECCV2022-RIFE](https://github.com/hzwer/ECCV2022-RIFE), MIT source; the upstream `inference_img.py` documents `--img`, `--exp`, `--model` and `output/imgN.png`. Use a trusted actual upstream local checkout pinned to an exact verified commit and compatible trusted weights with their license checked separately. Install upstream dependencies in an isolated CPU Python environment alongside the existing requirements; do not silently install or download during execution. Network DNS blocked acquisition in this environment, no source or weights bundled, no inference verification claimed. GPU hidden with CUDA_VISIBLE_DEVICES; upstream CPU compatibility depends on model version. Reject unsupported checkpoints rather than synthesize replacements. Only opaque, nonorganic effects with continuous motion, no cuts, no intentional flashes or holds; no characters/animals/monsters, sprite-stacking layers, original authored poses or camera-angle changes. Transparent effects are excluded from this RIFE bridge; never flatten a transparent sprite to make it eligible. Use existing exact Bitmapflow route for eligible rigid RGBA translations and authored volume/pose rendering for other transparent objects.

1. Audit original with `quality.py audit SOURCE --flow --mode loop` or once. Use SciPy retiming only in its previously approved rigid cruise domain, never to alter effect timing or intentional acceleration. RIFE preserves every original interval, requires >=10 ms per subframe; no duplication to fake FPS.
2. `python scripts/rife_bridge.py SOURCE PREVIEW.png --mode loop --factor 2 --repo /trusted/ECCV2022-RIFE --revision EXACT_40_HEX_COMMIT --weights /trusted/train_log --confirm-opaque-nonorganic-effect`. For factor 4 use --factor 4. CLI invokes actual upstream inference for each pair including cyclic seam; one-shot final hold stays unchanged. All original frames are copied byte-exactly, only intermediate RGB frames originate in RIFE. Model loading uses upstream code; no alternative synthetic backend. Checkout and weights must already exist. Per-pair pixel-step improvement, SciPy Sobel edge-energy proxy, OpenCV LK coverage >=80% and acceleration p95 guard (5% or 0.01 numerical tolerance), NumPy duration/keyframe checks and Pillow APNG round-trip cooperate. Thresholds are conservative heuristics, not visual proof. Preview is not production-approved; inspect ghosting, edge texture, motion, timing, seam and compare source. If any guard fails, retain original. Do not replace original asset, do not assert improved artistic quality, and do not route failures to another interpolator to bypass gates. Use real authored rendering when needed. Keep prior OpenCV, Bitmapflow and SciPy integrations unchanged.
3. Validate APNG compatibility before game integration. Compare technical pixel-step reduction and LK measurements separately; neither is an artistic percentage. Local synthetic validation of the bridge is not a RIFE inference run. For actual effects, visual approval remains mandatory.

## Blender 4.5 LTS + SciPy protected root motion v0.6.0
Official GPL [Blender](https://www.blender.org/), API [ActionKeyframeStrip](https://docs.blender.org/api/4.5/bpy.types.ActionKeyframeStrip.html). External Blender 4.5 LTS executable, not bundled. Never download or run unknown blends with automatic Python scripts enabled. No Blender or bpy was installed in the authoring environment, so only the SciPy solver and Python syntax were executed; no real rig, GLB, rendered volume or contact result was validated. Do not call this automatic anatomy repair or a finished Blender animation.

For an existing authorized `.blend` with an explicit single-slot, single-layer, single-strip active action on a local unparented armature, apply this opt-in only to **unintentional object-root jitter in a one-shot smooth travel clip**. No loops, attacks, deliberate acceleration, jumps, braking, root rotations, constrained rigs, NLA, shared actions, or missing source keys. The solver smooths XYZ root translations, not joint anatomy. Never reconstruct a skeleton from GIFs, never change mesh, skeleton, weights, materials, bone animation curves, camera, action length or source file. Contact windows and additional anchors must be authored/identified from the original motion, not guessed by a threshold; for a grounded character they must include all support intervals. `[]` only for explicitly floating/mechanical rigs with no ground contacts. If the worker rejects the rig, route to Monster Anatomy 3D / Blender Model Animation Enhancer or keep the source. Do not relax restrictions.

1. Locate Blender 4.5 LTS and external Python with existing NumPy/SciPy requirements. Inspect original movement in Blender and specify exact rig/action, confirmed contact bone names and inclusive frame intervals, additional authored event anchors and physically justified maximum root displacement in scene units. Run `blender -b ORIGINAL.blend --disable-autoexec --python-exit-code 1 --python scripts/blender_root_worker.py -- --rig RIG --action ACTION --output NEW.blend --solver-python /path/to/python --radius 0.03 --contacts '[{"bone":"foot.L","start":10,"end":15}]' --anchors '[18]' --confirm-unintended-root-jitter` (example values only, not defaults). For no contact use explicit `--contacts '[]'` only in permitted cases. Ensure `--disable-autoexec` precedes file load in actual command invocation: `blender --disable-autoexec -b ORIGINAL.blend ...`. No source modification. Worker uses real bpy Action channelbag FCurves and evaluated poses, not synthetic substitute. Only dense, aligned linear XYZ location channels are eligible. It invokes external SciPy `lsq_linear` with sparse second/third-difference operators, locks the first/last two frames, contact intervals and author anchors, and bounds displacement. Reject if jerk RMS fails to improve by >1%, acceleration RMS increases, pose matrices change, or sampled world contact points move. Keep all other action channels unchanged. Save separate blend only after checks. This does not establish foot contact on an originally sliding rig or prove subframe collision freedom.
2. Inspect full original and candidate in Blender with identical cameras, frame times, lighting and render dimensions. Route genuine evaluated full-volume poses to Sprite Stacking Grunge Horror from the candidate .blend (same pivot and sampling, every angle from same volume); route original skeletal assets to Blender Model Animation Enhancer for GLB export, preserve animations and run Khronos validator when available. This release does not implement a new voxelizer or exporter. For character GIFs render distinct complete frames from the same source and obey Hero Animator restrictions on authoring/identity; no RIFE or Bitmapflow on organic poses. For genuine render sequences, assemble lossless APNG with Pillow and compare both via `quality.py audit PATH --flow --mode once`. OpenCV can identify optical discontinuity, seam for other cyclic clips, or coverage issues; compare actual frames visually, protect intentional actions and reject visible regression. Do not claim global artistic improvement from a root-motion proxy or from render FPS. Only existing nonorganic translation and opaque-effect routes may use Bitmapflow/RIFE, never as a substitute for Blender poses. NumPy/SciPy use actual 3D coordinates, OpenCV uses the rendered output; their complementary metrics are not interchangeable. User-facing output is improved asset only after actual rendering and review.
3. Solver local synthetic check: 48 samples of linear cruise plus sinusoidal position noise, 24 fps, 0.03 unit maximum displacement, anchors at sample indices 20–22. RMS jerk 770.78 → 54.72 scene units/s³; RMS acceleration 17.10 → 1.82 scene units/s²; max deviation 0.01733. These are synthetic 3D trajectory results, not actual Blender or Bullet Car improvements. No claim of complete pipeline execution. Retain previous integrations unchanged.


## FFmpeg + FFprobe CPU delivery — v0.7.0

Официальный https://github.com/FFmpeg/FFmpeg, https://ffmpeg.org/ (LGPL/GPL в зависимости от сборки). Используются реальные системные исполняемые файлы FFmpeg/FFprobe, проверено на 7.1.5; бинарники не включены в архив. Проверять наличие libwebp_anim для WebP. Запуск после OpenCV/SciPy, разрешённых Bitmapflow/RIFE и Blender/авторских поз, никогда не вместо них.

- `python scripts/ffmpeg_export.py INPUT.gif OUTPUT.gif --flow` — новый GIF, глобальная палитра, без dithering, сохранение исходного тайминга и повторов.
- `python scripts/ffmpeg_export.py INPUT.gif OUTPUT.webp --allow-webp --flow` — только при явно подтверждённой поддержке animated WebP в игровом runtime и бесконечном цикле. Аналогично вход APNG (`INPUT.png`) после SciPy/рендера Blender. FFmpeg libwebp_anim lossless, CPU, без масштабирования или FPS-фильтров. WebP не заменяет автоматически GIF и PNG-срезы, оригинальный URL/файл остаётся. Не использовать WebP как подтверждение поддержки animated texture в Three.js: проверить фактический способ воспроизведения в игре.
- FFprobe читает поток; FFmpeg создаёт кандидат; Pillow декодирует ВСЕ RGBA кадры с disposal; NumPy проверяет точное совпадение видимых RGB/alpha (RGB полностью прозрачных пикселей незначим), размеров, порядка кадров, каждой длительности, loop metadata. Опция --flow реально запускает прежний OpenCV audit на обоих файлах и требует совпадения метрик. Не менять FPS, не удалять одинаковые позы, не придумывать новые движения. Не гарантируется сохранение неигровых комментариев/произвольных metadata.
- Кандидат сохраняется исключительно при уменьшении байтов и неизменности исходного файла. При несовместимости палитры, alpha, тайминга, лимите CPU или отсутствии кодека оставить исходник без изменений. Ограничение 80 млн декодированных пикселей на клип; таймаут команды 120 с. Не ослаблять сравнение для получения выигрыша. Сравнение не доказывает улучшение художественного качества, FPS игры или потребления GPU.
- Для Sprite Stacking выполнять только на производных многовидовых GIF/APNG, не трогать исходные RGBA срезы, stack.json, риг, позы или атласы. Сначала реальные улучшения движения, потом оптимизация доставки. При наличии исходника сравнивать художественное качество по прежней рубрике отдельно от размера.
- Реальное локальное исполнение: контрольный 12-кадровый GIF 13143 → 1881 байт (GIF) и 818 байт (WebP); APNG с полупрозрачными кадрами 1064 → 572 байта (WebP); все проверки RGBA, длительностей, loop и OpenCV прошли. На четырёх GIF Bullet Car same-format уменьшение 2.19–2.23%, точное декодированное совпадение; полный архив не обработан. Высокая степень сжатия WebP на сложных образцах не завершилась в бюджете среды, поэтому финальная конфигурация умеренная. Bitmapflow, RIFE, Blender по-прежнему имеют ранее описанные ограничения запуска.
