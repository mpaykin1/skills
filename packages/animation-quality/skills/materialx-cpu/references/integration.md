# MaterialX CPU material interchange
Upstream https://github.com/AcademySoftwareFoundation/MaterialX/tree/270b5cf2ae2be24a3b6ef4b0569f1c93038dda1d (v1.39.4, Apache-2.0, LICENSE blob d9a10c0d8e868ebf8da0b3dc95bb0be634c34bfe). Native Python package `MaterialX==1.39.4` is an external CPU worker dependency; verify the distribution and hash from the official release before installing. No GPU is needed for graph validation or this texture exchange. Do not claim native execution if import or validation fails. No arbitrary third-party graph evaluation, external URL or shader execution. Our bridge writes a narrowly scoped opaque glTF PBR graph with original image bytes, not a general MaterialX renderer/importer. It does not compile arbitrary OSL into MaterialX or directly import arbitrary MaterialX into Blender/Three.js.

## Producer
1. Preserve approved model, skinning, UVs, materials and original textures. OpenSubdiv produces reviewed geometry; OSL CPU + Material Maker provide candidate texture maps. Run existing `osl-cpu-materials/scripts/audit_material.py` on an OSL pack first. Material Maker packs may be supplied only from actual reviewed exports with explicit `meta-material-maker-pbr-v1` material.json: size 256/512/1024/2048, source_recipe_sha256, tileable bool, normal_convention "+Y", orm_channels ["occlusion","roughness","metallic"], maps.baseColor/normal/orm entries with exact matching filename (key.png), sha256 and color_space (srgb for baseColor, linear otherwise). All three opaque maps must be RGB PNG at same resolution; no automatic substitution of missing channels. Do not apply to transparent materials, hair alpha or approved hand-painted sprite frames.
2. `python scripts/materialx_bridge.py export SOURCE NEW_DIR` copies baseColor, normal and ORM exactly, splits ORM channels losslessly, builds MaterialX 1.39 `gltf_pbr`/`normalmap`/`surfacematerial` graph, fixed color-space contract and clamp unless approved tileable. Existing source untouched. PBR graph uses glTF semantics; no claim of full Standard Surface equivalence, procedural shader translation or new detail from the exchange format itself.
3. `python scripts/materialx_bridge.py validate-native NEW_DIR` loads pinned MaterialX standard library and validates actual graph. Missing native dependency = blocked, not a pass. `audit` independently verifies file hashes, source identity, channel equality and graph safe subset. Native validation does not prove render equivalence. Keep output candidate; only approved material selection in existing Blender workflow. OSL stays offline; Blender use existing Principled texture wiring (base sRGB, data non-color, normal map +Y, ORM roughness G/metal B, occlusion R through glTF exporter if supported); compare with source. No automatic import of arbitrary nodes. Use existing Khronos Validator, glTF Transform and meshoptimizer after actual export. Do not denoise texture maps with OIDN; use it on separate new preview images only.

## Consumers and quality
Fusion/Style Forge use the same exact PBR map bytes, material IDs and recipe hashes in the GLB and volume bake. Three.js standard PBR texture path, not runtime MaterialX, Canvas2D complete approved frame fallback. True Sprite Stacking volume cross-sections derive from actual 3D geometry and surface colors; normal map microdetail requires a supported normal-aware bake, never claim it appears automatically. Rigify/NLA timing, sword mount and complete poses unchanged. Check same source pose across front/rear/side and eight views, no UV drift, cloth seams and steel silhouette, material color/roughness, illumination and texture shimmer. Verify provenance and visual approval, not just hashes. Preserve Mantaflow/OpenVDB/NanoVDB actual animated fire, Effekseer combat, Quarks ambient, OIDN CPU preview and Black Screen Guard. No second physics or RAF; no GPU dependency for offline material preparation. No game update or quality percentage implied by this module.
