# АНТИЗАСТОЙ — Skill Nexus 1.3.0
При каждом запуске после свежей инвентаризации и до выбора OSS собери факты из актуальных GitHub HEAD/PR/check-runs, фактических импортов и потребителей модулей, результатов двух последних различных завершённых запусков. Сверь актуальные поручения владельца с PLAN и карточками. Для SYMPHONIA :36 единственный интегратор game/, modules/svyaz/, общего progress и каталога; :48 надзор/скилы, не запись в game/. Остальные роли сохраняют свои области. Не изменять защищённые проверки, meta6 и расписание.
Запусти `node scripts/progress-guard/progress-guard.mjs snapshot.json`. Формат: `{head,roles:{gameWriter:':36',nexus:':48',contradictions:[]},checks:{head,required:[{name,conclusion,jobId}]},modules:[{path,status:'integrated'|'pending'|'unknown',consumerPath,consumerHead,runtimeVerified}],stages:[{id,name,accepted,acceptedHead}],runs:[{id,completed,stageDelta}]}`. Для Z23 все 14 уникальных этапов обязательны. Снимок — только свежие факты, неизвестное не выдавать за success, исключать optional/skipped только если они действительно не обязательны. Модуль без работающего вызова и подтверждённого runtime не готов. Stage accepted — подтверждённый полный критерий на точном HEAD, не число файлов; отдельная метрика реализованного кода может быть выше.
При roles_conflict исправить инструкции/полномочия; refresh — получить факты; repair — исправить первопричину красной проверки, без ослабления теста; verify — дождаться результата в текущем доступном запуске или подготовить независимый следующий шаг, не считать PASS; integrate — ближайший готовый модуль, не новый OSS; stalled — изменить подход к блокеру, не повторять тот же SHA; finish — закрыть следующий этап. Только eligible разрешает очередной необязательный OSS. Разрешена зависимость, непосредственно устраняющая выбранный блокер. Следующее действие выполняет владелец соответствующей файловой области, :48 улучшает инструменты и инструкции, не редактирует чужой игровой код. Не публиковать/мержить при красном CI. Не гарантировать, что автоматизация исполнит правила без наблюдения реальных запусков.
XState 5.33.4 (MIT, upstream statelyai/xstate tag xstate@5.33.4, commit bd77717b8d33c49af1c8ee4a7e22cebb936cc8b1) — закреплённая npm-зависимость. `npm install --prefix scripts/progress-guard --ignore-scripts` при доступной сети; затем запусти CLI, требуй engine=xstate для подтверждения XState. Без npm работает независимый детерминированный gate, не выдавать его за XState. Никакого сетевого доступа, секретов или автоматических разрешений внутри gate. Он выбирает действие, не меняет репозитории сам. Связь с nexus-automation-supervisor и nexus-project-operator обязательна. При каждом запуске реально применяй выбранное действие, а не просто пересказывай вывод.
